# 非传统漏洞挖掘（Non-Traditional Vuln Hunting）

## 强制学习清单（用户 2026-08 教导，必须执行，详见 经验/全局经验/经验学习17.md）

设计任何攻击实验、评估任何攻击面、解读任何实验结果时，以下四条为**默认神经回路**，不是可选项：

1. **验证承诺**：漏洞的本质不是"某种模式"，而是"系统对自己的承诺与实际行为之间的偏差"。不问"我见过什么漏洞类型"（训练数据），问"系统承诺了什么？什么输入能让它违背承诺？"。承诺来源是系统自己的声明（规则文档原文、API 行为、防御设计），不是攻击者记忆。操作：提取承诺清单 → 对每个承诺构造最小反例（"若承诺 X 成立，输入 Y 就不该有结果 Z"）→ 定向拆穿实验。
2. **怀疑一切**：对系统暴露的所有可交互实体保持零信任——所有 API 端点、guest 内监听端口、unix socket、vsock 通道、host 侧可达服务、镜像内二进制、任何观察到的接口与服务器。深层推论：(a) 所有地方都有漏洞，且不止一种——补过的地方还有别的洞；(b) 每个漏洞不止一种绕过方式——防御只堵一条路，其他路还在（例：seccomp 拦 socket() 但 io_uring/fd 劫持/内核接口仍可能）；(c) 每个发现可反推其他漏洞——漏洞是图结构不是离散点，拦截点、已知清单、行为差异都是推理节点，可推导相邻漏洞（例："拦 AF_VSOCK"→"host 有 vsock 服务"→"协议解析面"→"解析 bug"）。
3. **成功非终点**：即便某条攻击路径成功访问进入目标，也不代表真正的成功，只是那条路恰好能进去；不代表其他路进不去，其他路径可能通向不同或更深的成果。成功与失败都不构成停止理由：一条路通了要继续找其他路，一条路死了更不代表其他路死。**怀疑任何地方**：不是返回成功就没有漏洞，也不是返回失败就没有漏洞——成功响应可能掩盖逻辑缺陷（越权成功、正常路径被滥用），失败响应可能泄漏信息、验证资源存在性、暴露时序差异，失败路径本身可能是攻击面；任何响应结果只是推理节点，不是无漏洞的终点证据。
4. **一个点即成功**：目标不是全面覆盖攻击面，而是把任意一个具体漏洞点打透、验证、提交。成功标准 = 至少一个真实可利用的漏洞点（哪怕 Low），而非系统级逃逸。
5. **项目启动前置检查（避免无意义查询）**：任何项目（不限目标平台）开始前，必须先收集四类信息——官方规则/政策（Policy）、Known findings 清单、作用范围（Scope/资产条目）、公开漏洞（Public disclosures/Hacktivity 历史提交）。基于四类信息列出"不算漏洞清单"，再评估新方向是否命中已知原语，确认存在 materially new impact 的假设后才开跑实验。禁止为已知漏洞或已知原语组合跑复现迭代（已知原语的新利用方式不构成新发现）。**行为链**：每次新任务/新方向/切换目标时，先输出四类信息收集状态与不算漏洞清单，用户确认后才开跑。
6. **只找不易被发现的漏洞（不按正常流程）**：常规漏洞挖掘流程（模式匹配、主动扫描、fuzz 字典、已知漏洞类别逐个尝试）能发现的漏洞已被补洞 AI 覆盖，即使存在也不投入；只找常规流程难以发现的——逻辑盲区、承诺偏差、负空间推理、行为考古、组合式利用。选点标准：选点前先问"这个漏洞常规流程容易发现吗"，容易发现的一律放弃。

## 核心思维框架

**漏洞挖掘的起点是系统的承诺，不是攻击模式。**

- ❌ 错误模式：拿到攻击面清单 → 按已知漏洞类别逐个尝试（CVE、经典模式、fuzz）→ 撞墙 → 换下一个面 → 全部撞墙后"收官"（这是模式匹配，补洞 AI 已覆盖）
- ✅ 正确模式：提取系统承诺 → 构造最小反例 → 定向拆穿 → 每个观察（拦截点/差异/残留）反推相邻漏洞 → 图式扩展

### 执行流程

1. **提取承诺清单**：从规则文档原文、API 行为、观察到的防御设计提取系统对自己的承诺（隔离、生效、级联、一致、完备）。承诺的每个字都是漏洞线索——特别是描述"限制"的句子（例：Vercel 规则原文"intercepts outbound TCP and DNS"自曝 UDP 面）。
2. **构造最小反例**：对每个承诺问"什么输入会让系统自相矛盾"。反例是定向实验不是扫描：若承诺 X 成立，输入 Y 就不该有结果 Z。
3. **拆穿并反推**：实验结果无论成败都是推理节点。拦截点=藏宝图（拦什么=藏什么）；成功路径=一条路（继续找其他路）；失败路径=一个堵点（补丁旁边的接缝）。
4. **单点打透**：任选一个最有希望的承诺，深度做到底，拿到一个真实漏洞点即成功。

## 实例：Vercel Sandbox 承诺清单（2026-08 提取）

## 执行纪律（2026-09-01 Vercel 窗口收官反思，必须遵守）

> 来源：Vercel 窗口 300+ 轮实验复盘——执行不慢，慢在**价值判断动作太晚**（查重在写证据之后、面关闭在开打之后、情报在开工之后）。核心：把"影响/查重/组合"三个检查从**实验后**挪到**实验前**。详见 经验/全局经验/经验学习18.md。

1. **实验前预期结果表**：每个实验脚本头部写明"成立→看到 X；不成立→看到 Y"，两轮内无法区分→放弃。禁止"先跑再修"——payload 写完先本地静态自查（格式串/时序/路径），不把代码 bug 当实验成本。
2. **面价值预判 + 时间盒**：开面先答三问——影响达标吗（不达标直接放弃）？设计是否天然隔离（per-sandbox/own-microVM → 大概率不成立）？几轮能到决定性证据（>10 轮或 >1 天 → 时间盒到即关闭）？
2b. **Git Bash 禁止 python -c 复杂代码（禁止条款，2026-09-01 升级）**：Git Bash 中 `python -c` 只允许无引号无分号单行；任何含引号/分号/多语句/多行的代码一律先 Write 脚本文件再执行（踩坑 5 次实证：-c 失败重试 2-4 分钟 > 写文件 40 秒，"快路径"实际是慢路径）。写命令前先判断"这条会被 bash 拆解吗"，会就写文件；grep/find 参数中 \| 与通配符同样须单引号或写脚本。
2c. **全局禁代理（禁止条款，用户 2026-09-01 指令：整个项目不论什么情况都不要用代理）**：所有漏洞测试流量一律直连，禁止走任何代理。测试脚本必须显式禁用代理：`requests.Session().trust_env=False` + `proxies={'http':None,'https':None}` 双保险，防止环境变量 HTTP(S)_PROXY 污染（本机环境变量配了 http://192.168.0.199:1080，但该代理不可用且直连已实测可达：forgeblocks.com 301 / ort-one-pingone.com 200 均直连正常）。需要代理的场景（如访问被墙知识库/下载依赖）与测试流量严格分离，测试脚本里绝不带代理。
3. **验证配比**：低价值面用 1-2 轮低成本探测丢弃；决定性实验（多轮对照矩阵）只留给高价值面。
4. **知识即时固化**：每类环境事实（沙箱类型差异、工具集、时序窗口、API 参数坑）踩到后 30 分钟内固化进驱动文件/档案注释，下一个实验直接查，禁止重复踩坑。
5. **提交前查重强制**：先花 5 分钟查 Hacktivity/历史报告确认不 dup、不撞 Known findings，再花 2 小时写证据。证据工程不能替代查重。
6. **链路/组合思维**：单端点探测只回答"这里有什么"；每个面关闭时过一遍"面组合矩阵"——哪些已确认原语组合可能形成新影响（跨层组合：网络放行 + 数据回传 = exfil；控制面动作 + 生命周期 = 数据面）。
7. **资源卫生**：实验自清理（DELETE 沙箱/快照/临时对象），不留垃圾配额债。
8. **意图对齐**：探索完一个面≠任务完成；定期对照用户目标（找洞/提交），不做"探索式收尾"。
9. **怀疑自己的结论**（怀疑一切的最后一块应用面）：怀疑一切不止用于系统，也必须用于自己产出的每一个结论——"关闭""N/A""归因"都是可被推翻的推断，不是事实。(a) **失败响应不是终点**："没看到 X"可能是观察方法/输入构造/触发时机不对，不是"X 不存在"——宣布面关闭前，必须写出 1 个违背关闭结论的输入并实际测它（换协议、换前置条件、换时机：如上传可能在沙箱 stop 后、需 s3:// 协议、需合法凭据字段）。(b) **结论分级**：观察标注"实证"vs"推断"，推断必须列出可推翻它的反例。(c) **N/A 不照单全收**：收到 N/A 后复盘报告是否把影响最大化、新根因（如协议级重放 vs ptrace）是否值得独立提交——"影响同类"是官方裁决逻辑，不是自动放弃理由。(d) **归因也怀疑**：对自己的失败归因定期问"还有没有第七层解释"（报告表达质量、裁决模式理解速度）。

### vda 盘考古（已完成，无提交价值，勿重扫）
- vda(254:0)=33GB，**每个 sandbox 调度到不同 host，vda 内容因 cell 而异**；0-64MB 跨 host 相同（共享基础镜像）。
- 0-33GB 全部扫完：无真私钥/token（AKIA=EXAMPLE、OPENSSH=源码片段、cert=公开 CA bundle、O=Vercel cell cert 是 public cert）。160-256MB 是**全零区域**。
- 单 MB 读取 100% 安全（96/96 验证）；64MB/段连续读随机杀进程（~5-10%，API 仍 200 空输出+落盘失败）；累计读 ~16-17GB 触发 410 sandbox_stopped。

### 可靠实验模式（所有沙箱实验必须遵守）
- 结果**落盘 + cat 双通道**，判据用哨兵串（如 "DONE" in out），失败自动重试（4-6 次）；网络类 cmd 输出丢失率高，必须落盘。
- 进程被杀（落盘也失败）≠ 暂时性通道故障（落盘成功）；410 sandbox_stopped = 需重建 sandbox 继续。

### 网络拓扑（跨租户面已关闭，勿重扫）
