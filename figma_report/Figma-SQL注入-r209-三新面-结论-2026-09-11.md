## 三、面② code_connect in_context 三端点（集合位 `asset_keys`，43 发）

- **校准**：缺字段 → 400 `asset_keys is required`；空数组 → 400 同；类型混淆（字符串非数组 / 数字 / 对象 / 嵌套数组元素）→ 400 `Error in route typechecking for /api/code_connect/...`（**路由声明式校验**）。

## 四、面③ voting_sessions（写面全字段，~95 发）

### 4.1 关键转折：单活跃会话门与污染（本次最大方法论教训）

- **门实证（G 组）**：G1 create→200；G2 第二发 create（同文件）→ **400 泛化 `Bad request.`**（1.6s）；G3 PUT 结束→200；G4 再 create→200。⇒ 同文件**仅一个进行中会话**，第二发一律泛化 400。
- **污染事故**：首轮矩阵（r209m）V 组 7 发"title 拒绝引号/特殊字符"**全部是门假象**（V1 创建后未即时清理）；m2 的 B/C 组同被污染。净化重测（m3，逐发 create→delete）后**全部翻案**。

### 4.2 净化矩阵（全负 + 正面铁证）

| 槽位 | 矩阵 | 结果 | 判读 |
|---|---|---|---|
| `title`（V1） | `'` / `"` / `%` / `;` / U+2019 / `\` / 300 字 / `' AND '1'='1` / `';SELECT pg_sleep(4)--` | **全 200，原样回显入库**，零时延（398-534ms） | **参数化铁证（回显法）** |
| `user_vote_limit`（V2） | JSON 数字 1 → 200；浮点 1.5 → 200 但**截断为 1**；字符串 `"2"`/`"1+1"`/`"1'"`/sleep 形 → **500 零时延**；null/数组 → 400 required | 全负 | **类型空转**：Ruby `String#floor` 型 NoMethodError；非 SQL（SQL 插值下 `"2"` 必成功） |
| `page_node_id` | `0:1'` → 400 `Missing or invalid required parameter page_node_id` | 格式校验 | GUID 正则先行 |
| `in_progress` | 字符串 `"true"` → 200（宽容强转 true） | 宽容 | 注入空间零 |
| `num_people_in_file` | `"1'"` → 200（to_i/吸收） | 吸收 | 与 uvl 不同处理路径（画像） |
| PUT/DELETE 真 id（路径位） | `/idabc`、`/id'`、`/id'--` → **全 200 且动作真生效**（会话被结束/删除；plain 复删 404） | 全负 | **to_i 写面版**（解析值真参与操作） |
| `voting_session_id_to_end` | plain / `'` / `'--` 三态全等（B 创建成功=A 被结束）；**不存在 id → A 未被结束 → B 被门拦 400（阴性对照）** | 全负 | to_i + 参数化；解析值真参与关联操作 |
| PUT/DELETE 非存在 id | `1` / `1'` / `1 OR 1=1` → 404 `Not found.` ×3 同构 | — | 反枚举同构 |

### 4.3 写面净化纪律执行结果

全程 create→操作→delete，收尾再 create→delete 确认门释放；**净残留 0**（会话 567310-567340 系列全部删除，含 567326 补清）。

## 六、画像与缺陷记录（记录，不提交）

1. **`user_vote_limit` 字符串 → 500**：类型空转健壮性缺陷；响应泛化（无栈/无泄露）、无数据影响 → 不单独报告，作为"500≠注入"反例入库。
2. **单活跃会话门**：同文件第二发 create → 400 泛化（伴耗时 1.0-1.6s）——行为画像。
3. **写面 to_i 前缀解析**：PUT/DELETE 路径与 `id_to_end` 尾缀吸收且**动作真生效**——与读面同族。
4. **in_context 判别面未激活**：缺真实 asset key 样本（响应键 `"lk-…,guid"` 复合已验证结构）——待未来有样本再激活。
