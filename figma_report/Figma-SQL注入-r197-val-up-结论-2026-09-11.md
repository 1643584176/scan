# Figma 值→标识符升格族（val-up）三面结论（r197，2026-09-11）

> 面①：`/api/versions/{fk}` 路径位（前轮反编译中的 `$1` 绑定位）
> 面②：`/api/folders/{id}/paginated_files`（query `folderId` + path `id`）
> 面③：`/api/resource_connection_invite/folder_search`（`org_id`/`team_id`）
> 方法：三态升格实验（基线 / 自引用恒真 / 残缺语法崩）+ 校准针（格式合法不存在值）+ 引号突围 + 算术对
> 结论：**三面升格族零信号，全部机制归属；无提交物。** 新增 2 条判别技术（to_i 截断矩阵 / 死参数判定）与 1 条纪律（403 校准针）。

---

## 一、实验设计

升格族问题：值位输入会不会在后端被当**标识符/表达式**用（`WHERE file_key = fv.file_key` 恒真、`folder_id = 634606972+1` 参与运算）?

| 态 | 构造 | 升格时的预期异常 |
|---|---|---|
| 基线 | 真值（可达 key/id） | 200 正常数据 |
| 自引用 | `fv.file_key` / `folderId` / `file_key` | 恒真 → 结果集炸开/异样 |
| 残缺 | 真值+尾点/尾引号（`key.` / `key'` / `id.` / `id'`） | 裸拼接 → SQL 语法错 500 |
| 校准针 | 格式合法但不存在值（随机 key / 相邻 id） | 定 403 语义（默认分支 or 差异） |
| 算术（数值位） | `id-0` vs `id+1` | to_i 截断=全同基线；表达式= -0 同 / +1 异 |

## 二、面① `versions/{fk}` 路径位（6 发）

| 发 | 路径值 | 结果 | 判读 |
|---|---|---|---|
| V1 | `laF5…KJ4e`（真 key，可达） | 200 957ms 返回 versions | 判别面激活 |
| V2 | `fv.file_key` 自引用 | 403 355ms `cant_view_file` | 与不存在同构 |
| V3 | `file_key` 裸列名 | 403 352ms | 同构 |
| V4 | `laF5…KJ4e.` 残缺 | 403 351ms | 无语法崩 → 非裸拼接 |
| V5 | `q1w2…p0a1`（随机 22 位） | 403 702ms | **校准针 = 403 反枚举默认分支** |
| V7 | `laF5…KJ4e'` 尾引号 | 403 360ms | 引号突围无崩 → 非带引号拼接 |

**判定**：403 反枚举默认分支（V5 校准，五种形态全同构）；V4/V7 无 500 排除两类裸拼接 → 残余机制 = 参数化 or 权限门先行（按原值判权），**两者均不含标识符升格 → 升格排除**。

## 三、面② `folders/{id}/paginated_files`（14 发）

### 3.1 query `folderId` —— 死参数（未消费）

7 值变体：C1 基线(FID=634606972) / C2 `folderId` / C3 `FID-0` / C4 `folderId.` / C6a `634606973` / C6b `1` / C1r 重放

**全 200**，且 JSON 结构级比对逐文件逐字段一致：同 5 文件、同序、同 `folder_id`（唯一差异 = 瞬态 `realtime_token`）。
→ **参数未消费（死参数）**：不是"参数化安全"，是"值根本没进任何环节"。记为画像（无安全影响）。

### 3.2 path `{id}` —— to_i 前缀截断

| 值 | 结果 | 判读 |
|---|---|---|
| `634606972` | 200 基线 | 判别面激活 |
| `folderId`（自引用） | 403 | 串→数字转换失败/无权限（同构） |
| `634606973`（相邻不存在） | 403 | 反枚举默认 |
| `636027532`（他属 folder） | 403 | 403 同构（*账号 A 不可达，画像*） |
| `634606972-0` | 200 同基线 | 截断 = 原 id |
| `634606972+1` | 200 同基线 | **若表达式参与应查 634606973 → 403；实测同基线 → 非 SQL 表达式** |
| `634606972.` | 200 同基线 | 截断 = 原 id（`.` 无语法崩） |
| `634606972'` | 200 同基线 | 截断 = 原 id（引号被丢弃） |

**判定**：应用层 to_i 式数字前缀截断（后缀全丢弃）→ 值带不进任何语法 → **升格排除**。

## 六、画像（记录不提交）

1. **死参数**：`paginated_files` 的 query `folderId` 被服务端忽略（任意值全同）——不影响数据面。
2. **to_i 截断**：path id 取数字前缀（`-0/+1/./'` 后缀全丢弃）——与 H1 user_ids parseInt 同族。
3. `realtime_token` 动态字段：`/file-<key>:<ts>:0:<hmac>`、`/folder-<id>:<ts>:0:<hmac>`，每请求必变（diff 前必剥离）。
