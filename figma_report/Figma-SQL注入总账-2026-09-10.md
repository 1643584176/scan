## 三、防御模型终版（跨面归纳）

**七层结构**（按拦截顺序）：

```
1. route typecheck        声明式参数类型校验（数组语法/JSON 解析级）
   └ 指纹: Error in route typechecking ... Expected string/Number/Array/JSON @L:C
2. Rails 强参数            expect/permit + 双解析路径
   └ 指纹: Invalid query parameters: expected Array (got String / Rack::QueryParser::Params)
3. 参数映射层             外部名→内部名（file_type→editor_type）
   └ 指纹: 消息暴露内部名
4. schema/白名单/枚举     精确匹配（不归一化）/静默回退/trim 分裂/清洗存活
   └ 指纹: Invalid sort_column parameter / must be 'asc' or 'desc' / 静默回退
5. 参数化（搜索字符串位） 全静默 + 零时延 + 结果无差分
   └ 终判: pg_sleep 嵌入合法表达式零延迟
6. opaque token           游标/cursor 服务端生成（base64+JSON / max_nesting=100）
   └ 指纹: 浅层 500 + rescue 边界
7. 权限门                 403 家族 + 反枚举默认分支 + 计划门
   └ 指纹: no_permission / no_permission_contact_org_admin / 403-404 不可辨
```

**分裂行为备忘**（同名家族不可跨端点外推）：
- 枚举位：`account_type_request ` 尾空格拒（精确） vs `credits_used ` 放行（trim）——逐端点独立确认
- 403 模板：`You don't seem to have permission` vs `...Contact your organization administrator`——门类型不同
- 处置模式：白名单拒绝（sort_column）/ 静默回退（file_type）/ 清洗存活（folder_search query）/ 静默宽容（related_links 批量）
