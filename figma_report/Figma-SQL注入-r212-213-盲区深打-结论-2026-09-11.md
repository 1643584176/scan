## 二、逐面矩阵与判定

### 2.1 `GET /api/resources/group_by_team/{orgId}` —— 探活即门死

| 发 | 构造 | 结果 | 判读 |
|---|---|---|---|
| 历史 r6 | A/B 双 org | 403 `Contact your organization administrator` | **org admin 门** |
| 判定 | 参数注入不可达（403 先于参数解析，按总账模型） | **判死（门内）** | — |

注：该面 V6 逗号串（resource_type）、I3（sort_by）、数字位（num_resources_per_team）均为 q26 A2 标注盲区，但门不可达，无法测参数层。

### 2.2 `GET /api/files/{fk}/videos/{sha1}/thumbnails` —— 三层墙 + 数据面永空

**JS 形态**：`toAPIParameters({max_results, start_timestamp_ms, end_timestamp_ms})` + 路径位 `sha1`（视频媒体哈希）。

| 发 | 构造 | 结果 | 判读 |
|---|---|---|---|
| V1 | videos 列表（自有文件） | 200 `{videos:{}}` | 无视频数据（空集） |
| V4 | `/videos/{sha1}/upload` | 403 `uploads can only be performed on files that belong to a subscribed team` | **付费计划门**（免费团队永远无视频媒体） |
| V2/V3/V10 | 假 sha1 基线 / 数字位冒烟 / max_results=-1 | 404 `error.not_found` | 无媒体记录（业务级 404） |
| V6/V7/V8/V9 | sha1 尾引号 / OR / pg_sleep / 短值 | **400 `Missing or invalid sha1`** | **路径位 hex 格式墙**（注入字符串不可达） |
| V11 | `start_timestamp_ms=0'` | **400 `Error in route typechecking ... Non-number characters in quoted integer`** | **数字位 route typecheck** |
| V12 | `end_timestamp_ms=99999999999999999999` | **400 `... Integer overflow`** | **数字位溢出校验** |

**判定**：路径位（V1 [x] 格式墙）+ 数字位（V2 [x] typecheck+溢出）双层封死；且上传侧 403 计划门导致**数据面永远为空**（连判别面都不存在）→ **判死**。

### 2.3 `GET /api/make/ds_import_libraries` —— 静默宽容（无差分）

**JS 形态**：`toAPIParameters({org_id, library_key, include_nonextracted_libraries:"true"})`（DS 导入库列表）。

| 发 | 构造 | 结果 |
|---|---|---|
| D1/D2/D3 | 基线（org_id=TEAM_A）/ library_key=abc / 重打 | 200 `{meta:[]}` |
| D4 | library_key=`abc'` | 200 同构 |
| D5 | library_key 时延盲注 | 200 同构 425ms（零延迟） |
| D6 | org_id=`TEAM_A'` | 200 同构（org_id 无类型校验） |
| D7/D8 | org_id=0 / 999999999999 | 200 同构 |
| D9/D10 | include_nonextracted_libraries=true / library_key 空串 | 200 同构 |

**判定**：全形态同构 200 空 + 零时延（引号存活 = 清洗宽容或参数化；无 org 存在性差分）。**空数据面 + 静默宽容**——按判读库标准不记「参数化安全」，记「判别面未激活」→ **判死**。

### 2.4 `GET /api/billing/notification_settings` —— 格式墙 + 枚举墙 + 静默宽容（三层）

**JS 形态**：`toAPIParameters({plan_id, plan_type, notification_type})`，响应 `meta:{frequencies, recipient_settings, recipients}`。

**plan_id 语义确权矩阵（完整）**：

| 发 | 构造 | 结果 | 指纹 |
|---|---|---|---|
| N1/N2 | 缺 plan_id | 400 `Missing required parameter plan_id` | 必填 |
| N3 | UUID 值 | 400 `must be a valid number, received type String` | 非十进制拒 |
| N4 | TEAM_A（19 位十进制） | **200**（无 meta——空设置） | 通过 |
| N5 | TEAM_B（他人 team） | **403 `Contact your team administrator`** | **值消费+权限判别** |
| N11/N23/N21 | 12345 / 19 位大数 / 0 | **403 同模板** | **存在性与无权限同响应（不可辨）** |
| N12 | `TEAM_A.0` | 400 | 浮点尾拒 |
| N13 | `0TEAM_A`（前导零） | 400 | **无前导零（除单 0）** |
| N14 | `%20TEAM_A`（前导空格） | **200** | **trim 后校验** |
| N15/N16 | `1e18` / `1e999` | 400 | 科学计数拒 |
| N22 | 30 位数字 | 400 | **≤19 位（int64 量级）** |
| N8/N9/N10 | 尾引号 / 布尔 / pg_sleep | 400（同 106 字节文案） | 注入形态全被格式层拒 |

**plan_type**：`junk` → 400 `Invalid plan type: junk`（枚举白名单 {team, organization} 精确）；`organization`+TEAM_A → 404（分支查询消费）；缺省 → 400。
**notification_type**：junk / 尾引号 / OR / pg_sleep / 布尔 → **全 200 同构 40 字节**；空串 → 400「缺失」（空串=缺参数语义）；时延零。

**判定**：plan_id=强格式墙（十进制/int64/trim/无前导零；注入字符串全 400）+ plan_type=枚举墙 + notification_type=静默宽容无差分 → **判死**（V3 数字位 [x] / I4 枚举位 [x] / V1 静默）。
