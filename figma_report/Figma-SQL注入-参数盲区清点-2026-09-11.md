# Figma SQL 注入「参数盲区」清点（q21-q25 对账，2026-09-11）

> 问题：历史打过的面中，有没有「JS 逆向已暴露、但我们没想到/没打过」的参数？
> 方法：`_q21_param_gap.py`（全量差集）→ `_q22_param_audit.py`（URL 调用点窗口法提取端点×参数）→ `_q23_blindspot.py`（命中计数）→ `_q24/q25`（定向复核上下文）

## 一、结论总述

**是，有。** 三层盲区：

| 类型 | 数量级 | 说明 |
|---|---|---|
| A. 已打面 × 未打参数 | ~10 组 | 面测过但 JS 真实参数集没打全（部分因参数名形态错误而假阴性） |
| B. 零覆盖新面 | ~8 个 | 端点从未发过请求（或只被无参探活） |
| C. 假阴性风险 | 1 类 | camelCase 参数名 → 服务端未识别 → 静默 200 误判（A5 陷阱同类） |

## 四、C 类：假阴性风险（参数名形态）

- 已知实证（A5 序列化名陷阱）：counts 端点真名 `query_string/request_permission_level/view_all`，打 camelCase → 静默 200 未识别。
- 嫌疑复盘点：凡「打过的参数」中 camelCase 形态直接发出而未回显/无差分的，需要按 snake_case 重打一遍确认（如 A8 `ids` vs `widget_ids`）。
- 清单化建议：对总账 25 面中所有"静默宽容/200 空"的判定，抽查其参数名是否与 JS `toAPIParameters`(camel→snake) 输出一致。
