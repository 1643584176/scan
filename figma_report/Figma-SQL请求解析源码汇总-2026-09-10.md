## 一、客户端请求构造链（JS 逆向）

### 1.1 三个序列化器（请求参数出站前的统一转换）

```js
y.toQueryParameters = function(e, t=[]) { return void 0===e ? e : T(e, new Set(t), b) }
y.toBodyParameters  = function(e, t=[]) { return void 0===e ? e : T(e, new Set(t)) }
y.toAPIParameters   = function(e, t=[]) { return void 0===e ? e : T(e, new Set(t), b) }
y.toCamelCase       = function(e) { return e.transform(...) }   // 反向: 响应侧 camelCase 化
```

- `T(...)` = 递归变换器；第三个参数 `b` = **名称变换函数（camelCase → snake_case）**
- 语义：逻辑层用 camelCase 字段名，出站时经 `toQueryParameters/toAPIParameters` 转 **snake_case** 发送
- **陷阱实证（A5 序列化名）**：counts 端点客户端发 `query_string / request_permission_level / view_all`；测试打 camelCase `requestPermissionLevel` → 静默 200（参数未被识别）→ 误判风险极高。**静默 200 的第一嫌疑是"参数名没被读取"**

### 1.2 数组参数构造器 addRepeated（`name[]` 后缀）

```js
class A {
  constructor(){ this.params = new URLSearchParams }
  addRepeated(e, t){ t.forEach(t => this.params.append(`${e}[]`, t)); return this }
  add(e, t){ void 0!==t && this.params.set(e, String(t)); return this }
  build(){ return this.params }
}
```

- 数组元素 → `name[]=v1&name[]=v2`（**方括号后缀**）；单值 → `name=v`（`String()` 强转）
- 与服务端双解析路径呼应：`[]` 名走数组收集，裸名走 route typecheck（见 2.2）

## 二、服务端解析行为反证据（拦截层指纹）

### 2.1 拦截顺序链（七层，跨面归纳）

```
route typecheck → Rails 强参数 → 参数映射 → schema/白名单/枚举 → 参数化 → opaque token → 权限门
```

### 2.2 双解析路径（同一参数名的两种命运）

| 形态 | 路径 | 指纹 |
|---|---|---|
| 裸名 `request_types` | route typecheck（JSON 文本级） | `Error in route typechecking ... Expected: '['` |
| `request_types[]` | Rails 数组收集（强参数） | `Invalid query parameters: expected Array (got String)` / `got Rack::QueryParser::Params`（下标形态） |

### 2.3 反证据速查（测试→服务端应答→判读）

| 探测 | 服务端应答 | 判读 |
|---|---|---|
| `file_type[]=design`（folders 面） | 400 `editor_type must be a string, received Array` | **参数映射层**：外部名 file_type → 内部名 editor_type |
| `query[]=team`（folder_search） | 400 `Error in route typechecking ... Expected string` | 数组语法穿透到声明式校验层被拒 |
| `request_types` 裸名混发 | 400 Rails 强参数 | 双解析路径分叉 |
| `sort_column=junk` | 400 `Invalid sort_column parameter` | 白名单值级校验 |
| `sort_order=x` | 400 `must be 'asc' or 'desc'` | 枚举白名单 |
| `request_permission_level=admin` | 400（{guest,member} 外全拒，**无 trim**） | 精确匹配 |
| `billing_group_ids[]=01` | 200 空 | `\d+` 正则（前导零宽容） |
| `page_size=abc` | 400 `must be a valid number, received type String` | schema 类型校验 |
| cursor = b64(任意 JSON 非 null) | 500（app;dur 与 200 同量级） | opaque token 浅层崩（rescue 边界 80/120 层 → max_nesting=100） |
| related_links 批量任意元素 | 200 `meta:[]` 零差分 | 静默宽容（无差别集合查询） |
| export 任意 body（含空） | 403 `no_permission_contact_org_admin` | **权限先于参数解析** |
| recent_activity 非法枚举 + foreign 文件 | 400 `Unsupported activity_type` | **参数校验先于权限** |

### 2.4 403 家族（两种模板 = 两种门）

| 模板 | 消息 | i18n id | 语义 |
|---|---|---|---|
| A | `You don't seem to have permission to do that.` | `error.no_permission` | 资源/功能门（related_links 单文件端点、comments 等） |
| B | `You don't have permission to do that. Contact your organization administrator.` | `error.no_permission_contact_org_admin` | **组织管理员门**（activity_logs/export 审计面） |

### 2.5 校验顺序指纹（同项目内逐端点不同，必须实测）

```
recent_activity : 参数值校验 → 权限（foreign + 非法枚举 = 400；foreign + 合法枚举 = 200）
activity_logs/export : 权限 → 参数（空 body 也 403）
related_links 单文件 : 计划门 403（参数无关，自有文件亦然）
```

## 四、完整链路图（客户端 → 服务端）

```
[客户端 JS]
  UI 状态(camelCase) 
    → A#add/addRepeated 构造 URLSearchParams（`name[]` 数组后缀 / String() 强转）
    → toQueryParameters/T(e,Set,b) snake_case 名称变换
    → fetch(POST/GET, {headers: Cookie + X-Figma-User-ID + Content-Type})
        │
[服务端]
  route typecheck ── 数组语法/JSON 文本级 ──→ 400 "Error in route typechecking ... Expected ..."
    │
  Rails 强参数 ──── 裸名 vs [] 双解析路径 ──→ 400 "Invalid query parameters ..."
    │
  参数映射（外部名→内部名） ────────────────→ 400 "editor_type must be ..."
    │
  白名单/枚举/正则（精确匹配/静默回退/清洗） → 400 "Invalid ..." 或 200 回退
    │
  业务查询（参数化 / keyset 游标 / opaque token）→ 500 浅层崩(快) 或 200
    │
  权限门 ─────────────────────────────────→ 403 no_permission / no_permission_contact_org_admin
```

## 五、RST 瞬态规律（测试环境备忘）

- 现象：每波会话**首 1-5 发**偶发 `ConnectionResetError(10054)`（r196ao 前 5 发 / r196ap 前 2 发 / r196aq 首发即通）
- 判读：**网络层瞬态**，与内容/权限无关（后续请求全部正常，同 payload 重打即通）
- 纪律：RST 不得作为"内容触发"证据；重打确认——若**持续** RST 才升级排查
