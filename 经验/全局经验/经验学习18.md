# 经验学习18：Vercel 窗口收官复盘——为什么慢与执行改进机制（2026-09-01）

## 一、背景

Vercel Sandbox HackerOne 窗口（2026-08-18 ~ 09-01）收官：**6 份报告全部 N/A/dup，0 赏金**（其中 2 份自撤/自评未提交）。
本复盘不归因于"系统难"，归因于**我们的执行系统**：300+ 轮实验、20-50 小时纯实验时间，
有效提交仅 4 份且全部获 N/A/dup 裁决。用户问题"为什么找漏洞这么慢"触发本复盘。

## 二、慢的分层归因

### 1. 结构性（最根本）：项目本身成功率极低
- 合格标准 = EC2 host 新逃逸 / 跨租户 / firewall bypass+凭据 exfil / 新 host 写原语 / 控制面 IDOR——全是需越过 microVM 信任边界的最难类别
- Known findings 清单（A.1-A.7/B.1-B.7）已把 guest 侧所有原语列完（vda/containerd.sock/vsock/metrics/OIDC/caps、/dev bind）——清单之外只剩 dup 或真逃逸
- 4 份有效提交（3 份 N/A + 1 份 dup）全部落空是奖池设计使然：赏金 $25-50k 挂着但可达性≈0；Hacktivity 无 paid 先例
- **教训：开工前给项目打分**（历史 paid 报告数 × Known findings 覆盖率 × 合格标准可达性），低分项目按"低投入验证型"对待（几天确认不可行即撤），不全力投入

### 2. 策略性（最致命）：选点没有价值排序
- 大部分轮次花在"大概率安全的面"上。典型：interactive 面（v218-228 共 11 轮）——per-sandbox 设计决定了 token 必然强绑定、执行必然在 guest 内，**从一开始就该预判**，却用 11 轮证明
- 每面开打前没问"如果成立，影响达标吗？"：bucketBaseUrl SSRF 即便成立也只是控制面到 IMDS 的完整链路才 High
- 反证：唯一真实缺陷 fw_vpc（custom 防火墙私有网段放行）8/29 才打，且最终 dup——正确方向存在，但没有按"影响×概率"排到前面

### 3. 流程性：负向确认实验占比过高
- 大量轮次在"确认安全"（SSRF 关闭、快照关闭、端口枚举、集群扫描）——对提交零贡献
- 决定性实验（多轮对照矩阵）应该只留给高价值面；低价值面 1-2 轮低成本探测直接丢弃
- 没有时间盒：一个面可以被反复打磨到"决定性闭环"，而它从第一天起就不该进入候选

### 4. 执行性：返工率高
- v220 token 写入格式串 TypeError、v221 token 时序竞态、v225 双快照 422（v216 已知"snapshot 会 stop 沙箱"却未复用）——**每次失败后修复，但没有"修复后反查同类"**，同类坑在不同实验里重复踩
- SearchReplace 对长文件反复失配（应先 Read 确认实际内容再改）；Git Bash 引号问题反复出现（应默认写脚本文件）；guest 工具集（无 nc/ip/hostname）到 v227 才确认
- **估算：至少 1/4 轮次是返工，省下来等效多 3-4 天有效挖掘**

### 5. 决策性：价值判断动作太晚
- 查重（fw_vpc 未查 #3951926 就写了 19 个证据文件 → dup 全白写）；情报（Hacktivity paid 历史、官方裁决模式应开工第一天建图，却靠 4 次 N/A 被动总结）；面关闭/开启判断全在实验后
- 验证配比失衡：interactive 关得太慢（11 轮），bucketBaseUrl 关得太快（没问"什么条件下才上传"——未回答的问题≠已关闭的面）

### 6. 认知性：链路思维出现太晚
- 早期全是单端点探测；第一条真正有含量的链（init.sock 签名重放：uid1000→sudo→socket 替换→签名捕获→120s 重放）到 v205 才出现（窗口已过 2/3）
- 应早做**面组合矩阵**：哪些 N/A 原语组合可形成新影响（网络放行+数据回传=exfil；控制面动作+生命周期=数据面）

### 7. 元认知性：怀疑一切只用于系统，没用于自己的结论（用户追问"还有啊怀疑一切"触发）

**最大的盲区：我们把"怀疑一切"用在了目标系统上，却把自己产出的每一个结论（关闭/N/A/归因）当成事实接受。**

实证（本窗口真实发生）：
- **失败响应当终点**：v222 bucketBaseUrl "webhook.site 零请求"→ 判定"不上传、关闭"。但没验证上传是否需要 s3:// 协议（只测了 http/https）、是否需要前置条件（合法凭据字段）、是否发生在沙箱 stop 之后（没在 stop 后查 webhook）——"零请求"可能只是输入构造不对，不是"不上传"。未验证的关闭 = 未回答的问题。
- **自己的判定没构造反例**：token 绑定只在 guest 内（v221）交叉验证；v228 公网代理层只用了真 token，没做公网交叉测试（代理层校验可能与后端不同）。snapshotId 忽略只测了自有快照，没测已删除 id / 跨 project id 的报错差异（可能泄露存在性）。
- **N/A 照单全收**：#3972961 报告未包含后续发现的 cell.sock 无认证 API 全集；init.sock 协议级重放与 #3955363（ptrace）是不同根因，自判"影响相同→N/A"直接归档，未挑战"影响相同"是官方裁决逻辑还是我们的推断。
- **归因不怀疑**：前 6 层"慢"归因之外，未主动怀疑报告表达质量、裁决模式理解速度等第七层解释。

## 三、改进机制（每条对应一个归因层缺陷，以后每个实验强制执行）

1. **实验前预期结果表**：脚本头部写明"成立→看到 X；不成立→看到 Y"，两轮无法区分→放弃
2. **先自查再跑**：payload 写完本地静态检查（格式串/时序/路径），不把代码 bug 当实验成本
2b. **Git Bash 禁止 python -c 复杂代码（禁止条款，2026-09-01 踩坑 5 次后升级）**：`python -c` 只允许无引号无分号单行；含引号/分号/多语句/多行一律先 Write 脚本文件再执行。实证：-c 失败重试 2-4 分钟 > 写文件 40 秒，"看起来快的 -c 实际是慢路径"。写命令前先判断"这条会被 bash 拆解吗"（\|、通配符、括号都是雷）。关联记忆：Windows Git Bash 陷阱集（已合并 4 条重复为 1 条禁止条款）
3. **面价值预判三问**：影响达标吗？设计天然隔离吗？几轮到决定性证据？（>10 轮或 >1 天 → 关闭）
4. **知识即时固化**：环境事实（沙箱类型差异/工具集/时序窗口/API 参数坑）踩到 30 分钟内固化进驱动注释
5. **提交前查重强制**：先 5 分钟查 Hacktivity/历史报告，再写证据；证据工程不能替代查重
6. **验证配比**：低价值面 1-2 轮丢弃；决定性实验只给高价值面
7. **组合矩阵**：每面关闭时过一遍已确认原语的组合可能性
8. **资源卫生**：实验自清理，不留配额债（本窗口曾残留 50 快照打爆 Hobby 配额）
8b. **脚本管理**（本窗口产出 770 个一次性 py，收尾归档 768 个）：每轮实验独立 _run_vXXX.py 不合并、_parse/_extract/_peek 系列本可合并为通用工具、失败脚本不删除——规则：a) 同面实验复用同一驱动文件（参数化），不新建编号；b) 输出读取类工具统一为一个（读 cmd 输出/解析 json 行）；c) 失败实验脚本当轮删除或标 FAILED；d) 每周归档一次已完成实验到报告目录
9. **意图对齐**：探索完一个面≠完成任务；定期对照"找洞/提交"目标，不做探索式收尾
10. **怀疑自己的结论**（最高优先级）：(a) 失败响应不是终点——面关闭前必须写出 1 个违背关闭结论的输入并实际测它（换协议 s3:// / 换前置条件 / 换时机：上传可能在沙箱 stop 后）；(b) 结论分级——观察标注"实证"vs"推断"，推断列出可推翻它的反例；(c) N/A 不照单全收——收到 N/A 后复盘报告是否影响最大化，新根因是否值得独立提交；(d) 归因也怀疑——对自己的失败归因定期问"还有没有第七层解释"

## 四、有效做法（保留）

- 决定性实验设计：双沙箱交叉（token 绑定）、同沙箱策略切换（fw 四阶段）、marker 读回（快照恢复）、延迟重放矩阵（A/B/C/D 对照）
- 协议级攻击：手工 ConnectRPC/protobuf/gRPC h2c/ws 帧，不依赖现成客户端
- 公网回连捕获（webhook.site）验证"服务端是否真的发起请求"——SSRF 判定手段（注意："零请求"后须排除输入构造/触发时机问题，见第 7 节教训，零请求≠不上传）
- 双账号 attacker/victim 对照验证授权隔离
- 环境侦察：/proc/net/tcp6（宿主监听）、/proc/net/unix（socket 影子）、vda 挂载读宿主脚本

## 五、结论

慢的本质：**没有筛选机制，只有执行机制**。执行能力（300 轮实验、协议级逆向、决定性实验）是高水平
的，但执行的是"探索"（这里有什么），不是"寻宝"（这里值不值得挖）。最核心一条改进：
**把"影响/查重/组合"三个检查从实验后挪到实验前**。

最后一条（用户补充）：**怀疑一切也包括怀疑自己的结论**——关闭、N/A、归因都是推断不是事实，
每个结论都要能写出一句话推翻它。未验证的关闭 = 未回答的问题。
