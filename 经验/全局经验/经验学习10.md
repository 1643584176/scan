# 案例:网关层拦截识别 / 搜索索引越权验证 / SSRF 价值分级 / 混合参数 ACL 验证

> 定位:案例复盘(2026-08-12 Figma 会话沉淀)。适用于所有 SaaS 目标,结论必须实测验证。

## 1. 网关层拦截识别(403 纯文本 = 不是 ACL)

**信号**:请求返回 `403 Forbidden` **纯文本**(无 JSON 错误结构、无 i18n 错误对象)时,大概率是**网关/代理层(WAF/nginx/ALB)拦截**,不是业务 ACL。

**判定三步**:
1. 打同一前缀的**任意不存在的路径**(如 `/api/internal/foo`)——如果也 403,说明是前缀级拦截
2. 打**非该前缀的对照路径**(如 `/api/search/...`)——如果 200,确认拦截是前缀级的
3. 用**真实浏览器会话 + 完整头**(含 x-csrf-bypass、client-version、tsid、WAF cookie)重试——仍 403 则坐实网关拦截

**结论判定**:
- 前缀白名单拦截(如 `/api/internal/` 只放行 WS 升级握手)→ 该通道**浏览器 JS 从不直接请求**,resolver/内部端点只由服务端内部转发 → **攻击面关闭,无需再让用户抓包**(浏览器里永远抓不到这类请求)

**要点**:连"受害者自己打自己的数据"都 403 = 与身份无关,是通道问题。先做这一步再怀疑 ACL。

## 2. 搜索索引越权验证(文件标题/元数据泄露)

**场景**:平台有搜索功能时,搜索索引若权限过滤不严,会泄露无权文件的标题/元数据(经典信息泄露)。

**方法**(三组对照缺一不可):
1. **越权面**:攻击者搜目标文件的**特征词**(文件名、creator_id、唯一数字串)
2. **基线**:文件拥有者搜同样的词——确认文件确实在索引里、搜索接口本身正常
3. **对照**:攻击者搜自己的文件——确认接口对攻击者正常

**细节**:
- 用唯一特征词(如 `creator_id` 数字)而不是通用词("Untitled"),避免噪声
- `link_access=view`(链接共享)文件可能**不进入**接收方索引——搜索不到不代表泄露,不代表越权
- 返回结构可能是 `meta[0].results[]`,解析时注意嵌套

## 3. SSRF 价值分级(什么值得报)

| 能力 | 判定 |
|---|---|
| 内网/云元数据可达 | Medium+ 值得报 |
| 公网回显 + 内网隔离 | **备胎级**:by design 风险高,建议不提交(攻击者自己 curl 公网无业务差异) |
| 编码绕过字符串过滤(hex IP)但网络层隔离 | "防御可绕过 ≠ 业务可绕过",H1 不吃,只作为报告里的支撑细节 |

**判断要点**:服务端 fetch 环境是否 = 用户沙箱环境。若用户在沙箱里本来就能 curl 公网,downloadUrl 无新增能力 → Informational。

## 4. 混合参数批量 ACL 验证

**场景**:批量端点(如 `?team_ids=A` )返回 400/403 时,用**混合参数**区分"批量逐项校验"与"单对象校验":

- `?team_ids=A`(无权)→ 400 "does not have access"
- `?team_ids=B`(自己)→ 200
- `?team_ids=A&team_ids=B`(混合)→ 200 但**只返回 B**,A 被静默过滤 → **批量端点逐项校验,ACL 正确**
- 若混合返回 A 的数据 → 批量 IDOR

**关键**:400 参数校验错误 ≠ 无 ACL,必须带全参数打到 ACL 层才能下结论。错误文案 "User does not have access to one of the requested teams" 本身就是确定性 ACL 证据。
