# 经验学习 11：多域共享身份架构的 token 链与服务面测绘（Superhuman×Grammarly 实战）

## 背景

Superhuman 收购 Grammarly 后，认证与订阅沿用 Grammarly 架构。目标：找出跨域共享数据导致的越权/泄露。核心难点不是"接口怎么调"，而是**用哪个域的 token 打哪个网关**——不同域签发的 token 的 `aud` 不同，决定了网关访问权。

## 关键链（可迁移方法论）

### 1. 同构 mediator 链 = 各域 token 的免费入口

每个域（id.superhuman.com / settings.superhuman.com / account.grammarly.com）都有同构链：

```
GET {domain}/v1/mediator/initiate（带已登录 cookie）
→ 302 到 {authBaseUrl}/tokens/v4/api/oauth2/authorize?client_id=xxx&scope=grammarly.capi.all
→ 已登录会话 307 直接带 code 回调（免交互！）
→ GET {domain}/v1/mediator/token → access_token
```

- client_id 各域不同：settings 域 = `settings`，Grammarly 域 = `accountV2`
- 已登录 IdP cookie 使 authorize 免交互（307 带 code），**不需要浏览器自动化**
- token 10 分钟过期，脚本内嵌刷新链

### 2. aud 是网关访问权的唯一标准

- settings token：aud = [id.superhuman.com, gateway.superhuman.com] → 打 superhuman 网关
- Grammarly token：aud = [treatment/auth/gateway.grammarly.com] → 打 grammarly 网关
- 之前 gateway.grammarly.com 全 401 = 用错了域的 token，不是目标不可达
- 两域 token 的 sub 一致（3119518190）→ 共享身份系统 → 后端可能共享数据库（nomos 双域部署）

### 3. 前端环境配置 = 攻击面地图

主 bundle 里的 JSON.parse 配置模块直接给全服务面：

```
api: { auth, tokens, nomos, subscription, passport, vito,
       institution(含 admin/members/invite-link), payments, sso, gateway }
```

还暴露 staging（ppgr.io）/ QA（qagr.io）完整环境链。

### 4. 错误语义三分法（避免误判攻击面）

| 响应 | 语义 | 行动 |
|---|---|---|
| Fastify `FST_ERR_VALIDATION` + anyOf const | 枚举值全量泄露 | 收集作合法参数（specialOffers 105 个） |
| Spring 404 + `path:/public/x` | 内部路由命名空间 | 试正确外部路径 |
| 空 body 404 | 业务语义（无组织） | 换不依赖对象的端点验证路由 |
| 403 `Access denied` | 归属校验生效 | 此对象不可越权，换获取对象的路径 |
| 400 + `arg0.planId` 字段路径 | Jakarta 校验反推参数 | 构造合法 body |

## 已关闭线（避免重复投入）

1. **specialOffers 优惠注入**：105 个合法枚举值全拿到（pro_free_trial、trial_extension_on_cancel_v2 等），注入 plans 定价无变化（30 美元恒定）——服务端不信任查询参数优惠
2. **vito/subscribe 免费订阅**：要求 Braintree nonce（支付令牌），无伪造手段
3. **x-authorization-userId 伪造**：OpenAPI 定义它是 apiKey security，但实测 JWT sub 才是身份源（16 位 organizationId → 403 Access denied 归属校验）
4. **organizationId 枚举**：16 位字母数字空间，且归属校验生效
5. **trial/extend 无限试用**：400 校验需要 planId>0 + specialOffer 非空（合法值可构造，但免费账号无试用可延）

## 教训

- **401 ≠ 不可达**：先确认用哪个域的 token（aud），再判断认证失败还是路由失败
- **403 vs 400 vs 404 必须区分**：403=归属校验（漏洞线关闭，换获取对象路径）；400=参数构造（继续）；404 空=业务语义（换端点验证）
- **校验错误是文档**：Fastify 枚举、Jakarta 字段路径、Spring path 字段都在泄露服务端结构，全部收集
- **优惠/折扣面低价值**：服务端不信任查询参数优惠，除非优惠来自服务端签发（如机构 specialOffer）
- **支付 nonce 是硬墙**：Braintree nonce 不可伪造，支付类端点直接关闭，不浪费时间
- **进入组织的路径才是钥匙**：organizationId 是所有组织级端点（SCIM/成员/升级）的前置，获取途径 = 邀请链接激活 / 机构创建完整参数链，而不是枚举
