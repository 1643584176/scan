# 经验学习17：非传统漏洞挖掘方法论——验证承诺/怀疑一切/成功非终点/一个点即成功（2026-08-25）

## 一、背景

Vercel Sandbox 漏洞赏金挑战（$1M，窗口 2026-08-18 至 09-01）发布前，项目方已用 AI 补了多轮漏洞。传统漏洞挖掘（训练数据驱动的模式匹配：已知漏洞类型枚举、CVE 匹配、经典绕过、fuzz 字典）与补洞 AI 共享同一"漏洞语料库"——**模式匹配找模式匹配补过的系统，必然空手**。本方法论是用户确立的替代框架：抛弃传统方法，从第一性原理出发。

## 二、方法论之一：验证承诺（Promise Verification）

**漏洞的本质不是"某种模式"，而是"系统对自己的承诺与实际行为之间的偏差"。**

- 传统问题："我见过什么漏洞类型？"（训练数据，与补洞 AI 同源）
- 新问题："**系统承诺了什么？什么输入能让它违背承诺？**"（第一性原理）

**承诺的来源是系统自己的声明**——规则文档原文、API 行为、观察到的防御设计。补洞 AI 补的是"漏洞模式"，无法补"承诺与行为的偏差"，因为偏差不是模式，是系统自相矛盾的点。

操作步骤：
1. 从系统声明提取承诺清单（隔离、生效、级联、一致、完备——特别注意描述"限制"的句子，每个字都是线索）
2. 对每个承诺构造最小反例："若承诺 X 成立，输入 Y 就不该有结果 Z"
3. 定向拆穿实验（不是扫描）

## 三、方法论之二：怀疑一切（Zero Trust Everything）

对系统暴露的所有可交互实体保持零信任：所有 API 端点、guest 内监听端口、unix socket、vsock 通道、host 侧可达服务、默认镜像内二进制、任何观察到的接口与服务器。禁止"这是官方的/内部的/看起来安全的所以不测"的预设。

深层推论（漏洞是图结构不是离散点）：
1. **所有地方都有漏洞，且不止一种**——补过的地方还有别的洞，找到一个不意味着穷尽
2. **每个漏洞不止一种绕过方式**——防御只堵一条路，其他路还在。实例：seccomp 拦 `socket(AF_VSOCK)` 和 `io_uring_enter`，但 `io_uring_setup` 放行、`pidfd_getfd` 可用、/dev/mem 设备区可映射——堵点旁边的路都开着
3. **每个发现可反推其他漏洞**——拦截点、已知清单、行为差异都是推理节点：例："拦 AF_VSOCK" → "host 有 vsock 服务" → "协议有解析面" → "解析可能有 bug" → "解析 bug 连着 host 侧其他服务"

## 四、方法论之三：成功非终点（Success ≠ Done）

- 即便某条攻击路径成功访问进入目标，也不代表真正的成功——只是那条路恰好能进去；不代表其他路进不去，其他路径可能通向不同或更深的成果
- 成功与失败都不构成停止理由：一路通 → 继续找其他路；一路死 → 更不代表其他路死（J288 撞墙只证明那些路被堵，UDP 面/vsock 劫持/fd 复用等其他路未验证）

## 五、方法论之四：一个点即成功（One Point Is Success）

目标不是全面覆盖攻击面，而是把任意一个具体漏洞点打透、验证、提交。成功标准 = 至少一个真实可利用的漏洞点（哪怕 Low），而非系统级逃逸。结合"深度单点优先"策略：火力集中在一个点，挖穿它。

## 七、执行要求

1. 每个新实验先问：这是"模式匹配"还是"验证承诺"？前者禁止
2. 实验结果无论成败都是推理节点：拦截点=藏宝图，成功=一条路，失败=一个堵点
3. 禁止"按类别收官"——撞墙只证明那些路被堵，不证明面死亡
4. 每个承诺优先零风险反例（纯读/纯 API 交互），再考虑高成本实验
