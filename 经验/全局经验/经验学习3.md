# 案例：GiveWP 导入导出链中的文件读写风险

> 定位：历史案例复盘。版本、CVE 对应关系和受影响范围在引用或报告前需回查厂商公告/CVE 记录，不从案例笔记直接外推到当前版本。

GiveWP <=2.20.2 双漏洞标准化总结（适配 AI 学习，分 LFI、RCE、通用规律）
基础信息
插件：WordPress 捐赠插件 GiveWP（10 万 + 站点安装）
权限门槛：仅需 GiveWP Manager 角色登录，普通订阅者无权限
两个漏洞对应 CVE：
CVE-2022-31475：认证本地文件读取 LFI
CVE-2022-28700：认证任意文件写入→远程代码执行 RCE
修复版本：≥2.21.0，修复核心是文件名强过滤
一、漏洞 1：CVE-2022-31475 路径穿越 LFI（任意文件读取）
1. 漏洞根源
批量导出功能give_process_batch_export_form直接接收用户可控file_name参数，未做路径净化；
Give_Batch_Export构造文件路径时直接拼接输入：
php
运行
$this->file = trailingslash(上传目录) . $this->filename;
无basename()/sanitize_file_name()过滤，../../可跳出上传目录，传入file_get_contents()读取任意本地文件。
2. 利用前置条件
拥有 Manager 账号；
先正常导出一次捐赠 CSV，从 AJAX 响应拿到合法give-batch-export Nonce（接口强制校验 Nonce，无则 403 拦截）。
3. 完整利用流程
后台导出页面点「Generate CSV」，抓admin-ajax.php响应提取nonce；
构造 GET 请求，file_name传入../../../../etc/passwd等穿越载荷；
接口实例化导出类，调用get_file()读取目标文件并直接输出到页面；
可读取wp-config.php数据库密钥、系统敏感文件。
4. 修复方案
对文件名执行文件名专用净化并仅保留基础文件名；同时使用服务端生成的文件名会更稳妥。以下仅表达思路，不能替代目录边界校验：
php
运行
$filename = sanitize_file_name(basename($_REQUEST['file_name']));
二、漏洞 2：CVE-2022-28700 路径穿越文件写入→RCE（高危）
1. 两层核心缺陷（缺一不可）
缺陷 A：文件名路径穿越
AJAX 导出接口give_do_ajax_export接收file_name，仅用sanitize_text_field过滤，该函数不能拦截../../，可指定服务器任意路径写入文件。
缺陷 B：导入 CSV 可控恶意 PHP 代码
前端手动捐赠数据会被give_clean转义过滤，但CSV 导入功能完全无过滤，可在捐赠姓名字段写入<?php system($_GET['c']); ?>等 WebShell。
缺陷 C：导出接口追加写入文件
stash_step_data()函数会把 CSV 捐赠数据（含恶意 PHP）追加到用户指定路径文件；写入.php后访问即可执行代码。
2. 完整利用链路
Manager 后台上传恶意 CSV 导入，将 WebShell 写入捐赠数据；
正常导出 CSV，抓 AJAX 导出请求；
修改 POST 参数file_name为../../wp-content/uploads/shell.php（网站可访问目录）；
接口执行导出逻辑，把带 PHP 后门的数据写入 shell.php；
浏览器访问/wp-content/uploads/shell.php?c=id完成远程命令执行。
3. 修复方案
同 LFI 修复逻辑，统一用basename+sanitize_file_name剥离所有目录跳转字符，禁止跳出导出 CSV 目录。
三、两个漏洞通用底层代码风险点
批量导出功能接收可控文件名，文件读写函数file_get_contents/file_put_contents直接拼接原始输入路径；
混淆过滤函数能力：sanitize_text_field只过滤 HTML，无法防御路径穿越../../；
导出 / 导入数据过滤不一致：手动输入严格转义，批量 CSV 导入完全无净化；
仅做 Nonce 防 CSRF，未对文件路径做目录锁定，未限制文件后缀。
四、通用挖掘检测清单（AI 可复用）
WordPress 插件文件类漏洞检测
检索代码file_get_contents/file_put_contents上游参数是否来自前端可控$_REQUEST；
检查文件路径拼接是否使用用户原始输入，缺少basename/ 目录白名单；
区分过滤函数：sanitize_file_name才是文件专用过滤，sanitize_text_field不能防路径穿越；
批量导入 CSV/Excel 功能重点排查：批量数据常缺少转义，易注入 PHP/JS 载荷；
导出功能同时存在读、写文件逻辑时，大概率串联 LFI+RCE 复合漏洞。
五、防御通用标准（开发修复模板）
文件路径强制净化：所有前端传入文件名必须执行basename(sanitize_file_name($name))；
锁定工作目录：读取已有文件时规范化完整路径并校验其位于允许目录内；写入新文件时不能只依赖 `realpath()`（目标尚不存在时会失败），应先规范化并校验父目录，使用服务端生成的文件名和安全创建语义，并在创建后复核最终路径；
区分数据录入过滤：手动表单、批量导入使用同一套转义净化逻辑；
限制文件后缀：导出仅允许.csv，禁止.php/.phtml可执行后缀写入；
最小权限：导出目录设置不可执行，Web 服务器禁止解析目录内 PHP 文件。
六、一句话极简总结
GiveWP 导出功能前端可控文件名未做路径过滤，Manager 权限可通过../../路径穿越实现任意文件读取（LFI）；结合 CSV 导入无过滤可注入 PHP 后门，再通过同一导出接口写入网站可访问目录，实现远程代码执行 RCE，修复核心是使用basename+sanitize_file_name剥离所有目录跳转字符。
