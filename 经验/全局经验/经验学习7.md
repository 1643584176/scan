# 现代 Web 与 API 安全边界补充

> 定位：缺口专题。用于补齐多租户、身份联邦、异步系统、缓存与文件处理等常见边界；所有验证均遵循经验学习6的授权和停止条件。

## 一、多租户与间接对象访问

直接替换资源 ID 只是起点。对象也可能经搜索、自动补全、统计、导出、通知、审计日志、附件、分享链接、批量接口和后台任务被间接访问。

思考清单：

- 租户上下文来自可信会话，还是可由 Header、子域名或请求字段覆盖？
- 子资源是否只验证父对象存在，却未验证父对象属于当前租户？
- 批量接口是否逐项授权，还是只检查第一项或容器对象？
- 删除、归档、转移后的对象是否仍能通过旧链接、搜索索引、导出或 CDN 获取？
- 错误差异是否泄漏跨租户对象存在性？

证据标准：用两个自有租户/账号证明对象级边界，不触碰第三方数据。

## 二、OAuth / OIDC、账号绑定与恢复

重点不是“Token 看起来像什么”，而是身份在多个系统间如何绑定。

思考清单：

- `state`、PKCE、redirect URI、issuer、audience、nonce 是否被正确生成并校验？
- 登录回调是否把“已在身份提供方认证”错误等同于“应绑定当前本地账号”？
- 邮箱大小写、别名、未验证邮箱或身份提供方切换会不会造成账号错误合并？
- 邀请、换邮箱、找回密码、MFA 恢复、组织转移是否要求近期认证并使旧凭据失效？
- 登出、改密、撤销授权后，旧会话、刷新令牌和设备会话是否按预期失效？

验证只使用自有身份和回调地址；不得诱导或接管他人账号。

## 三、Webhook 与服务间信任

Webhook 是外部事件进入内部状态机的信任边界。

思考清单：

- 是否验证签名、时间戳、事件来源和目标环境？签名是否覆盖原始请求体而非重新序列化后的内容？
- 是否有重放窗口、事件 ID 去重和幂等处理？
- 事件顺序颠倒、重复或延迟到达时，状态机是否仍安全？
- 测试与生产密钥、租户和回调端点是否隔离？
- 下游是否只信任事件内的金额、角色或对象归属，而不回查权威数据源？

使用测试环境或自建事件验证，不伪造真实支付、物流等第三方事件。

## 四、共享缓存、CDN 与数据隔离

缓存会把原本单请求的数据边界扩展到其他用户。

思考清单：

- Cache Key 是否包含身份、租户、语言和所有影响响应的参数？
- 带认证响应是否被错误标记为 public，或忽略 `Vary` 与 Cookie？
- 缓存是否存储错误页、重定向、敏感导出或一次性链接？
- URL 规范化在 CDN 与源站是否一致，可能把两个不同语义映射为同一缓存键？
- 权限变更或对象删除后，缓存是否及时失效？

验证时只缓存和读取自有无敏感标记数据，避免污染公共缓存。

## 五、文件上传与处理流水线

上传安全不止后缀检查。数据通常经过接收、对象存储、转码、解压、解析、预览和 CDN 分发。

思考清单：

- 服务端是否同时校验声明类型、实际内容、文件大小和允许格式？
- 文件名、压缩包路径、元数据和解析器输出是否跨越目录或命令边界？
- 上传目录是否不可执行，下载是否使用安全的 Content-Type 与 Content-Disposition？
- 图像、文档、媒体转码器是否隔离、限时、限内存并保持更新？
- 私有文件的对象存储权限、签名 URL 有效期、缓存策略和删除传播是否一致？

避免上传会执行代码、消耗大量资源或攻击解析器的样本；优先用无害标记验证边界。

## 六、异步任务、队列与导出

创建任务时通过授权，不代表任务执行时仍然安全。

思考清单：

- 队列消息是否包含可由客户端覆盖的租户、角色、路径或目标 URL？
- Worker 执行时是否重新校验权限和对象状态，还是永久信任入队时快照？
- 任务结果、日志和下载链接是否绑定创建者/租户并设置短有效期？
- 重试是否导致重复扣款、重复发信、重复导出或状态回滚？
- 用户被移出组织或对象被删除后，排队中的任务是否仍执行并暴露数据？

## 七、输入处理的系统性覆盖

同一业务字段可能从 JSON、表单、GraphQL、CSV、Webhook 和消息队列进入。不要只验证一个入口：建立“字段 × 入口 × 解析器 × 下游”的数据流表，确认规范化、校验、授权和编码在每条路径一致。

重点区分：

- **规范化**：把等价表示转换成统一形式。
- **校验**：确认值符合业务允许集合。
- **授权**：确认当前主体可对目标对象执行动作。
- **输出编码**：按 HTML、URL、SQL、Shell 等具体上下文处理。

这些控制不可互相替代；“做过过滤”不是完整安全结论。

## 一句话总结

现代系统的高价值缺陷常出现在身份绑定、租户传播、缓存键、异步消息和文件处理链之间；沿完整数据流检查每次信任转换，比只盯单个 HTTP 参数更有效。
