## 一、判别面校准(三步定生死)

任何注入测试的**第 0 步**。判别面没激活,后面全是白打。

```
第1步:非空 —— 用合法值拿到非空结果集(200 且 len 明显 > 空集)
第2步:差分 —— 换合法值,结果必须变化(如 query='team'→1422B;query='design'→62B 空)
第3步:稳定 —— 同参数连打 2 次,逐字节一致(P3)
三步全过 = 判别面激活 → 开打矩阵
```

**案例对照**:
- ❌ 反面:H1 某接口 where 恒 0 行时打了 10+ payload——全 0 无信息(0 差异 ≠ 无漏洞,是没判别力)。
- ✅ 正面:Figma folder_search 空集时所有 payload"62 空"看起来一样;拿到真实 team_id 后 62/1416/1422 三态分明,矩阵才有意义。

## 二、快照与差分实验法

### 2.1 快照稳定性检查
```
1. 同参数连打 2 次 → 逐字节比较
2. 若稳定:进入 2.2
3. 若不稳:定位首个差异字符 → 归入动态字段表(见 2.3)
```

### 2.2 逐字节 diff 纪律
- 比较以**首个差异字符位置**为准,不要只看长度(len)。
- len 差 ±1~4 字节:优先怀疑浮点/时间字段。
- 内容区差异:才进入信号分析。

### 2.3 动态字段登记表(每个目标建一份)
| 字段 | 类型 | 变化规律 | 归一化方法 |
|---|---|---|---|
| `score` | 浮点 | 每次 +-0.000005 | diff 前 replace 为 `0` |
| `updated_at` | 时间戳 | 每次请求? | replace 为固定值 |
| `realtime_token`(列表项/角色项各一份) | 签字 token 串:`/file-<key>:<ts>:0:<hmac>` / `/folder-<id>:<ts>:0:<hmac>` | 每请求必变(ts 递增+HMAC) | replace 为固定值 |
| 列表行序 | - | 数据变动时漂移 | 固定在快照窗口内比 |

> 实战教训(r85→r87→r98):把时间漂移误读成"payload 差分群",花三轮才证伪。**先登记动态字段,再下结论**。

### 2.4 快照窗口
多收集(dump)全文,离线 diff。线上比较会受"两次请求间隙数据变动"干扰;dump 到文件后 diff 是唯一可靠方式。

## 三、对照设计(证据的骨架)

| 对照组 | 作用 | 例子 |
|---|---|---|
| 恒真 | 注入逻辑生效时应出数据 | `AND '1'='1` |
| 恒假 | 与恒真必须不同才算信号 | `AND '1'='2` |
| 空集 | 证明"不存在"的样子 | query=乱词→62B |
| 同构允许集 | 在"能出数据的地方"打同样 payload | H1:dim_hacker_reports(自己 7 行) vs dim_reports(RLS 0 行) |

**铁律**:任何"异常"必须能回答"同条件下正常应该长什么样"。答不出=重新设计对照。

## 四、层间差异探测法(编码地图)

同一字符的多种送达形态,分别投递并记录**响应/存储形态**,得到一张"各层解码与清洗位置"的地图:

```
' 的形态 ──► 打 ──► 观察
%27        URL层解码后到达应用 → 与字面 ' 等价?
%2527      是否二次解码(值变 ')?
\u0027     JSON 文本转义:文本扫描器看不到 ',JSON 解析后是 '
%C0%A7     overlong:解码器接受吗?
%u2019     IIS 风格:%u 解码器存在吗?
U+2019     归一化:存储后变 ASCII 引号吗?
```

**用途**:每一种"文本层看不到、下游能看到"的形态,都是穿过滤/清洗层的候选通道(B2-B6 的本质)。

## 五、零破坏流程(Figma 验证的完整版)

```
① 基线 dump
   - 用第二读通道(WS/列表API/导出)拉全量现状,存文件
   - 记录:资源 id 列表 + 关键字段(如 position)

② 测试写入(全部在临时资源上)
   - 临时资源命名:前缀-标签-短uuid(可 grep、可批量)
   - 真实数据只读不写

③ 清理
   - 按前缀清点临时资源 → 逐个 DELETE → 记录成功数

④ 读回验收
   - 再拉一次全量 → 与基线逐一对比
   - 判据:数量一致、关键字段一致、零测试残留

⑤ 差一点就恢复
   - 有基线快照在手,任何偏差可恢复(如 position 原值 '$' 写回)
```

**Figma 实操规模**:3 轮测试共写入 17+13+2 个临时 item;清理 15+17 个;最终验收 ListItemsView 恰好 6 个、position `!#$%&"` 逐一相同。

## 七、值→标识符升格判别(val-up 三态法)★

**问题**:值位输入(路径 id/fileKey、query id)在后端有没有可能被**升格**为标识符/表达式(如 `WHERE file_key = fv.file_key` 恒真、`folder_id = 634606972+1` 参与运算)?——三态实验:

```
① 基线:     真值 → 判别面激活(200/非空)
② 自引用:   输入=同名字段表达式(`fv.file_key` / `folderId` / `file_key`) → 升格恒真时结果集异常(炸开/异样)
③ 残缺语法: 真值+尾点/尾引号(`634606972.` / `key'`) → 裸拼接时 SQL 语法错(500);正常路径静默(403/404/忽略)
数值位增补: 算术对 `<id>-0` vs `<id>+1` — 全同基线=to_i 前缀截断;-0 同/+1 异(另一 id 响应)=表达式参与
```

**判据**:
- 三态全静默且与"格式合法但不存在值"同构 → 升格无信号(残余机制=参数化 or 权限门先行,均不含升格);
- 自引用引发结果集变化 = 升格实锤(升级为注入候选);
- 残缺引发 500 = 裸拼接;
- **校准针纪律(前置必打)**:先打"格式合法但不存在值"(随机同构 key/相邻 id)——与既有 403/404 全同构 = 该位是**反枚举默认分支**,判别力=0,只能写"无信号+机制归属",不得写"参数化安全"(03·七)。

**实证(2026-09-11 Figma r197)**:`versions/{fk}` 自引用/残缺/尾引号/随机 key 全 403 同构 → 升格排除;folders path 算术四发全同基线 → to_i 截断;`folder_search` org_id/team_id 字符串 → 整数反序列化 400(解析层排除)。
