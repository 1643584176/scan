# 05 · 实战案例(证据链示范)

> 每个案例按"目标 → 判别面 → 矩阵结果 → 防御判定 → 零破坏"结构记录。
> 用途:展示"一个位置从 0 到收口"的完整证据链;新模式出现时追加。

## 案例 1:Figma folder_search(防御=解析层+清洗,无注入)★核心案例

**位置**:`GET /api/resource_connection_invite/folder_search?query=...&team_id=...`

**判别面校准(踩坑→激活)**:
- 初期打空集(query=随机词→62B 空):所有 payload "全一样",无判别力。
- 从 user_state 挖到真实 `team_id=1666382706663462213` → `query='team'` 命中 1422B → **62/1416/1422 三态激活**。
- 教训:空集上打矩阵 = 白打;先找"能命中的合法值"再开打。

**矩阵结果**:
- 值位全打(V1/V2):引号/注释/布尔对/OR/数字/null/大小写/空格/UNION/LIKE → **全部"存活命中"**(清洗后=base,仅 score 浮点噪声)。
- A1 数组语法(`query[]=team`)→ **400 "Error in route typechecking ... Error parsing JSON @1:10: Expected string"** = 解析层直接拒。
- A2 HPP:取**最后一个**(`query=team&query=design`→62 空,证取尾)。
- B2 双重编码:仅一层解码(`%2527` 不变引号)。
- B3/B4/B5:overlong/花式引号/反斜杠 → 全"存活命中"。
- 时间盲注统计:3×base(544/768/788ms) vs 3×sleep(497/498/547ms)**全重叠**。
- 路径位/枚举位/分页位:team_id 三态(200/403/404);sort 白名单(仅 relevancy);org_id 强类型(int64 溢出→400)。

**防御判定**:三层——① route typechecking JSON 解析层(参数语法级);② 应用层清洗(剥离非字母数字);③ 权限模型(三态分明)。**无注入行为**。

**零破坏**:全程只读(除 URL id 矩阵用畸形 id,天然打不中)。

## 案例 2:Figma CMS items(写面深水区,防御=解析层+bind)

**位置**:`POST /api/collections/{J}/items`(createItem)、`/items/import`、`PUT .../items/{id}/fields/{fid}`

**技术链路**:
- 值位:引号/注释/布尔/sleep → 全 200 无差分(早期"bind 或转义"二分)。
- **B7 null 三形态**:createItem 回显 `SQLSTATE 22021 "invalid byte sequence for encoding UTF8: 0x00"`(**值到达 PG 的物理证据**);import → 应用层 400 "string contains null byte";JSON `null` → 解析层 "Required field 'value' is missing"。
- **B6 JSON 转义层间(本题高光)**:**手工拼 JSON 文本**发 `\u0027`(文本里看不到引号,解析后是 `'`)→ 200 且 **WS 读回存储=`a'b`**(解码正常、无清洗);对照 `\\u0027` → 存字面 `\u0027`。**证伪"文本层清洗"假说**。
- **C1 类型混淆**:value=数字/布尔/数组/对象 → 三端点全 400 "Expected string"(解析层前置)。
- **字符族补全**:换行/制表/反引号/双引号/分号/`--`/`/*`/全角 → **13/13 WS 读回原样存储**(含 `x' OR '1'='1--` 四引号原样)——“bind 或完全等价转义”闭环。
- **400 不落库验证**:类型混淆 400 后读回,原值不变。

**防御判定**:解析层(route typechecking)+ bind/等价转义;无拼接迹象。

**零破坏完整演练**:15+2 个临时 item 用 `r107-/r108-` 前缀管理,全 DELETE;**验收 ListItemsView 恰好 6 个,position `!#$%&"` 逐一相同,零残留**。

## 案例 4:H1 analytics DSL(参数化架构,另一极)

- 输入面 25 参数字段 + 输出面 8 字段全穷尽;**全值类型 bind**(string/number/boolean/timestamp/in 元素/variables/函数参数 七路交叉证实,物理证据=`can't quote Array`)。
- 枚举硬校验(29 表/556 列/函数×列配对/别名正则);RLS 全覆盖(过滤器/join/聚合/分页/distinct)。
- 唯一"无校验进 SQL"= `join.as`——但 `"` 字符触发**引号敏感层**零容忍崩(26 样本)→ 不可利用。
- 方法论贡献:判别力校准雏形(允许表 7 行 vs 空表 0 行同构对照)、or 语义穷尽、order_by 输出列名匹配机制。

**对照价值**:同一矩阵技术在两个极端目标(H1=DSL 参数化 / Figma=解析层+bind)下都跑到收口——证明矩阵的完备性与普适性。

## 案例 5:Figma folders/paginated_files(新面首战:映射+白名单+枚举回退)★

**位置**:`GET /api/folders/{folderId}/paginated_files`(sort_column / sort_order / file_type / page_size)

**测绘链**:JS 逆向拿参数形态(`sort_column`/`sort_order`/`file_type`)与合法值映射;`GET /api/teams/{team}/folders` 拿真实 folder id(9 位数字,非 uuid);基线 `name/asc`=13534B 含真数据、连打两发字节一致。

**矩阵结果**:
- 判别面:name asc/desc **顺序反转**=排序参数真参与查询(激活)。
- **I1 列名位**:白名单恰={`name`,`touched_at`,`created_at`}(20+ 候选全 400 “Invalid sort_column parameter”;JS 里的驼峰 `createdAt`/`touchedAt` 反而被拒)。`sort_order` 严格 {asc,desc}(大写全拒)。
- **枚举位(V4/I3)**:`file_type` 非白名单——识别值(`design`→8.7k、`slides`→1.6k)生效过滤;非法值(junk/引号/UNION/CASE/overlong/U+2019/反斜杠)全部 **静默回退全量** 200,不报错不崩。
- 值位全打:引号/注释/布尔/OR/堆叠/UNION/LIKE/大小写→全无差分;时间盲注无延迟(658ms vs 549ms)。
- **C2(新,原R12)**:`file_type[]=design`→**400 “editor_type must be a string, received Array”**(内部名泄露);`editor_type` 直发被忽略(双发对照证映射单向)。
- **C3(新,原R13)**:`' touched_at'`(首空格)过白名单=**trim 归一化**;`name\x00` 过白名单、`des\x00ign`→design 命中=**\x00 完全剥离(非截断)**;`DESIGN`/`Design` 拒=大小写严格。
- HPP 取尾(3 证);双重编码单层;`page_size=abc`→400 “must be a valid number, received type String”;负数/0→静默空页;20 位大数→200 宽容。

**防御判定**:外部名映射→解析层类型校验→trim/\x00 剥离归一化→白名单/枚举识别。无注入信号。

**零破坏**:全程只读(GET),无写入无清理。

**沉淀**:新增 `C2 参数名映射探测`、`C3 归一化剥离探测`;判读库新增“防御处置四模式”与“归一化行为(预处理证据)”。

## 案例 6:Figma admin_requests(全格收口:双解析路径 + opaque cursor)★

**位置**:`GET /api/plans/{planId}/admin_requests`(list/counts/dashboard_view 3 端点,16 参数)

**测绘链**:JS 逆向(`figma_app-main.js` @2719500)拿三组真值——request_types 小写枚举(大写常量名=无效值域)、counts 参数经 `toQueryParameters` 转 **snake_case** 发送、`[]` 后缀由 `addRepeated` 拼成;服务端指纹=Rails(强参数错误)。

**矩阵结果**:
- **双解析路径**:裸名 `request_types` 走 route typecheck(JSON 数组文本,`Expected: '['`);`[]` 名走数组收集(强参数 `expected Array (got String)`/`got Rack::QueryParser::Params`)。
- **V6 精确白名单**:非法元素(尾空格/NUL/引号附加)→ 整单 400 原值回显;合法+非法混合 → 全拒(全量校验)。
- **V2 `\d+` 正则**:billing_group_ids 前导零 01/20 位溢出→空集;+1/1.0/-1/尾空格/全角全拒。
- **枚举精确匹配**:request_permission_level 仅 {guest,member}(owner/admin/Guest/尾空格全拒,无 trim)。
- **A5 序列化名陷阱**:camelCase `requestPermissionLevel` 静默 200(**参数名未被读取**);snake_case `request_permission_level=admin` → 400 校验错误(双发对照定案)。
- **cursor(opaque)**:非 b64/b64(null)→200 rescue 忽略;b64(任意 JSON 非 null)→500 浅层崩(server-timing 与 200 同量级);80 层 500 / 120 层 200 → **max_nesting=100 rescue 边界定案**;28+ 单字段/组合/命名变体零差分 → 外部不可构造。
- query_string 全静默 + pg_sleep 零时延(0.6-0.68s)→ 参数化终判。

**防御判定**:route typecheck + Rails 强参数 + 精确白名单(元素级不归一化)+ 参数化;cursor=服务端 opaque token。无 SQLi 证据,16 参数全格打满。

**零破坏**:全程只读(GET)。

**沉淀**:`A5 框架序列化名转换`/`D3 opaque token 探针`(06)、`框架强参数指纹`/`耗时头判据`/`精确匹配行`(03)、`V2 数字正则族`/`V6 全量校验`(01);结论文档 `figma_report/Figma-H1-admin_requests-r196-结论-2026-09-10.md`。

## 案例 7:Figma related_links / recent_activity / activity_logs-export(计划门+静默宽容+校验顺序)★

**位置(三面)**:
- `POST /api/files/related_links`(批量 file_keys[]) + 单文件四端点(POST/PUT/DELETE + `/link_preview`)
- `POST /api/files/{fk}/recent_activity`(activity_type)
- `POST /api/activity_logs/export`(org_id/start_time/end_time)

**测绘链**:533 路径覆盖对账(HIT 83/MISS 450)→ JS 提取 8 个未测面 → 选 related_links;逆向拿端点全形态(file_keys 数组/`lg_optimistic_mutation_uuid`/`link_preview_json`=any schema);activity_type 枚举 7 真值从 JS 解出(`postRecentActivity` 调用点)。

**矩阵结果**:
- **related_links 批量**:21 发(own/foreign/混合/空数组/无参/裸串/尾引号/pg_sleep 盲注/嵌套数组/重复元素;含 7 发 RST 重打)——合法与注入**全 200 `meta:[]` 零差分零时延**(pg_sleep 元素 364ms);空数组/无参 400 `Missing required parameter file_keys`。
- **related_links 单文件**:自有文件 POST 创建也 403 `error.no_permission`(GET 无参同样)→ **计划门**(排除权限/形态解释)。
- **recent_activity**:foreign+非法枚举=400 `Unsupported activity_type`(**参数校验先于权限**);foreign+合法枚举=200(无权限门);接受子集 ⊇ {design_file_seen, dev_mode_file_seen},file_edit 拒。
- **export**:11 发全 403 `error.no_permission_contact_org_admin`(含空 body 与 pg_sleep payload)→ **权限先于参数解析**。

**物理证据**:无(注入层不可达或静默);副产品=**双 403 模板**可探测门类型(i18n id 字段);**RST 瞬态**规律(会话首 1-5 发 10054,重打通)。

**防御判定**:批量=集合语义静默宽容(判别面未激活,不写"参数化安全");单文件=计划门 403;recent_activity=枚举白名单(V4)+参数先行校验序;export=org admin 门。

**零破坏**:全只读/无害探测;写面被 403 挡无实写;RST 重打确认。

**沉淀**:03 双模板细分/校验顺序指纹/RST 噪声行;01 V6 静默宽容;总账+源码汇总两文档(`figma_report/Figma-SQL注入总账-2026-09-10.md`、`Figma-SQL请求解析源码汇总-2026-09-10.md`)。

## 案例模式提炼(新案例追加时保留此结构)

```
### 案例 N:目标+位置
- 判别面:如何激活(合法值/对照/三态)
- 矩阵:哪些组有异常、哪些全绿
- 物理证据:拿到过什么(错误回显/读回/错误消息)
- 防御判定:层结构及机制
- 零破坏:测试量/清理/验收结果
- 沉淀:本案新增到矩阵/判读库的条目
```
