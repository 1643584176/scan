# 06 · 送达与过障(把 payload 送进 SQL 入参的通道技术)

> 分工:`01` 管"进 SQL 什么位置、怎么构造语法";本文件管"**payload 怎么穿过解析层/网关/框架的拦截,送达 SQL 入参**"。
> 用法:按 01 定位槽位并构造 payload 后,用本文件的形态逐个送达。
> **送达失败 ≠ 入参不存在**——换个通道再送一遍。
> (本文件由原"R 组 + 编码形态"重构而来,源:R12→C2、R13→C3,其余 A/B 族。)

---

## A 结构语法族(参数本身的形态)

**A1 数组/哈希语法**★
```
file_type[]=design        file_type[0]=design        file_type[key]=design
```
- 用途:①逼内部名(错误消息泄露接收端字段名);②绕过只检查标量的校验层。
- 判据:被拒 = `"xxx must be a string, received Array"`(类型断言存在,且泄露内部名);生效 = 结构层解析(该字段支持数组,注意元素级注入)。
- 实证:folders `file_type[]=design` → 400 `"editor_type must be a string, received Array"`(内部名泄露)。

**A2 HPP(参数污染)**——同名参数多值:`?a=1&a=2`
- 判据:取尾(多数框架)/ 取首 / 合并成数组(可再用 A1 视角)。
- 实证:folder_search、folders 均**取尾**(尾值生效)。

**A3 结构残废**——截断 JSON、缺键、空串值、多余括号。
- 判据:400 = 解析层严格;静默走默认值 = 宽容(**默认值也可能进 SQL,记录**)。
- 实证:folders `page_size=-1` 静默接受(记录:负数宽容)。

**A4 Content-Type 切换**——同一逻辑接口改用 JSON / form / multipart 送。
- 判据:行为差异 = 解析路径分叉(不同中间件 = 防御不一致的机会)。
- 坑:先确认服务端真的接受该类型,有些直接 415。

**A5 框架序列化名转换(逻辑名 vs 真实送达名)**★
- 背景:框架序列化函数(如 Figma `toQueryParameters`)会把 camelCase 逻辑名转 snake_case 发送;打在外部"逻辑名"上 = 服务端不认识 = **静默忽略**。
- 打法:①JS 逆向"序列化函数"拿真实发送名(源码级证据);②双发对照(`queryString=` vs `query_string=`)——用**能引发校验错误的恶意值**判定哪个名被识别(静默 200 = 未被读取)。
- 判据:**静默 200 的第一嫌疑 = 参数名没被识别**(而非"参数化安全")——先排除参数名问题,再谈安全结论。
- 实证:Figma counts——`requestPermissionLevel=OWNER`(camel)静默 200 vs `request_permission_level=admin`(snake)400 校验错误:前者根本未被读取。

## B 编码族(字节形态,同一语义的多种送达)

**B1 URL 单编码**:`'`=`%27`、空格=`%20`、`#`=`%23` …(基线形态)
**B2 双重编码**:`%2527`→解码一次仍 `%27`;`%252527`、混合 `%2527%25OR%251`;测试是否有两层解码不均等。
**B3 overlong UTF-8**:`%C0%A7`(2 字节 overlong `'`)、`%E0%80%A7`(3 字节)、`%C1%9C`(`\` 的 overlong)、孤立高位 `%80`——上层字符级过滤看不见 `'`;接受=解码器宽容(可穿),报编码错=拒绝(记录)。
**B4 全角/Unicode 变体**:`U+FF07`(全角`'`)、`U+2019`/`U+201D`/`U+02BC`(花式引号)、全角空格——看清洗是字符集粒度还是码点粒度。
**B5 反斜杠**:`\'`、`\\'`、`%5c%27`、尾部单 `\`——**先判数据库**:MySQL(NO_BACKSLASH_ESCAPES 关)下 `\'` 可能把引号"吃掉"=危险;PG(standard_conforming_strings=on)下 `\'` 就是两个字符=无特殊语义(此环境价值转为"存储原样"验证)。
**B6 JSON 转义(层间扫描绕过)**:`\u0027` / 双重 `\\u0027`——**必须手工拼 JSON 文本**(`json.dumps` 不会生成 `\u0027`):`{"value":"x\u0027 OR \u00271\u0027=\u00271--"}`;文本扫描器看不到引号,JSON 解析后是真引号。对照 `\\u0027`(解析后是字面 `\u0027`):两者行为/存储**不同**=存在"解析前文本扫描"清洗层(且可被绕过);相同=清洗在解析后或不存在。抓包确认文本里是**反斜杠+u0027**。
**B7 null 四形态分层(最强探针之一)**:同一位置四种送达——①URL `%00`;②JSON `\u0000`;③`json=` 直发(自动转义);④多字节 `\x00\x00`/前后包裹。**看哪一层先拦**(分层结果本身就是防御架构地图):
  - 边界层(CDN/nginx)拒 → 400 **HTML** 页(非 JSON);
  - 应用层拒 → 400 JSON "string contains null byte" 类消息;
  - 到达 PG → **SQLSTATE 22021** / "invalid byte sequence for encoding UTF8: 0x00"(值直达数据库的物理证据);
  - 500 未捕获崩 = 应用对 null 无防御(记录)。
  值内语义:①中间插入 `des\x00ign` 剥离后变 `design`=**完全剥离**;②截断于 null=截断型(区分法:中间插入)。
**B8 关键字变形(绕黑名单)**:大小写 `sElEcT`;空白替代 `/**/`/`+`/`%09`/`%0a`;运算符替代 `||`→OR、`&&`→AND;关键字多空格拆分。
  - 判据:变形后行为变化=存在**关键字黑名单**式过滤(可绕);始终无变化=非黑名单防御。**别硬凑**——黑名单被绕过应有真行为信号(布尔对/时间)。
**B9 边缘字符与长度**:控制字符 `\x0b`/`\x0c`、emoji、`0x7F`;超长(200/5000 字符);同一 payload 放**开头/中间/结尾**三位置。
  - 判据:超长处错误/截断长度不同=缓冲截断语义;位置不同结果不同=拼接位置敏感;注意区分 WAF(CDN HTML 页)与应用层(JSON 错误)的拦截来源。
- 总判据:哪种形态"清洗后存活"= 反推清洗规则表;哪种直接穿透 = 网关不拦。
- 实证:`des\x00ign`→design(剥离);`U+2019` 被拒;全角引号被 400。

## C 类型/混淆族

**C1 类型混淆**:`abc`(String)塞数字位、`009` 前导零、`true`(String)塞布尔位。
- 判据:`must be a valid number, received type String` 类消息 = 解析层类型校验;**先定解析层,再谈注入**。
- 实证:folders `page_size=abc` → 400 类型消息;数组元素塞嵌套结构(`request_types[][evil]=1` / `request_types[][]=x`)→ route typecheck 层 400(元素必须标量,嵌套在解析级即拒)。

**C2 参数名映射探测(外部名↔内部名)**★
- 打法:①数组/类型混淆逼错误消息提取**内部字段名**;②内部名**直发**;③双发对照(`file_type=design&editor_type=junk` 看谁生效)。
- 判据:直发被忽略 = **映射单向**(安全:内部名不可从外部到达);直发生效 = 可绕通道(危险:可直接操作内部字段绕过外部校验)。
- 实证:folders `editor_type` 直发被忽略、`file_type` 控制 `editor_type` → 映射单向。
- 价值:拿到映射链 = 知道"外部校验"和"内部真字段"的差;若外部校验弱于内部字段的合法性要求 → 缝隙候选。

**C3 归一化剥离探测(预处理行为)**★
- 打法:`' value'`(前空白)/ `'value '`(后空白)/ `va\x00lue`(中间插入)/ `VALUE`(大小写)。
- 判据:trim 后识别 = **预处理归一化**(哪些字符被归一化→清洗规则表);中间 null 剥离 = 完全剥离语义;严格大小写敏感 = 白名单枚举(大小写不敏感则枚举面更宽)。
- 实证:`' touched_at'`(前空格)→ 被白名单识别(trim 证据);`touched_at` 生效而 `touchedAt`(JS 驼峰)被拒。

## D 组合策略(送达矩阵)

**D0 回显探针(层间地图)**:能读回/回显的接口,把同一字符的多种形态(B1-B9)各打一遍,读回看**存的是哪种形态**——得到各层解码/清洗位置的地图。本身不是注入,是为 B 族选路的侦察。

**D1 时间盲注送达(崩因判别/终极否决权)**★:把目标值构造成**尾接合法运算符的条件表达式**再嵌 `pg_sleep`——形态:`<原值> AND 1=(SELECT 1 FROM pg_sleep(3))`,时间型位用 `TS' AND 1=(SELECT 1 FROM pg_sleep(3))--`(尾 `--` 保证拼接假设下引号闭合、语法合法)。LIKE 包裹型值位可用双兼容形态:`x' AND 1=(SELECT 1 FROM pg_sleep(2)) AND 'x' LIKE 'x`(等值/ LIKE 两种拼接假设下均语法闭合)。
- **读法**:慢(≥3s)= 表达式被 SQL 执行(值以语句身份进 SQL);快(<1s)= 未执行(解析/校验层已拦或参数化)。
- **用途**:①给每个"500"定性(解析崩 vs SQL 崩);②对已"排除"位做终审复核。
- **纪律**:每处 2-3 发;快慢对照;>2500ms 记慢;无延迟的 500 不得归因 SQL。
- **实证**:Figma org_id(500/368ms)、user_ids(200/354ms)、versions before(500/412ms)全快:解析层拦截终判;admin_requests query_string 三端点(dv/counts/list)全快 0.6-0.68s:参数化/未生效终判。

**D3 opaque token 结构化探针(服务端生成型游标/token)**★
- 场景:`cursor`/`token` 类参数,怀疑是 base64+JSON 编码的服务端生成物(客户端纯透传,无解码逻辑)。
- 打法(分层递进):
  ① **解码形态四发**判别:`abc`(乱值) / `{}` 未编码原文 / b64(`null`) / b64(`{}`)——分辨"解码宽容 / rescue 忽略 / nil 特判 / 处理链"四条分支(200/200/200/500)。
  ② **深度边界**:嵌套 5/10/20/50/80/120 层——**101+ 层被忽略 = JSON.parse max_nesting(默认100) 的 NestingError 在 rescue 内**——证明"解析异常→当无效忽略"分支存在,且限深前全部进处理链。
  ③ **结构快筛**:28+ 常见字段名单发 / 组合 / 元组数组 / `__` 前缀 / 命名风格变体——全 500 无差分 = 结构含未知早检查(版本/签名),**不可外部构造**。
- 判据:解析成功且非 null 的一切输入 → 500(通用文案)时,**用 server-timing(如 `app;dur=`)/ 总耗时与 200/400 同量级(<400ms)佐证崩点浅(未到 DB 查询)**——浅层崩=早检查拒绝,非 SQL。
- 收口措辞:"opaque token,外部结构化构造 N 发零差异化,注入路径不可达";副产品(任意合法 JSON 触发未处理异常 500)= 低危记录,不单独成报告。
- **实证**:Figma admin_requests cursor——54+ 样本零差分;80 层 500 / 120 层 200:max_nesting=100 边界定案。

**D2 超界对照法(latent OR 条件显影)**★:怀疑 SQL 是 `(A) OR (B)` 复合条件时,正常输入让 A 恒真、B 被短路,永远测不到 B。打法:把 A 输入推到**超界**(游标时间>真值+1µs、数字>上限等)让 A 恒假,再只变 B(B=下限±1/0/缺省)。
- 判据:超界下 B=基准-1 或 0 → 行救回 ⇒ 存在 OR,且可辨含界方向(B=基准→空 ⇒ 严格;→救回 ⇒ 含等);
- 价值:①反编译复合条件结构/运算符/条件数;②直接产出"旁路"构造(实证:`before=未来+sb=0` ⇒ 时间过滤全旁路、全量返回);
- 实证:Figma versions r152/r153——`(created > $1) OR (id > $2)` 由此定案;after 侧 `(created < $1) OR (id < $2)` 对称验证。

同一个 payload 至少试 **8 种送达形态**(B1-B9 + A1/A2 里挑),每种可能穿过不同拦截层。

**opaque 类参数专属法则**:任何"服务端生成、客户端透传"的 token/cursor/signature 参数,先做 D3 分层判别再决定投入——**判别结论"结构不可外部构造"即为有效收口**(不算漏测:已验证了"外部不可达")。

**送达失败 ≠ 入参不存在**。收口时,负结果必须注明:打了几种形态、分别被哪层拦(消息证据)。
