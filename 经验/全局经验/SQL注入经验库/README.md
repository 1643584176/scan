# SQL 注入经验库 · 总纲

> 核心视角:**SQL 入参**——每个能进 SQL 的输入,以什么身份进(字符串值?标识符?排序位?模式?),
> 用什么构造让它逃逸出"数据"变成"语法"。URL/编码/HPP 只是把 payload **送达**的通道(见 06),不是主线。
> 建立:2026-09-10(Figma 战役后)。重构:2026-09-10(对齐 SQL 入参视角)。

---

## 一、这是什么

一个以 **SQL 入参分类**为轴的**作战清单**:
- **槽位表**(01):SQL 语法里有哪 12 类"输入能进的位置",每一类的合法性断言、逃逸构造、payload 全文、判据。
- **入参清单**(01 第三节):每个项目填一张"参数→内部名→槽位→证据"的表;填完 + 每格按槽位打 = 全用。
- 打完产生的新槽位/新构造 → **追加进 01**(槽位内编号顺延),并在 `CHANGELOG.md` 记录。

## 二、强制流程(SQL 入参版)

```
1. 列候选:找出所有"值会进 SQL"的输入(方法见 04:JS 逆向/端点建模/参数名挖掘)
2. 定槽位:对每个候选入参,用"定位四问"(01 第三节)确定它进 SQL 的哪个槽位:
   - 类型断言错→报什么?(类型层证据)
   - 加空白/大小写/中间 null→行为?(归一化证据)
   - 非法枚举值如何处置?(白名单拒绝?静默回退?清洗?)
   - 能逼出内部名吗?(数组/类型混淆逼错误消息)
3. 构造打:按 01 该槽位的 payload 库逐条打;通道层配合 06(编码/结构/参数名技术)
4. 判读:用 03 的证据体系(崩/空集/存活命中 + 物理证据)
5. 对账:输出"入参 × 槽位 × payload → 结果"表;缺一格不许收口
6. 回流:新槽位/新构造/新判据 → 追加 01/03/06,写 CHANGELOG
```

## 三、铁律(吃过的亏)

1. **空集无判别力**:先证明"入参真影响结果集"再打(判别面校准,见 02)。
2. **差分前剥离动态字段**:score/时间戳噪声 ≠ 信号(见 02)。
3. **"打了"不等于"判对了"**:没有对照组的差异不算证据。
4. **槽位是推断出来的**:每个"我猜它进了 ORDER BY"都要有证据(错误消息/字典 miss/排序变化);无证据=待定,不算打对。
5. **零破坏**:写测试只在临时资源上;基线 dump→打→清理→读回验收。
6. **送达多样性**:同一个 payload 至少试 8 种送达形态(URL 编码/双重/JSON 转义/null/全角/反斜杠…)——见 06。
7. **物理证据 > 行为猜测**:quote 错误/SQLSTATE/存储回读,能拿就拿。

## 五、编号规则

- 槽位:`V`=值位(Value)、`I`=标识符位(Identifier)、`F`=函数位(Function)、`M`=多语句(Multi)、`X`=二级注入(eXecution)。
- 送达通道(06):`A`=结构语法 / `B`=编码族 / `C`=类型混淆 / `D`=组合策略。
- 追加新条目:组内最大号 +1;**永不重排、永不删号**(失效条目划掉并注明原因)。
