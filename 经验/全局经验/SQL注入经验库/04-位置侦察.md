# 04 · 位置侦察(找注入点)

> 目的:系统化找出"值会进 SQL 的位置",并摸清每处端点的形态。注入选点质量 > payload 数量。

---

## 一、注入位置盘点清单(逐类过)

| 类别 | 例子 | 重点 |
|---|---|---|
| URL query 参数 | `?query=x&sort=y&limit=10` | **搜索/过滤参数是首选**(值直达查询) |
| URL 路径段 | `/api/collections/{id}/items/{id2}` | 值位(路径 id);畸形 id 零破坏 |
| Body JSON 字段 | `{value:"x"}`、`{fields:[...]}` | 值位+结构位(C1/A3) |
| 排序/分页/枚举位 | `sort=relevancy&direction=desc` | 白名单回显(I3/I4) |
| 头部 | `X-Figma-User-ID`、`Referer`、自定义头 | 常被忽略;部分后端拼进查询 |
| WS/实时通道 | livegraph mutation/subscribe | 与 HTTP 后端同源时=同一注入面(注意找 mutation 帧) |
| 导入/批量接口 | `/items/import` | 数组结构内字段(嵌套值位) |

---

## 二、参数名与端点收集(三个来源)

1. **JS bundle**(最全):
   - `grep -o '"/api/[a-z_/]*"'` 抓路径;`grep 'url\`'` 抓模板字符串;
   - 找 API client 类方法:`deleteItem|createItem|updateItem|import` 附近 2KB 是同类端点全集。
2. **前端行为抓包**(用户导出 HAR 最准——本项目约定:人工导出提供)。
3. **响应/错误消息**:白名单回显("Invalid value for X")、必填消息("Required field 'x'")直接泄露字段名。

---

## 三、JS 逆向三招(实操模式)

```python
# 招1:模板字符串端点全集(一次 grep 拿到所有 URL 形态)
re.finditer(r'url`([^`]{0,120})`', js_text)
# 招2:方法定义窗口(deleteItem 案例——同一窗口有 create/update/import 姊妹方法)
i = js_text.find('deleteItem'); print(js_text[i-2500:i+800])
# 招3:feature gate / 开关(揭示隐藏功能面)
re.finditer(r'feature[Gg]ate[^,]{0,60}|fmr_\w+', js_text)
```

**案例**:Figma `_js/4740-*.min.js` 一处窗口同时挖出 `deleteItem`(`n.del(n.url\`/api/collections/${e}/items/${t}\`)`)与 `createItem` 调用链(`optimisticallyCreate`),直接确定了两个端点的 URL 形态。

---

## 四、端点形态建模(CRUD 五件套)

对每个资源域,把五个端点都找出来,逐一过矩阵:

| 端点 | 典型形态 | 重点技术 |
|---|---|---|
| List/Search | `GET /api/xxx?q=` | V 组值位全打(判别面校准后) |
| Create | `POST /api/xxx` body 字段 | B6/B7/C1(JSON 层) |
| Update | `PUT/PATCH /api/xxx/{id}` | 路径 id + 值位 |
| Delete | `DELETE /api/xxx/{id}` | 路径 id;顺便=清理工具(零破坏流程) |
| Import/Batch | `POST /api/xxx/import` | C1/A3(数组内字段) |

---

## 五、通道盘点(别漏入口)

- 同一后端常暴露多通道:HTTP REST / GraphQL / **WS 实时**。
- "乐观更新"(optimistic mutation)的 endpoint 大多**仍是 HTTP**(Figma 验证:createItem 走 HTTP POST)。
- WS 的 **mutation 帧**若独立于 HTTP 存在,单独过矩阵(本题暂未发现独立数据面 mutation)。

---

## 六、宽容解析探测(找未文档化参数)

1. 往 body 加**未知字段**(如 `x:"1"`),看是否报错/被忽略/被处理。
2. 被"静默接受"的字段 → 值得用 C1/A3 深挖(可能是隐藏参数)。
3. 反面注意:宽容解析 + 坏值可能崩(见 03 判读库:null 全字段敏感案例)。

---

## 七、选点优先级(时间有限时)

```
1. 搜索/过滤参数(值直达查询,回报率最高)
2. 排序键/表名/列名位(拼接高发)
3. 路径 id 位(便宜,零破坏,兜底)
4. 导入/批量接口(结构复杂,易漏)
5. 头部/隐蔽参数(随缘)
```
