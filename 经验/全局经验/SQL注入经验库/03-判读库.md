# 03 · 判读库(响应语义与防御层识别)

> 目的:把"响应"翻译成"防御架构信息"。判读统一走本表,避免过度解读或无谓重复。

---

## 一、错误消息指纹表(按拦截层归档)

| 层 | 消息格式特征 | 实例 | 含义 |
|---|---|---|---|
| 边界层(CDN/WAF) | **HTML** 错误页(非 JSON)| `<!DOCTYPE HTML ... <TITLE>ERROR` / 400 | 请求在到达应用前被拦(常为 null/畸形 URL) |
| 路由解析层 | `Error in route typechecking for /api/xxx: Error parsing JSON @L:C: Expected string` | Figma `query[]=` / 非 string value | **声明式参数校验**(JSON 解析级)先于业务——最强防御信号 |
| 框架强参数层 | `Invalid query parameters: expected Array (got String) for param 'x'`(
`got Rack::QueryParser::Params` = 下标形态) | Figma `request_types` 裸名混发 | Rails ActionController 强参数(expect/permit);**数组参数有两种解析路径**:裸名=JSON typecheck / `[]`名=数组收集 |
| schema 校验层 | `'x' must be a valid number, received type String` / `Required field 'x' is missing` | Figma org_id/前导零 | 类型/必填校验(比解析层晚,比业务早) |
| 参数映射层 | 类型消息暴露**内部名**(消息里的名字≠请求里的名字) | Figma `file_type[]=`→"editor_type must be a string, received Array" | 外部名→内部名映射存在;数组语法是逼出内部名的工具(C2) |
| 白名单校验层 | `Invalid <param> parameter` | Figma `Invalid sort_column parameter` | 值级白名单;枚举外全拒(与"静默回退"模式相对) |
| 游标校验层 | `Invalid column type in cursor object` / `Endpoint requires secondary_column cursor to be set` | Figma versions(column/secondary_column) | keyset 分页游标对象的列名/组合校验;SQL 前拦截(死位) |
| 应用业务层 | 标准 JSON:`{"error":true,"status":404,...}` / 403 "You don't seem to have permission" | 404/403 业务语义 | 已到业务代码,权限/资源查找语义 |
| 权限门(双模板细分) | 403 消息 A:"You don't seem to have permission to do that."(`error.no_permission`)/ B:"...Contact your organization administrator."(`error.no_permission_contact_org_admin`) | Figma related_links 单文件(功能/计划门=A) vs activity_logs/export(组织管理员/审计门=B) | **两种门语义不同**;模板差异=门类型差异(i18n id 字段最可靠) |
| 数据库层 | `SQLSTATE 22021` / `CharacterNotInRepertoire` / `invalid byte sequence` / `Integer overflow` | PG 错误回显 | **值到达数据库的物理证据** |
| 语言运行时 | `NoMethodError: undefined method 'x'` / `can't quote Array` / `TypeError` | Ruby 翻译器崩溃 | 对象方法链/quote 环节的物理证据 |

**用法**:测试中每个新错误消息 → 当场归层 → 更新指纹表。层定位决定"这个信号值不值得追"。

## 二、状态码 × 场景语义矩阵

| 码 | 可能语义 | 判别方法 |
|---|---|---|
| 200 | 正常 / 静默忽略(写盲接口)/ "存活命中" / **参数名未被识别** | 对比 base len/内容;写接口看读回;**先排除 A5(序列化名/形态未识别)**:同语义恶意值双发(camel↔snake、`[]`↔裸名),静默 200 过半数是打在了未被读取的名字上 |
| 400 | 解析层拒 / schema 拒 / 业务参数拒 | **看消息文本**(@L:C 解析格式 vs 类型消息 vs 业务消息) |
| 403 | 存在但无权 / 防枚举统一应答 | 与 404 对照:同位置"存在+无权"vs"不存在"是否可区分 |
| 404 | 资源不存在 / 端点不存在 / 路由不匹配 | 用已知合法资源打对照;消息格式(JSON vs HTML) |
| 500 | 未捕获异常:null/类型/权限/重复键 | 隔离变量(每次只改一个字段)找根因;**并做时间维反证(见五·补)** |
| 200 空集 | 参数被清洗后无匹配 / 参数被忽略 | 与"命中"值对照;变换参数是否影响结果 |

**403 反枚举默认分支(重要)**:资源不存在时可能**不走 404 而走 403**(防枚举设计)——实例:Figma file_followers(未知 key→403 `You don't have permission to view this prototype`)、comments(→403 `comments feature`)、versions(未知 fileKey→403 `permission to view this file`)。**判别**:用"已证合法资源"与其字符变体(引号/大小写/裁剪/加尾字符)各打一发——**行为完全一致→反枚举默认分支(不是注入信号)**;行为分叉→真权限边界。

**403 双模板细分(重要)**:同一项目可并存两种 403 消息模板——A `You don't seem to have permission to do that.`(i18n `error.no_permission`;功能/计划/资源门)vs B `You don't have permission to do that. Contact your organization administrator.`(i18n `error.no_permission_contact_org_admin`;组织管理员/审计门)。**模板差异=门类型差异**,i18n id 字段最可靠。用途:①快速定性"这面被什么门挡"(功能计划门 vs 组织管理员门);②计划门可换账号解锁,管理员门记录即可。实例:Figma related_links 单文件(自有文件也 A=计划门);activity_logs/export(空 body 也 B=**权限先于参数解析**)。

## 二·补 校验顺序指纹(参数校验 vs 权限校验,逐端点实测)

同一项目内不同端点的校验顺序不同,决定"在无权资源上能否做参数层探测":

| 顺序 | 表现 | 实例 |
|---|---|---|
| 参数值校验先于权限 | 无权资源+非法参数→400(参数消息);无权资源+合法参数→200/进权限 | Figma recent_activity(foreign+非法枚举=400 `Unsupported activity_type`;foreign+合法枚举=200) |
| 权限先于参数解析 | 空 body/任意参数→403(权限消息),参数层完全不可达 | Figma activity_logs/export(空 body 也 403 组织管理员门) |

**判法**:取"无权资源"各发两发——①带非法参数值 ②空 body——比消息类型即可定序(参数消息先现=参数先行;权限消息先现=权限先行)。
**用法**:①参数校验先行→可在无权资源上无害探枚举/参数行为(信息量极低但可写画像);②权限先行→参数层完全不可达,换账号前别投入。

## 三、结果三分法(每个 payload 必须归类)

```
① 崩(5xx / SQL 错误 / 运行时异常)
   → 进入本节指纹表归层;找根因(哪个字符/字段引发的)
② 空集(与空集基准一致)
   → payload 语义 = "一个找不到的词";对判别面贡献为零
③ 存活命中(与 base 相同,即"清洗后=原值语义")
   → 清洗层存在(剥掉了 payload 的语法部分);记录清洗范围:
     例:"引号/注释/分号/括号全剥,字母数字保留" → 说明白名单式清洗
```

**关键认知**:"存活命中"不是"注入失败",是**清洗层行为画像**。多个 payload 的画像拼起来 = 清洗规则反推。

## 三·补 防御处置四模式(同一层的不同取舍)

| 模式 | 表现 | 实例 | 含义 |
|---|---|---|---|
| 白名单拒绝 | 枚举外值→400 明确消息 | `sort_column=junk`→`Invalid sort_column parameter` | 校验前置、零宽容;白名单集合可用二分枚举 |
| 静默回退 | 枚举外值→200 走默认 | `file_type=junk`→200 全量 | 宽容取舍;**值在识别失败即弃,未进查询** |
| 清洗存活 | payload→200 与 base 相同 | folder_search 引号族 | 剥离式清洗;需跟踪存活字符集 |
| 类型拒绝 | 类型/语法错→400 类型消息 | `page_size=abc`→`must be a valid number`;`file_type[]=`→`received Array` | 解析层类型系统;数组语法可逼出**内部字段名** |

**判读原则**:同一参数上先定模式,再选打法——白名单模式做二分枚举(确定集合);静默回退模式试"能否让识别失败变成识别成功"(编码/剥离/截断变体);清洗模式做存活字符集测绘。

## 四、读回验证语义

| 存储形态 | 判定 | 安全性 |
|---|---|---|
| 输入原样(`x' OR '1'='1--` 原样) | bind 或完全等价转义 | ✅ 安全(两者等价,不必强分) |
| `''` 双写(`x'' OR ''1''...`) | 应用层做了 SQL 转义后拼串 | ✅ 安全(转义正确);记录"存在转义层" |
| 被剥离(`x OR 11`) | 清洗层拼接前剥离 | ⚠️ 危险候选:若剥离+拼串组合错误可注入;继续布尔对测试 |
| 被截断 | 长度限制 | 记录;结合溢出测试 |

**原则**:读回只能证明"存储态";注入可能性的最终裁决永远是**行为测试**(布尔对/时间)与**物理证据**(quote 错误)。

## 五、物理证据清单(值得主动追求的)

| 证据 | 制造方法 | 证明了什么 |
|---|---|---|
| `can't quote Array` 类错误 | A1 数组语法喂进值位 | 该值经过 quote 环节 |
| `SQLSTATE 22021`(null 字节) | B7 的 `\u0000` 到达 PG | 值**到达数据库**(参数或文本,不区分) |
| `table 'x' not defined in schema` | I1/I2 标识符位喂畸形 | 标识符进了**字典查询**(拼接嫌疑层) |
| 白名单回显 `Invalid value for X: yyy` | I3 枚举位 | 合法值列表泄露 + 校验存在 |
| 正则消息 `alias should match [A-Za-z]...` | I2 别名位 | 白名单正则防御存在 |
| `Integer overflow` | V2 数字边界 | 类型/范围校验层存在 |

## 五·补 500 归因:时间维判别(必做步骤)★

**规则**:任何"500/SQL 疑似"必须在时间维度反证——把 `pg_sleep(3)` 嵌进**语法完全合法的表达式**再送(如 `1 AND 1=(SELECT 1 FROM pg_sleep(3))`,尾接 `--` 确保拼接假设下语法闭合):
- 慢(≥3s)= SQL 真的执行 → 注入实锤;
- 快(<1s)= 崩在解析/校验层(整数溢出、日期解析、null 字节、类型断言),**不是 SQL**。

**原因**:500 有太多平凡来源;只有时间侧信道能区分"解析崩"与"SQL 崩"。**没有时间维证据的 500 不得写入注入结论**。
**实证**:Figma org_id `1 AND 1=(SELECT 1 FROM pg_sleep(3))`→500/368ms(parse 层崩);user_ids 同 payload→200/354ms(parseInt 截断,无执行);versions before→500/412ms(游标解析崩)。三处全部以"快"否决拼接。
**纪律**:每个位 2-3 发;基线对照取同会话近邻请求;>2500ms 记慢。

**第二判据·耗时头同量级(浅层崩佐证)**:服务端返回 timing 头(如 `server-timing: app;dur=`、`X-Runtime`)时,对照"通用 500"与同会话 200/400 的耗时——**同量级(<400ms 级)= 崩点在早检查/解析层,未到 DB 查询**;若 500 显著慢于基线 = 崩点更深,值得继续追。实证:Figma admin_requests cursor 全部 500 的 app;dur(124-385ms)与 200/400 应答同量级,佐证浅层崩(早检查拒绝)。

## 六、噪声清单(别当信号的东西)

| 噪声 | 表现 | 处理 |
|---|---|---|
| score/相关性浮点 | 同 payload 两次 len±1~3 | 归一化后再 diff |
| 时间戳字段 | updated_at 变化 | 固定快照比较 |
| 列表序漂移 | 数据变动时整个 body 变 | 同窗口内比;逐字节定位首差异 |
| 网络抖动 | 计时 ±300ms | 时间盲注用 3+3 组统计 |
| **连接重置(RST)** | `ConnectionResetError(10054)`——**会话首 1-5 发**偶发,后续全正常 | 网络层瞬态,非内容/权限触发;重打确认——重打即通=瞬态,持续 RST 才升级排查 |
| 编码显示差 | `\` 与 `"` 在 grep/正则输出中的转义显示 | 落盘后按原始字节核对 |

## 六·补 归一化行为(预处理证据)

| 行为 | 探法 | 实证 | 含义 |
|---|---|---|---|
| trim | `' value'` / `'value '` | `' touched_at'` 过白名单 | 匹配前 strip(预处理) |
| **精确匹配(不归一化)** | 尾空格/NUL/大小写变体 | `account_type_request ` 拒(对比 `credits_used ` 放行) | **同名家族行为不可跨端点外推,逐端点独立确认** |
| \x00 完全剥离 | **中间**插入 `des\x00ign` | →design 命中;`name\x00` 过白名单 | 剥离(非截断);值被重构后再匹配 |
| 大小写严格 | `DESIGN` / `Design` | 拒绝/回退(不识别) | 大小写敏感白名单 |
| 严格单层解码 | `%2527` 类 | 单层解码后不再解 | 防双重编码链 |

**用法**:这些行为都是"值被应用层处理过"的物理证据——与"原样拼接进 SQL"不相容;但注意**不能用它区分 bind 与清洗**(两者都先处理值)。

## 七、"未发现注入"的表述标准

允许说:
- "本位置按入参矩阵(槽位 × 通道)逐条打完,无注入行为信号"(附对账表)
- "防御形态识别为:X 层校验 + bind/等价转义"

禁止说:
- "绝对没有 SQL 注入"(黑盒无法证明绝对)
- "打满了"(除非对账表全条覆盖)

**收口措辞模板**:
> 位置 X 参数 Y:矩阵(槽位 V1-V6/I1-I4/F1/M1/X1 + 通道 A/B/C)全条已打(不适用项已注明);判别面激活(三态可辨);全部 payload 归入"存活命中/空集/解析层拒",无崩无差分无物理证据泄露;判定:无公开可利用的 SQL 注入行为,防御=N 层(具体机制)。
