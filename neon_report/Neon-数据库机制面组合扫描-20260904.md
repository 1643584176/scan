## 一、组合推理框架（方法论）

对每个 PG 原语问三个问题：
1. **谁能执行**（ACL/角色/上下文）——查 pg_proc.proacl、角色成员链
2. **以谁的身份执行**（definer/invoker/事件 dispatch）——补丁 `neon.restrict_superuser_calls='block'` 的覆盖面
3. **什么能触发它**（触发场景 = 平台在租户上下文执行的操作）——pg_stat_activity 平台连接视角

触发场景是 Neon 最深的防线：**平台监控连接全部连 postgres 库，租户库 neondb 上平台从不执行 DDL**。

## 二、本轮测试面与结论（17 项全闭合，含 1 项事实修正）

## 三、防御架构观察（为何系统性无缺口）

1. **DDL 面隔离**：所有管理 DDL（CREATE ROLE/DATABASE）在 postgres 平台库执行；租户库 neondb 平台零 DDL → 事件触发器/DDL 钩子类攻击无触发场景
2. **平台库 DDL 权锁死**：postgres 库 public schema 权限归 cloud_admin（PG15+ 默认），租户无法建函数/表/触发器 → 平台库内无法预置对象
3. **dblink 双重防御**：客户端防继承（PG 原生）+ Neon 凭据验证强化（非 superuser 一律拒，连自连不放行）
4. **文件面全禁**：pg_read_file/pg_stat_file/pg_ls_dir 函数级 DENIED + COPY 服务端文件全禁（restrict_copy）+ copy_from_allowed_dir 为 postmaster 级
5. **信号免疫**：cloud_admin 连接不可终止（superuser 保护优先于 pg_signal_backend）
6. **角色成员 filter**：neon.membership_roles_filter（databricks_superuser/neon_superuser/pg_read_all_data/...）——高危成员可被平台按连接过滤
7. **扩展面**：pg_cron/partman 不实装（仅模板 preload）；unstable/deprecated 双列表独立拦截；可装扩展约 20 个均为普通功能
8. **平台表写保护触发器体系（含 1 处不一致）**：health_check/neon_migration.migration_id 挂 `neon_*_superuser_check` BEFORE 语句级触发器（plpgsql 查 current_user rolsuper，非 superuser 一律 42501，%I 字面输出 bug 无害）→ 实测租户 DML DENIED。**例外：public.lakebase_attributes 无触发器**，租户 I/U/D 实测全成功（pg_write_all_data）→ 消费方 = `get_compute_primary_memory_bytes()`（replica 侧 autoscaling 状态迁移内存指标，sql_exporter 每 ~20s 调 `SELECT bytes FROM (SELECT get_compute_primary_memory_bytes() AS bytes) t WHERE bytes IS NOT NULL`）→ **租户→平台监控跨信任边界数据注入面**。当前缓解：GUC `neon.autoscaling_state_transfer_enabled=off` → 函数恒返 NULL 断链；表 0 行。影响=单租户 autoscaling 输入数据伪造（无跨租户）→ **Low/N-A 观察项**（修复建议：给 lakebase_attributes 补同款触发器）
9. **内部免密口双层防线**：错误消息侧面证实 127.0.0.1:5432 存在免密认证内部口（compute 监控/代理设计使然）——Neon 对它的防护是双层的：Neon 自研 dblink 补丁（连 127.0.0.1 一律要求凭据且真密码也拒）+ PG13.2+ 原生 fdw `password_required` 默认值（服务器不要求密码时非 superuser 禁止连接；`false` 选项仅 superuser 可设且 DDL 阶段拦截）→ 无平行绕过载体；非 superuser 能建的联网原语（dblink/postgres_fdw/pg_create_subscription）均无法利用内部口

## 五、结论

**本轮 17 个机制面全闭合**（面 16 含 1 项修正：lakebase_attributes 消费方实锤，但 flag off + 单租户 → Low/N-A）：Neon 对"数据库函数面"的防御是体系化的（DDL 隔离 + 平台库权限锁 + dblink 凭据强化 + fdw password_required 原生双层 + 文件/信号/复制面收紧 + 平台表写保护触发器），非单点补丁。
除已提交 #3992341（补丁盲区类）外，**当前无可提交的新数据库漏洞**。
数据库方向若继续投入，剩余理论面：console API 跨项目校验（控制面）、Beta 功能（Buckets/Functions/Auth webhooks）、已装扩展源码级审计——均超出"数据库函数面"范围。
