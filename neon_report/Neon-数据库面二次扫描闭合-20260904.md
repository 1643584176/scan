# Neon 数据库面二次扫描闭合归档(2026-09-04)

- 环境:staging ep-crimson-fog-w2gucld1(neondb_owner 直连)
- 背景:#3992341 已提交(补丁盲区链),本扫描找**独立于该报告根因**的数据库侧新面
- 结论:**全部闭合,无可提交新漏洞**(防御系统性,无免提权捷径)

## 1. 全库枚举(_e1)
- 本 compute 仅 neondb/postgres 两库;neondb=neon_auth 自服务表(单租户,无跨租户),
  postgres 平台库=neon 9 个性能统计视图(cloud_admin)+ migration_id/health_check/lakebase_attributes(已知)
- 无未披露平台表/敏感列

## 2. role_names 注入面取证(_e2,闭合)
- 残留角色 `x"; CREATE ROLE pwn LOGIN; --`(oid 16584)与 NeonDb_Owner(16585)同批创建
  = _auth3.py `POST /projects/{id}/jwks` role_names 测试产物
- **pwn 不存在** -> 分号后语句未执行 -> **参数化安全,非 SQL 注入**
- 平台(cloud_admin)以 role_names 建普通 LOGIN 无密码角色(rolcanlogin=T has_pw=F,
  外部 SCRAM 无法登录,内部仅 trust cloud_admin)-> 设计内,无利用价值
- 残留角色 neondb_owner 无 ADMIN OPTION 无法 DROP(留待平台清理,无害)

## 3. pg_stat_statements 内容(_e3,闭合)
- 高频=监控轮询 SQL;低频=health_check 心跳/neon_auth 查询/迁移 DDL
- **全部参数化($1/$2),无明文敏感值**;本测试查询亦混入(无污染意义)

## 4. 免提权文件读写捷径(_e4/_e7,闭合)
| 路径 | 结果 |
|---|---|
| file_fdw | DENIED(Must be superuser) |
| lo.lo_import / lo_export | DENIED(permission denied for function) |
| pg_read_file 基线 | DENIED(已知) |

## 5. pg_cron(_e6,闭合)
- "can only create extension in database postgres"(cron.data=postgres)
- 平台库租户无 CREATE 权限 -> 不可装 -> 调度器面不可达

## 6. 租户可装扩展白名单实测(_e5/_e6)
- **可装**:vector 0.8.6 / lakebase_text / lakebase_tokenizer / neon_utils 1.1 /
  neon_procstat / pg_partman 5.1.0 / hypopg / pg_hint_plan / timescaledb 2.24.0 /
  pg_graphql / pg_repack / dblink / lo / pg_prewarm / hll / ip4r / roaringbitmap /
  pg_tiktoken / semver / pg_uuidv7(扩展对象 owner=cloud_admin,脚本在 superuser 上下文执行)
- **DENIED**:pg_cron(库限制)/ file_fdw / pg_surgery / pg_walinspect / pgaudit /
  amcheck / pg_buffercache / pg_visibility / neon_monitor / vector 依赖缺失类 / pg_search(废弃)
- neon_utils 仅 num_cpus()(cloud_admin owner,无平台数据面)
- 注:可装扩展内 cloud_admin 属主 SECURITY DEFINER 函数载体与 #3992341 同根因
  (扩展放行+definer),再报即 duplicate,不挖

## 7. 大对象溯源(_e8,闭合)
- 8 个 cloud_admin owner 大对象 = #3992341 测试自伤残留(loid 34307 等,0-28B)
- lo_get 全部 DENIED(大对象 ACL 默认 owner-only,防护正确);非 owner 无法清理,留待平台

## 8. 测试对象残留清单(本扫描)
- 无新残留:所有扩展事务内 ROLLBACK;终验 pg_extension 仅 plpgsql/pg_session_jwt
- 平台侧既有残留(非本扫描产生,无法自清):角色 x";.../NeonDb_Owner、8 个大对象、
  PGDATA//tmp 0 字节探测文件(重启即失)——已在 #3992341 报告 Impact/备注中可提及

## 9. 结论
Neon 单租户 DB 面的平台侧防御(库隔离+扩展白名单+函数 ACL+大对象 ACL+参数化)
在当前可测范围内无缺口;新漏洞只能来自:console 控制面 API(跨项目校验)、
Beta 功能面(Buckets/Functions/Auth webhooks)、或已装扩展的源码级审计。
