## 本轮结论(全部关闭/低危)
### 1. hooks 302 重定向 SSRF 矩阵 —— 关闭(旧证据链作废!)
- 方法: 12 个 url hook 绑 deploy_created, url 指向自己 site 的 302 路径(_redirects 12 种目标: ctl/pub 公网绝对URL / meta/r10/r172/r192/v6l/v6u/hex/int/nip 私网), zip deploy 触发, 轮询 success/disabled
- **deploy_created 事件确认触发**(publish 后 ~2 分钟, 12 hooks 逐个队列处理: poll10-23 陆续变化)
- **决定性发现: 所有 302->绝对URL 的目标(公网 ctl/pub 与私网 meta/r10 等 12 个)全部 disabled=True(回调失败)**
  → hook 客户端对 302 重定向到**绝对 URL** 的回调一律判定失败, 与目标公网/私网无关
- 旧证据(meta hook 302->169.254.169.254 disabled=True)系实验设计缺陷(对照用了相对 vs 绝对混合)——作废
- 相对 URL 302(旧 ctl /hookctl/* -> /index.html)才被跟随成功; 但相对 302 只能同域, 无法到私网
- 附加: disabled=True 是临时状态(冷却后自动恢复 poll30), hook 失败会重试
- 结论: hooks SSRF 302 链不可行, 关闭

## 教训
- hook 回调的 302 跟随: 相对 Location 成功、绝对 URL 一律失败(判定为回调失败并累计禁用) —— 用 hooks 测 SSRF 必须同构对照, 否则误判
- disabled=True 是临时失败计数(冷却自动恢复), success 字段成功时不更新 —— 观测通道只有"失败"
- bitbucket-self-hosted/verify 等 UI 内部函数: 匿名可达 + 服务端出站 —— 测 SSRF 时先测时序区分"显式拦截(快)"vs"网络层黑洞(慢)"

## 轮次6: database-query 单接口攻破(9/3,用户指令:只技术/单接口打穿/禁无意义枚举)

### 实例形态确认
- host=ep-autumn-cherry-ay51mbqz.c-5.us-east-2.db.netlify.com → **Neon 白标 serverless PG**(ep- endpoint / c-5 compute / npg_ 密码 / 0.25CU autosuspend 300s / PG18.6 aarch64)
- 每 site 独立 Neon project(V1 pg_database 仅 netlifydb+postgres+template0/1,无共享实例)
- 凭证:owner+readonly 双角色连接串经 GET /sites/{id}/database 可取(跨账号 401 已隔离)

### 攻破过程(8 波假设检验,全部单条 SQL 无枚举)
1. **角色指纹**:owner 非 super,但 rolcreaterole/rolcreatedb/rolreplication/rolbypassrls 全 true —— 高权限非 super
2. **读文件/命令执行**:pg_read_file 拒 / COPY PROGRAM 拒 / lo_import 拒 —— 无 pg_read_server_files/pg_write_server_files
3. **wrapper 过滤真相**:多语句 400 "cannot insert multiple commands into a prepared statement" = psycopg 协议限制非主动过滤;**DO 块 200 通过** = 单语句限制可绕过(plpgsql 编排任意语句序列)
4. **扩展面**:dblink/postgres_fdw/lo/neon/neon_utils 显示可装但实为 **cloud_admin 预装**(V4+V2:函数 owner 全 cloud_admin);file_fdw/adminpack 400 "not available/permission denied" —— allowed_extensions 白名单≠用户可装
5. **prosecdef 审计**:全库仅 dblink_connect_u(owner=cloud_admin,prosecdef=true),但 ACL={cloud_admin=X/cloud_admin} 锁死,直调 400 permission denied
6. **neon 特性函数**:neon_check_for_superuser/neon_get_lfc_stats 等 10 个诊断函数,owner=cloud_admin 非 prosecdef,无攻击面
7. **复制面**:wal_level=replica(<logical)→ 逻辑复制死;**物理复制直连成功**(Z1: psycopg replication=database,IDENTIFY_SYSTEM 返回 7680866968875046352)——proxy 放行 replication,但 WAL 仅自己数据,无新增面
8. **出网/回连**:dblink 公网出站 could not establish connection(compute 无公网出网);localhost 回连(cloud_admin/owner)均 password or GSSAPI delegated credentials required(Neon patch 禁非 super 带凭据回连)
9. **wrapper 参数面**:body 加 role/connection_string 被忽略(恒 netlifydb_owner);siteId 畸形 400 不进 SQL(归属校验在连接获取层)

### 结论:关闭,无洞
- 所有跃迁点防护完整:无 superuser / prosecdef ACL 锁 / dblink 回连禁 / 出网断 / 独立 project 无共享实例
- 特性开放(rolreplication+物理复制、扩展预装)均为 Neon 白标设计行为
- 残留观察:neon.allowed_extensions 白名单可读(泄露内部扩展列表,低危);branches REST 端点存在(production 单分支)

## 轮次6补:PG 特性面穷尽(用户追问:变异/提取/select/事务/sleep/MySQL式旁门)

### 波9:会话/事务/时序模型(每请求独立连接确认)
- S1/S2:pg_sleep(1)=1.6s、pg_sleep(30)=30.6s 均 200 → wrapper 无短超时(≥30s)
- S3-S6:begin 单条 200;pg_advisory_lock(424242) 持锁后,下一请求 pg_try_advisory_lock=true → **非同一连接**;unlock 失败(锁在已断连接上)→ 无连接池复用
- S7-S8:set_config(application_name) 后下请求读为空 → 会话变量不残留
- S9-S10:set statement_timeout=3000 后下请求 pg_sleep(6)=6.5s 仍通过 → 无残留
- 结论:每请求独立连接/会话零残留 → 无会话污染、无锁继承、无超时异常态

### 波10:物理复制 BASE_BACKUP(数据目录全量读取,技术突破面)
- 裸 "BASE_BACKUP" 被 walsender 接受(带 LABEL/参数反而 syntax error → Neon/proxy 侧限制)
- psycopg3 高层不支持 CopyBoth 读 → 直接泵 libpq:send_query + get_result(先回 2 行 LSN)+ get_copy_data 循环
- 结果:**73KB tar 流 = compute 数据目录全量 48 文件**
- 内容:pg_hba.conf(local/127.0.0.1/replication 全 trust + 公网 md5)、neon.signal/zenith.signal(PREV LSN)、global/pg_control、PG_VERSION=18、compute_ctl_temp_override.conf(空)
- **无 postgresql.conf/server.key/表数据**(Neon 精简目录,数据在 pageserver)→ 目录内无敏感密钥
- 判定:rolreplication 用户跑 pg_basebackup 是 PG 标准行为,非漏洞;但证明 proxy 放行完整复制协议

### 波11:transaction action(官方多语句通道,此前 payload 结构未知)
- payload = {action:transaction, queries:[{sql},...]},元素必须为对象;返回逐元素结果集数组
- W1:中途错误 → 整体 400 + **全量回滚**(原子事务);W2:成功全部提交(跨请求可见)
- W3:元素内多语句仍被 prepared 拦截(协议层);W4:DO 元素通过(sleep 2s 生效)
- W5:错误中断后续元素;W6:元素间同事务可见;W7:begin/commit 元素被接受且提交生效
- 结论:transaction = 单连接单事务执行数组;给了数组级多语句但权限面不变;元素内事务控制可逃逸 wrapper 事务边界但无跨租户/无提权

### 轮次6最终判定(特性面穷尽后)
- PG 特性面全部闭合:会话(独立连接)、事务(官方通道+原子性)、时序(无超时)、复制(BASE_BACKUP 全目录只读)、扩展(预装无提权)、prosecdef(ACL 锁)、dblink(Neon patch)、文件原语(全拒)
- MySQL 式旁门映射:INTO OUTFILE/LOAD_FILE→pg_read_file/COPY 全拒;UDF→扩展装不了;general_log 写文件→无 super;@变量/PREPARE→PG 会话隔离;GET_LOCK→advisory lock 无跨连接
- 接口无洞,关闭
