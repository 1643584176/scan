### 1.1 名称边界

- `scan`：整个项目和仓库，根目录为 `D:\scan`；
- `AssetTrace`：`scan` 项目内当前由 `app.py`、`assettrace/`、`static/` 和 `templates/` 组成的扫描执行应用，当前优先面向 Qoder 或其他本地自动化代理提供 API 与结构化上下文；
- `skills/`、`programs/`、`tests/`、`docs/`：属于 `scan` 项目，但不能被 AssetTrace 子系统名称代替。

## 2. 项目定位

`scan` 是面向**已授权安全研究**的本地自动化研究工作台。

项目把以下环节组织成一个可审计、可重复、可持续改进的完整闭环：

```text
项目发现 → 政策与 Scope 整理 → 项目初始化 → 研究计划
        → 受控资产发现与检测 → 发现管理 → 经验沉淀 → 再次验证
```

系统的核心价值是：

- 帮助研究者找到适合研究的公开项目并整理官方资料；
- 把分散的政策、Scope、身份要求和禁止事项转成可执行规则；
- 在明确授权边界内自动发现 Web 资产线索并运行检测器；
- 记录本次研究测了什么、依据什么、得到什么结论；
- 把经过人工审核的通用经验沉淀下来，服务后续项目；
- 通过重复扫描验证目标当前状态，而不是依赖历史响应。

**AssetTrace 提供的政策门禁与请求执行账本是 `scan` 项目的安全执行基础设施，不是整个项目的产品定位。**

## 3. 要解决的问题

1. 漏洞赏金项目资料分散，政策、Scope、身份头和禁止事项难以统一整理。
2. 项目初始化缺少标准结构，研究过程容易依赖个人记忆和临时文件。
3. 资产发现、检测、发现归档和复测之间没有稳定的数据关系。
4. 自动化请求如果不经过统一授权判断，容易产生越界或不符合项目政策的行为。
5. 保存完整目标响应会增加敏感数据、凭据和业务数据泄露风险，但并不是证明“测过什么”的必要条件。
6. 有价值的研究经验缺少审核、版本和复用机制。
7. Skill、运行脚本与测试混放后，项目职责不清晰，也不利于验证和维护。

## 4. 产品目标与非目标

### 4.1 产品目标

- 建立从公开项目发现到复测的完整研究流程。
- 以项目为中心统一管理政策、Scope、资产、运行、请求、发现和知识。
- 在所有网络访问之前执行同一套政策门禁。
- 支持可插拔、带版本的检测器和后续执行适配器。
- 保存请求事实、项目接口目录、加密的可选扫描辅助配置、项目 JavaScript 当前文件与脱敏结论；其他响应仅在内存中使用后丢弃。
- 让每次运行可以审计、可以解释、可以重新执行，但不能恢复任意响应或 JavaScript 历史版本。
- 为 Qoder 或其他本地自动化代理提供稳定、脱敏、机器可读的项目研究上下文，支持其规划下一项授权检查。
- 所有默认界面、说明、错误提示和项目内 Skill 使用中文。
- 通过清晰的包结构和自动化测试保证后续可以持续改造。

### 4.2 当前非目标

- 不做通用网页镜像、爬虫数据仓库或响应归档系统。
- 不扫描未明确授权的目标，不根据经验自动扩大 Scope。
- 不执行破坏性验证、拒绝服务、社工、凭据攻击或政策禁止的动作。
- 不自动提交漏洞报告或代表研究者作出法律、政策判断。
- 不保存通用响应快照或 JavaScript 历史版本，也不使用已存文件替代本次网络响应。
- 当前不建设云端多租户、团队权限和远程任务集群。
- 当前阶段以被动 Web 研究为主，主动验证能力必须以后按风险单独设计。

## 5. 主要用户与使用场景

### 5.1 主要用户

- 已获得目标授权的安全研究者；
- 负责整理漏洞赏金项目政策和 Scope 的项目维护者；
- 编写检测器、Skill 和研究经验的项目开发者。

### 5.2 典型场景

1. 从 HackerOne 等公开来源筛选候选项目，保存可核验的来源信息。
2. 为候选项目生成标准目录，整理政策原文、Scope 原文和结构化配置。
3. 人工复核政策后，把配置绑定到本地研究项目。
4. 在 Scope、风险和速率限制内扫描一个明确授权的入口。
5. 从页面发现 JavaScript、Source Map 和端点线索，并对实际请求的资产执行适用检测器。
6. 通过 agent context 查看项目接口、请求账本、配置元数据、发现和 JavaScript 当前文件索引。
7. 查看请求覆盖、失败原因、检测覆盖和脱敏安全发现。
8. 对发现进行人工判断，把可复用经验提升为待审核知识。
9. 再次扫描同一项目，重新请求目标并验证发现是否仍然存在。

## 6. 整体业务流程

```mermaid
flowchart LR
    A[公开项目发现] --> B[项目资料初始化]
    B --> C[人工复核政策与 Scope]
    C --> D[创建本地项目]
    D --> E[固定政策与经验版本]
    E --> F[生成研究运行]
    F --> G[统一请求门禁]
    G --> H[内存响应与检测器]
    H --> I[脱敏发现与请求账本]
    I --> J[人工判断与知识审核]
    J --> K[再次验证]
    K --> F
```

流程约束：

- 公开项目发现和资料初始化不会自动获得扫描授权。
- 创建本地项目本身不会发送目标网络请求。
- 只有人工确认、政策有效、经验完整且运行上下文固定后才能执行。
- 经验决定“如何检查”，政策决定“允许检查什么”；经验不能扩大政策范围。
- 检测器只能使用当前请求产生的内存响应。

## 7. 核心领域模型

| 对象 | 职责 |
| --- | --- |
| `ProgramRegistration` | 表示一个本地公开项目资料源及其同步状态 |
| `Project` | 研究工作的主聚合，关联目标、政策、运行、资产和发现 |
| `PolicySnapshot` | 某个时间点经过复核的不可变政策版本 |
| `ScopeRule` | 结构化允许或禁止规则，包括方法、风险和资格信息 |
| `ExperienceReceipt` | 证明某次运行完整加载了哪些经验及其版本 |
| `ScanRun` | 一次不可变研究运行及其计划版本 |
| `RequestPermit` | 一次具体请求的授权判断和执行状态 |
| `Asset` | 实际被调度并请求过的研究对象 |
| `AssetRelation` | 页面、脚本、Source Map 或端点之间的发现关系 |
| `ApiEndpoint` | 项目内去重后的接口结构、方法、来源和发现/测试状态 |
| `ProjectScanConfigItem` | 用户录入或研究中发现、经加密保存的可选扫描辅助信息；不定义扫描计划或 Scope |
| `AnalysisJob` | 某检测器对某次内存分析输入的执行记录 |
| `Finding` | 经过脱敏、可去重、可跟踪状态的安全结论 |
| `KnowledgeEntry` | 从发现中提炼、经过人工审核后可复用的知识 |

## 8. 功能需求

### 8.1 公开项目发现

- `REQ-DISCOVERY-001`：项目发现应优先使用官方或可核验的公开来源。
- `REQ-DISCOVERY-002`：候选结果必须包含来源、查询时间、项目标识和可供人工复核的摘要。
- `REQ-DISCOVERY-003`：项目发现只生成候选资料，不得创建扫描授权或自动请求候选资产。
- `REQ-DISCOVERY-004`：来源不可访问或字段不完整时必须明确标记，不得编造 Scope 或政策。
- `REQ-DISCOVERY-005`：查询逻辑属于独立 Skill，其脚本、引用资料和测试必须放在对应包内。

### 8.2 项目资料初始化

- `REQ-INIT-001`：初始化工具必须为每个公开项目创建独立目录。
- `REQ-INIT-002`：目录至少包含结构化配置、项目说明、政策原文和 Scope 原文。
- `REQ-INIT-003`：结构化配置必须保存来源地址、获取时间、原文摘要和模式版本。
- `REQ-INIT-004`：Excluded Assets、Out of Scope 和禁止事项必须转换为禁止规则，且禁止规则优先。
- `REQ-INIT-005`：资料更新后必须能识别原文或配置变化，旧人工复核不得静默沿用。
- `REQ-INIT-006`：初始化脚本属于 `program-init` Skill，不得继续散落在仓库根目录。

### 8.3 本地项目与政策

- `REQ-PROJECT-001`：创建项目时必须记录目标和用户授权声明，但不得自动开始扫描。
- `REQ-PROJECT-002`：正式项目资料必须经过人工复核，并绑定复核时看到的精确配置摘要。
- `REQ-POLICY-001`：政策快照必须包含来源、观察时间、有效期、必需请求头、禁止动作、速率限制和 Scope 规则。
- `REQ-POLICY-002`：支持精确主机、通配子域、URL 前缀和显式 CIDR 规则。
- `REQ-POLICY-003`：精确主机不自动授权子域；禁止规则始终优先。
- `REQ-POLICY-004`：政策来源、原文、配置、状态或有效期变化后，关联政策必须失效并重新复核。
- `REQ-POLICY-005`：没有有效政策时禁止创建可执行运行。

### 8.4 经验加载与知识沉淀

- `REQ-EXP-001`：全局经验原文使用 Markdown 管理，系统只读加载，不在运行时改写。
- `REQ-EXP-002`：每次运行必须固定经验文档清单、内容摘要和完整加载凭据。
- `REQ-EXP-003`：必需经验缺失、超限或读取失败时，运行必须停止创建。
- `REQ-EXP-004`：经验只能影响检测方法，不能改变 Scope、方法、风险或速率授权。
- `REQ-KNOW-001`：发现可以提升为候选知识，但不能直接进入已批准知识库。
- `REQ-KNOW-002`：知识批准必须是明确的人工操作，并保留来源发现和审核状态。
- `REQ-KNOW-003`：导出知识只包含结构化、脱敏内容，不附带目标原始响应。

### 8.5 运行计划与调度

- `REQ-RUN-001`：每次运行必须固定项目、政策快照、经验凭据、计划版本、身份、响应保留模式以及本次显式选择的扫描辅助配置编号；未选择时固定为空列表。
- `REQ-RUN-002`：运行上下文创建后不可原地替换；政策变化需要创建新运行。
- `REQ-RUN-003`：扫描队列必须限制最大资产数和最大线索数，避免无界扩展。
- `REQ-RUN-004`：发现线索只有被实际调度并请求后才能成为“已测试资产”。
- `REQ-RUN-005`：系统必须保留实际请求资产之间的来源关系，便于解释发现路径。
- `REQ-RUN-006`：单个资产或检测器失败时，应在安全可控的前提下继续其他独立任务并汇总失败。
- `REQ-RUN-007`：运行结果必须区分请求数、处理响应数、保存 JavaScript 数、更新 JavaScript 数、丢弃其他响应数、分析任务数、失败数和发现数。

### 8.6 请求授权与执行账本

- `REQ-GATE-001`：所有 HTTP、浏览器和 API 适配器都必须在网络发送前经过统一请求网关。
- `REQ-GATE-002`：没有匹配允许规则、命中禁止规则、方法不允许、风险过高或缺少身份要求时必须阻止请求。
- `REQ-GATE-003`：每个重定向目标必须在发送下一跳前重新授权。
- `REQ-GATE-004`：私网、回环、链路本地和保留地址默认禁止，只有明确配置的受控环境可以例外。
- `REQ-LEDGER-001`：账本记录运行、目标 URL、方法、风险、政策、规则、授权决定、原因和时间。
- `REQ-LEDGER-002`：执行状态必须区分 `authorized`、`completed`、`failed`、`blocked` 和 `legacy_unknown`。
- `REQ-LEDGER-003`：`blocked` 请求不得产生目标网络流量。
- `REQ-LEDGER-004`：请求头值不得进入许可记录；错误只保存类别和脱敏摘要。
- `REQ-LEDGER-005`：请求 URL 中明确属于 Token、密码、签名或 API Key 的参数值不得原样持久化。

#### 8.6.1 项目接口目录

- `REQ-ENDPOINT-001`：每个项目必须维护独立、长期保留的接口目录；相同项目、接口结构和方法重复发现时更新当前记录，不创建扫描快照副本。
- `REQ-ENDPOINT-002`：接口记录至少包含安全 URL 结构、方法、状态、首次/最近发现运行、首次/最近尝试运行、首次/最近成功测试运行和来源关系。
- `REQ-ENDPOINT-003`：状态必须区分 `discovered`、`tested`、`blocked` 和 `failed`；只从响应中识别但没有实际请求的接口不得显示为已测试。
- `REQ-ENDPOINT-004`：接口 URL 查询参数只保留参数名，不保留任何值；数字、UUID 和明显的长不透明路径段使用占位符归一化。
- `REQ-ENDPOINT-005`：接口目录不得保存请求体、响应体、响应头、Cookie 或可重放的认证材料。
- `REQ-ENDPOINT-006`：页面链接使用 `GET`，HTML 表单使用声明的方法，无法从 JavaScript 静态文本确定方法时使用 `UNKNOWN`，不得猜测为已验证方法。
- `REQ-ENDPOINT-007`：已知接口通过统一请求网关执行后，许可记录必须关联接口并更新其最终状态；被动发现本身不得触发接口请求。

#### 8.6.2 项目扫描辅助配置

- `REQ-CONFIG-001`：项目可以保存辅助文本、Cookie、Bearer Token、API Key、Basic Auth 以及普通用户名/密码，来源可以是本人提供或研究中发现；敏感明文必须在专用边界加密后才能落盘。
- `REQ-CONFIG-002`：扫描辅助配置只是候选输入，不是扫描计划、执行命令、授权依据或 Scope；它不能要求系统必须使用，也不能扩大项目允许的目标、方法或风险。
- `REQ-CONFIG-003`：保存、更新、“允许请求选用”或确认配置都不得自动改变任何扫描。每次运行必须显式提交所选配置项编号；空列表与项目没有配置时的扫描行为一致。
- `REQ-CONFIG-004`：运行创建时必须验证所选配置均属于当前项目，并把去重后的编号固定在不可变运行上下文中；后续修改或删除配置不能改写该次运行曾选择的编号。
- `REQ-CONFIG-005`：每项配置至少记录项目、显示名称、类型、来源、URL 适用范围、是否具备请求选用资格、确认状态和非敏感来源说明；`user` 与 `discovered` 都默认不参与运行。
- `REQ-CONFIG-006`：Cookie、Token、API Key 或 Basic Auth 只有同时具备请求选用资格、得到授权使用确认、被本次运行显式选择且逐跳 URL 匹配时，才可短暂解密为请求头；此类请求至少按 `authenticated_read` 风险重新经过政策、Scope、方法、速率和重定向门禁。
- `REQ-CONFIG-007`：普通用户名/密码缺少明确登录流程时只能作为辅助上下文保存，不能自动提交；辅助文本也不得自动转成 URL、请求体或请求头。只有声明兼容类型的具体任务步骤才能按最小必要原则使用被选中的非请求配置。
- `REQ-CONFIG-008`：配置按 URL 前缀逐跳选择，不得把当前主机或路径的认证头泄漏到不匹配的重定向目标；传输适配器不能逐跳提供请求头时必须拒绝携带配置执行。
- `REQ-CONFIG-009`：列表、项目详情、运行摘要、许可账本、错误和日志只返回配置元数据或所选编号，不提供明文读取接口，不保存可离线猜测的普通密码摘要。
- `REQ-CONFIG-010`：加密主密钥必须与 SQLite 分开保存，可由环境变量或独立本地密钥文件提供；数据库与密钥必须一起备份才能恢复配置。数据库已有密文配置但密钥缺失时必须停止启动，不得生成替代密钥。
- `REQ-CONFIG-011`：目标响应中的 `Set-Cookie`、账号或查询结果不得自动进入项目配置；只有用户明确保存的最小信息才能成为候选配置，保存后仍默认不参与运行。

### 8.7 资产发现与检测器

- `REQ-ASSET-001`：当前资产类型至少支持页面、JavaScript、Source Map 和端点线索。
- `REQ-ASSET-002`：检测器必须声明名称、版本、支持的资产类型和统一分析接口。
- `REQ-ASSET-003`：页面检测器负责结构与引用面，JavaScript 检测器负责端点和敏感模式，响应头检测器负责安全配置，Source Map 检测器负责映射暴露风险。
- `REQ-ASSET-004`：检测器输出必须分为发现、线索、事实和统计，由执行层决定哪些内容允许持久化。
- `REQ-ASSET-005`：增加检测器不得绕过请求网关、隐私边界或运行上下文。
- `REQ-ASSET-006`：检测器升级后通过新运行和当前响应验证，不允许依赖历史响应重放。

#### 8.7.1 JavaScript 资产清单

- `REQ-JS-001`：每个项目必须长期保存实际发现并请求过的外部 JavaScript 资产记录。
- `REQ-JS-002`：JavaScript 资产记录至少包含所属项目、规范化 URL、资产类型、状态、首次发现时间、最近发现时间和最近测试时间。
- `REQ-JS-003`：必须保存页面到 JavaScript 的来源关系，并能追溯首次发现运行和最近发现运行。
- `REQ-JS-004`：每次对 JavaScript 的实际请求和检测任务必须能关联到具体运行、请求许可和检测器版本。
- `REQ-JS-005`：从 JavaScript 发现的端点必须写入项目接口目录，Source Map 被调度后保存为实际资产和关系，不能只存在于临时响应对象中。
- `REQ-JS-006`：成功获取的外部 JavaScript 正文必须保存到 `data/projects/<项目编号>/js/`，数据库记录相对路径、SHA-256、大小和最近运行。
- `REQ-JS-007`：同一 JavaScript 资产只保留当前文件；内容变化时原子替换，不创建历史版本或通用 Blob。
- `REQ-JS-008`：再次扫描时必须重新请求并分析 JavaScript，不得使用目录中的旧文件代替本次网络响应。
- `REQ-JS-009`：必须提供按项目列出和查看 JavaScript 当前文件的接口；查看接口按纯文本返回，禁止浏览器按脚本执行。
- `REQ-JS-010`：不得保存 JavaScript 响应头、Cookie、ETag、Last-Modified 或重定向响应正文。

### 8.8 发现管理

- `REQ-FINDING-001`：发现必须包含稳定指纹、类别、严重程度、置信度、标题、位置、修复建议和最小必要证据摘要。
- `REQ-FINDING-002`：所有发现必须在统一持久化边界脱敏和限长，不能只依赖检测器自行处理。
- `REQ-FINDING-003`：同一发现跨运行维护首次出现、最近出现和当前状态，不重复制造无意义记录。
- `REQ-FINDING-004`：不得保存检测器原始 facts、完整 discoveries 或完整响应片段。
- `REQ-FINDING-005`：发现状态变化必须可追溯到具体运行和实际请求。
- `REQ-FINDING-006`：报告或知识导出只能使用脱敏发现；项目 JavaScript 当前文件不得自动复制进报告或 Skill。

### 8.9 重复扫描

- `REQ-RESCAN-001`：重复扫描代表重新验证目标当前状态，必须创建新运行。
- `REQ-RESCAN-002`：每次都重新通过政策门禁、重新请求适用资产并重新运行检测器。
- `REQ-RESCAN-003`：不得使用 ETag、Last-Modified、`304`、历史响应或旧检测任务代替本次验证。
- `REQ-RESCAN-004`：不同运行的请求事实分别保留，发现通过稳定指纹更新状态。
- `REQ-RESCAN-005`：重复扫描的 agent context、API 和界面应清楚显示本次实际请求与检测情况，而不是“缓存命中”。

### 8.10 Agent/API 与控制台

- `REQ-AGENT-001`：必须提供项目级只读 agent context，供 Qoder 或其他本地代理一次性读取政策状态、最近运行、请求账本、接口目录、JavaScript 元数据、配置元数据、开放发现、分析任务和后续 API 路径。
- `REQ-AGENT-002`：agent context 不得创建运行、发送网络请求、读取配置明文、返回 JavaScript 正文或其他响应正文。
- `REQ-AGENT-003`：agent context 中的项目、资产、请求和接口 URL 必须使用安全结构，查询参数只保留名称和值占位符。
- `REQ-AGENT-004`：agent context 必须明确提示配置只是候选辅助上下文；任何新扫描仍需显式提交 `config_item_ids` 并经过统一请求网关。
- `REQ-API-001`：API 按项目资源组织，创建项目、导入政策和执行扫描必须是不同操作。
- `REQ-API-002`：错误响应应区分授权缺失、项目未就绪、政策导入阻止、请求失败和输入无效。
- `REQ-API-003`：健康接口必须返回应用版本、数据库模式、经验同步和项目资料同步状态。
- `REQ-UI-001`：控制台当前作为辅助只读入口，围绕项目展示政策状态、经验状态、运行、请求、已测试资产、检测覆盖、发现和知识。
- `REQ-UI-002`：涉及授权、阻止、失败、响应丢弃和旧数据兼容时必须给出明确中文说明。
- `REQ-UI-003`：界面不得展示未脱敏凭据、Cookie、异常或非 JavaScript 响应内容。
- `REQ-UI-004`：界面不得把发现但未请求的线索显示为已测试资产。
- `REQ-UI-005`：控制台可以滞后于后端能力，但已有入口必须保持安全边界，不得展示响应仓库式内容。

### 8.11 Skill 与测试包

- `REQ-SKILL-001`：每个 Skill 位于 `skills/<skill-name>/`，使用 `SKILL.md` 作为入口。
- `REQ-SKILL-002`：Skill 脚本放入 `scripts/`，资料放入 `references/`，界面元数据放入 `agents/`。
- `REQ-SKILL-003`：项目发现、项目初始化和扫描研究分别使用独立 Skill，不混合职责。
- `REQ-SKILL-004`：Skill 默认说明和示例使用中文，修改后必须通过标准校验。
- `REQ-TEST-001`：核心单元测试放入 `tests/unit/`。
- `REQ-TEST-002`：Skill 脚本测试放入 `tests/skills/`。
- `REQ-TEST-003`：临时实验脚本不得混入正式测试包，正式能力必须有可重复测试。

## 9. 数据保留设计

用户确认的数据原则是：**保存请求与测试事实、项目接口目录和加密的可选扫描辅助配置；外部 JavaScript 保存为项目当前文件；其他响应按当前分析需要临时使用，用完丢弃。辅助配置只在某次运行显式选择后才可参与该次扫描。**

| 数据类别 | 是否保留 | 保留目的与限制 |
| --- | --- | --- |
| 公开项目资料 | 是 | 保存官方来源、政策和 Scope，供人工复核 |
| 项目与政策快照 | 是 | 证明研究对象和授权依据 |
| 经验元数据与加载凭据 | 是 | 证明本次运行使用的经验版本 |
| 运行上下文 | 是 | 还原本次研究计划和执行依据 |
| 请求许可与执行状态 | 是 | 证明测过什么、为何允许以及是否完成 |
| 项目接口目录 | 是 | 每项目保存去重后的结构、方法、来源与状态；不含查询值和响应 |
| 项目扫描辅助配置 | 是 | 辅助文本、Cookie、Token、API Key 或账号密码使用独立密钥加密；默认不可回读、不可自动使用 |
| 实际请求资产与关系 | 是 | 描述本次资产覆盖和发现路径 |
| JavaScript 当前文件 | 是 | 每个项目、每个 URL 只保留当前正文，不保留历史版本 |
| 检测任务 | 是 | 保存检测器版本、状态和计数 |
| 脱敏安全发现 | 是 | 保存最小必要研究结论和修复建议 |
| 人工批准知识 | 是 | 复用经过审核的通用方法或模式 |
| 其他目标响应正文 | 否 | HTML、JSON、API 与 Source Map 只在内存中使用 |
| 完整响应头与响应 Cookie | 否 | `Set-Cookie` 等目标响应数据不自动进入数据库、Blob、日志或 Skill；用户明确录入的 Cookie 属于加密项目配置 |
| 通用响应快照与历史副本 | 否 | 不保存其他响应，也不保存 JavaScript 旧版本 |
| 检测器原始输出 | 否 | 不保存 facts、完整线索对象或调试转储 |

授权政策原文属于运行配置来源，不属于目标扫描响应，因此可以按版本保存并供人工复核。

## 10. 响应生命周期

1. 请求网关完成当前目标授权并创建许可记录。
2. 传输层在大小、超时、重定向和 SSRF 限制内取得响应。
3. 响应正文与检测所需响应头进入当前内存分析对象。
4. 适用检测器在当前进程内完成分析。
5. 把端点线索转成移除查询值的项目接口记录；该步骤不自动请求端点。
6. 若资产类型为外部 JavaScript 且请求成功，把正文原子写入项目 `js` 目录并更新元数据。
7. 统一隐私边界保存任务计数和脱敏发现。
8. 释放内存响应引用；非 JavaScript 正文不写文件，响应 Cookie 不自动进入项目配置。

除项目 JavaScript 当前正文这一明确例外外，以下内容不得持久化：HTML、JSON、API、Source Map 原文、完整响应头、Set-Cookie、ETag、Last-Modified，以及任何可以恢复完整响应的编码副本。

## 11. 分层与目录要求

```text
assettrace/domain/       政策、Scope、项目资料和运行领域对象
assettrace/application/  项目、政策注册和运行用例编排
assettrace/execution/    请求网关与最终授权门禁
assettrace/detectors/    可插拔、带版本的内存检测器
assettrace/javascript_artifacts.py  JavaScript 当前文件路径与原子替换
assettrace/credentials.py  项目辅助配置校验、加密、作用域与请求头转换
assettrace/privacy.py    所有持久化内容的统一脱敏边界
assettrace/storage.py    项目、运行、请求、任务、发现和知识账本
skills/                  项目发现、初始化和研究工作流
programs/                待复核的公开项目资料与政策来源
tests/unit/              核心单元测试
tests/skills/            Skill 脚本测试
static/、templates/      中文控制台，当前仅作辅助入口
docs/                    项目需求与架构文档
data/projects/<id>/js/   对应项目的 JavaScript 当前文件
data/.assettrace.key     默认项目配置主密钥；必须忽略 Git 并与数据库配套备份
```

依赖方向必须从 API、界面和应用层指向领域与执行接口，检测器不得直接控制授权政策，传输适配器不得自行决定是否允许请求。

## 12. 安全与隐私要求

- 没有有效授权、Scope、经验凭据或运行上下文时默认拒绝执行。
- Authorization、Cookie、API Key、Token、密码、JWT 和常见云访问密钥不得进入普通账本；只有项目辅助配置专用表允许保存认证密文。
- 项目配置 API 不返回密文或明文；主密钥不得进入 SQLite、Git、Skill、请求日志或错误信息。
- 请求头值不能通过错误、日志、判断原因或调试数据间接入库。
- 响应大小、扫描资产数、线索数、超时和速率必须有上限。
- 单个检测器抛出的原始异常不能直接写入数据库。
- 新增浏览器或 API 适配器时必须复用同一请求网关和响应瞬时协议。
- JavaScript 查看接口必须返回 `text/plain`，设置 `nosniff`、禁止缓存和限制性 CSP，不能把文件当作应用脚本执行。
- 项目 JavaScript 可能包含敏感常量，只能留在本地项目数据目录，不得提交 Git、写入日志或自动导出到 Skill。
- 任何超出“项目 JavaScript 当前文件”的原始响应保存功能都属于核心设计变更，不能通过普通配置开关静默启用。

## 13. 非功能需求

### 13.1 可审计性

任意运行都应能追溯到项目、政策、经验、计划、请求许可、执行状态、检测器版本和脱敏发现。系统只能读取 JavaScript 当前文件，不能恢复其他响应或 JavaScript 历史版本。

### 13.2 可重复性

相同项目可以基于新运行再次执行相同计划。重复代表重新请求和重新分析，不代表复用旧响应。

### 13.3 可靠性

- 数据库写入和模式升级必须使用事务。
- 响应处理、重定向拒绝、传输失败和检测器失败都必须结束对应执行状态。
- 一个独立任务失败不应破坏已经完成的请求账本。

### 13.4 可扩展性

- 检测器、项目来源和传输适配器必须具有明确接口与版本。
- 新能力必须复用授权、运行、隐私和存储边界，不能建立旁路。
- 性能优化不得恢复响应归档或历史响应复用。

### 13.5 可维护性

- 领域、用例、执行、检测、隐私和存储职责分离。
- 中文术语保持一致，避免同时使用快照、缓存、账本等相互冲突的表述。
- 正式功能、Skill 脚本和迁移逻辑必须有自动化测试。

## 14. 数据库迁移要求

- 当前 SQLite 模式版本为 `8`。
- 新运行固定使用 `response_retention = javascript_current`，表示只保留项目 JavaScript 当前文件。
- `javascript_artifacts` 保存项目、资产、相对路径、内容摘要、大小和最近运行，不保存响应头。
- `api_endpoints` 与 `api_endpoint_sources` 保存项目接口结构、状态和来源；查询值在写入前统一移除。
- `project_credentials` 是兼容保留的内部表名，保存扫描辅助配置元数据、Fernet 密文和带密钥 HMAC 去重指纹；不保存明文或普通密码散列。
- `run_contexts.config_item_ids_json` 固定本次运行显式选择的配置编号；默认值为 `[]`，配置存在本身不影响运行。
- `request_permits.endpoint_id` 只关联已在项目接口目录中的请求；许可 URL 同样只保存安全结构。
- 为兼容旧外键而暂留的 `asset_revisions`，新记录只保存请求身份信息，响应字段为空或中性值，并标记 `retention_mode = request_only`。
- `agent-context` 是只读聚合视图，不新增表、不保存导出副本，所有字段来自现有账本、目录和元数据。
- 旧响应记录标记为 `legacy_response`，旧请求状态标记为 `legacy_unknown`，不得伪造新执行结果。
- 升级不得自动删除旧 `data/blobs/` 或历史响应记录。
- 新扫描不得读取或写入旧 Blob。
- 旧数据清理必须是独立、显式、可预览、得到用户确认的一次性操作。

## 15. 整体验收场景

### 15.1 项目闭环

1. 能从公开来源得到候选项目，并生成标准项目资料目录。
2. 未人工复核的资料不能直接形成可执行授权。
3. 创建本地项目后不会自动发起网络请求。
4. 导入有效政策并完整加载经验后，才能创建研究运行。
5. 运行后可以查看实际请求资产、资产关系、检测覆盖和脱敏发现。
6. 发现可以人工提升为候选知识，并经过单独批准后导出。

### 15.2 授权边界

1. 未授权目标、禁止规则、超风险动作和越界重定向在发送前被阻止。
2. `blocked` 请求没有目标网络流量，并保留可解释的许可记录。
3. 成功请求进入 `completed`，传输失败进入 `failed`，错误内容经过脱敏。
4. 政策资料变化后，旧复核和旧运行不能静默继续使用。

### 15.3 响应与重复扫描

1. 全新数据库执行扫描后不创建 `blobs`，只在对应项目的 `js` 目录写入成功请求的 JavaScript。
2. JavaScript 正文只存在于当前文件，不进入 SQLite；HTML、JSON、Source Map 与 Cookie 标记不进入数据库或项目文件。
3. 同一 JavaScript URL 内容变化后覆盖原文件，目录中仍只有一个当前文件，不产生历史副本。
4. 同一目标连续扫描两次会产生两次独立网络请求、运行和许可记录。
5. 第二次扫描不发送条件缓存头，也不使用已存 JavaScript 替代本次响应或检测任务。
6. JavaScript 列表与查看接口返回正确项目文件，跨项目编号不能读取。
7. 检测器输出和异常中的 Token、Cookie、JWT 或访问密钥在数据库中只出现遮蔽内容。
8. 页面、表单和 JavaScript 发现的接口在同一项目内按结构和方法去重；重复扫描更新最近运行，不生成接口快照副本。
9. 未实际请求的接口保持 `discovered`；完成、阻止和失败请求分别更新为 `tested`、`blocked`、`failed`。
10. 接口查询值、Cookie、Token、用户名和密码不能出现在接口目录、请求许可、项目详情或日志中。
11. 本人提供和研究中发现的辅助配置均以密文保存；保存、允许请求选用或确认后都不会自动参与扫描。
12. 不选择任何配置时，即使项目已有可用 Cookie，扫描仍不携带它；运行上下文记录空选择。
13. 某次运行显式选择 Cookie 等请求配置后，只有匹配 URL 作用域的逐跳目标会收到它，请求风险提升为认证读取且继续服从政策门禁。
14. 普通用户名/密码和辅助文本不能自动变成请求；没有兼容任务步骤时，选择只作为本次运行上下文记录，不伪装成已使用。

### 15.4 Qoder 与本地代理读取

1. `GET /api/projects/{项目编号}/agent-context` 能返回项目、政策状态、最近运行、请求账本、接口目录、JavaScript 文件索引、配置元数据、开放发现、分析任务和后续 API 路径。
2. agent context 不会返回配置明文、密文、响应正文、JavaScript 正文、响应头或响应 Cookie。
3. agent context 中的项目、资产、请求和发现位置 URL 不包含查询值，敏感参数只保留占位符。
4. Qoder 基于上下文规划新检查时，仍必须通过 `POST /api/projects/{项目编号}/scans` 创建新运行，配置编号必须按本次任务显式选择。

### 15.5 工程结构

1. 项目发现、项目初始化和扫描研究三个 Skill 均位于独立目录并通过标准校验。
2. 初始化脚本位于对应 Skill 的 `scripts/`，不再位于仓库根目录。
3. 单元测试与 Skill 测试分别位于 `tests/unit/` 和 `tests/skills/`。
4. 完整 Python 测试、前端 JavaScript 语法检查和 Skill 校验全部通过。

## 16. 后续演进

在不改变授权优先和数据最小化原则的前提下，可以继续建设：

- 更完整的研究 Playbook、步骤依赖、重试、取消和检查点；
- DNS、证书、浏览器和受控 API 等新的资产来源与执行适配器；
- 发现人工复核、误报标记、报告模板和协作流程；
- 正式 `analysis_inputs` 表，替换兼容性的 `asset_revisions` 外键载体；
- 旧 Blob 清点、预览和显式清理工具；
- 经人工审核的检测规则与经验版本发布流程。

如果未来需要保存 JavaScript 历史版本或其他类型响应，必须单独提出设计变更，明确保存目的、最小字段、保存期限、加密、访问控制和删除机制，并再次得到确认。当前唯一原文例外是每个 JavaScript URL 的项目当前文件。
